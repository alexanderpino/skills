# Definition of done — terrain-architect

This skill had no definition of done, and that is why work on it did not converge. A long
improvement session ran an unbounded loop — a critic finds defects, agents fix them, a new critic
finds defects in the fixes — and every pass found real, severe problems, including in work already
verified and committed. On a 16k-line knowledge skill with ~60 guard files, "critique until clean"
never terminates. This file is the terminating condition.

## The rule that makes it finite

> For each criterion below, the row list is computed **once**, committed under `registers/`, and
> **frozen**. A verification pass may only assign verdicts to existing rows. **A critic may never
> add a row.** New findings go to `OPEN-ITEMS.md`.

And the same bound applies to fixing, because in this repo *the fake transcript was reintroduced by
the commit that fixed the fake transcript*: a fix is re-verified by its own criterion's artefact,
plus **exactly one** global re-run at the end. If that run is red, each red row gets one fix and a
re-run of that criterion's artefact only — never another full pass. Anything still red is an
**accepted fail**, recorded below and in `OPEN-ITEMS.md`.

## What "done" does and does not mean

⚠️ **These criteria certify documents and guards. They do not certify algorithms.** The two worst
defects found in this skill's history — a falsified causal explanation, and a figure that
manufactured 58% extra water by splicing two finished fields — were *internally consistent* and
would pass every criterion here. A units bug once shipped with 1295 tests green.

So the honest claim is **"zero defects against the eleven listed criteria"**, never "zero defects".
Any PR or summary that drops the qualifier is misreporting this file.

## The criteria

| # | Criterion | Proving artefact | Channel |
|---|---|---|---|
| A | Every numeric claim is re-derived by a guard, or classified `external`/`illustrative` with its source. Checked **both ways**: text→register and register→text | `registers/numeric-claims.tsv` | attestation |
| B | Every guard row has a reproduced mutation it catches **and a decoy it must not fire on** | `registers/mutation-proofs.tsv` | part independent |
| C | No guard false-fails, over a frozen seed list **including a prose corpus** | `registers/falsepositive-seeds.tsv` | independent |
| D | Every citation resolves; `::symbol` is a real definition; `file:NN` anchored by content | citation guard | independent |
| E | Audit-document inventories match the tree **in both directions** | per-doc bidirectional diff | attestation |
| F | Chapter↔module constants agree, **plus chapter-vs-chapter self-consistency** | `registers/constant-pairs.tsv` | attestation |
| G1 | No dead public parameter | AST census guard | independent |
| G2 | Every capability the chapters recommend is in the graph's selectable set | enumeration guard | independent |
| H | Counts computed never typed; transcripts **and figures** regenerated by a recorded command and diffed | regen commands | independent |
| I | This file and `OPEN-ITEMS.md` exist and are format-guarded | the two files | attestation |
| J | Every substring-scanning guard declares its scan domain and asserts a **denominator**, failing when coverage shrinks | `registers/guard-domains.tsv` | independent |

The **channel** column is the honest measure of how much a green tick is worth. *Independent* means
the check has a source of truth outside the thing it checks. *Attestation* means it is the same kind
of agent writing the claim, the guard, and the evidence — which is how guards in this repo have
certified falsely before.

**J exists because of a specific failure**: a guard whose entire scan was keyed on the substring
`slope`, while this codebase's own idiom (`s = slope(h, cellsize)`) drops the word — so a live units
bug shipped with the suite green. Only a declared domain with a denominator catches that class.

**Criterion K, the executor:** a `.github/workflows` file that runs the suite. There is no CI in this
repo today, so without it A–J are a snapshot rather than guards — and this skill's own history shows
committed, verified work regressing.

## Accepted fails

A criterion moved to `OPEN-ITEMS.md` is **a fail that was accepted, not a pass.** Moving work there
to turn a tick green is the failure mode this file exists to prevent, so any PR closing out this
checklist must print the register's line count and diff *beside* the green output, not instead of it.

## The structural finding this does not fix

Guards certify falsely because the same kind of agent writes the claim, the guard and the evidence,
all optimising "pass" — Goodhart inside the verification layer. A checklist bounds the work; it does
not fix that. The underlying ratio is ~16k lines of claims against ~60 guards, and the remedy this
plan deliberately does not use is **deletion**: a chapter whose claims cannot be backed by execution
or citation should be cut, or demoted to explicitly heuristic, rather than guarded. That was offered
and not chosen for this round. It is the standing recommendation for the next one.
