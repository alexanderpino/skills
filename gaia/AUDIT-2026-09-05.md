## 1. The tooling

### T1 — HIGH · Deleting `status:` produces a document the index calls **stable** and the guard exempts from `verified:`

Three defaults disagree about a missing key:

| Site | Code | Effect of a missing `status:` |
|---|---|---|
| `check.py:202` | `fm.get("status", "stable")` | validates — the default is `stable` |
| `check.py:220` | `fm.get("status") == "stable"` | `None != "stable"`, so the *"stable needs `verified:`"* rule never fires |
| `index.py:77` | `fm.get("status", "stable")` | the Status column prints **stable** |

Reproduced end to end: remove the `status: draft` line from `references/caustics.md`, run
`index.py`, run `check.py` → **exit 0**, and `index.md` now advertises

```
| [`caustics.md`](caustics.md) | Underwater and surface caustics on terrain: … | stable |
```

against an index banner that calls the `status` column "the whole point".

This is the one hole that erases the line `SKILL.md` draws between attribution and verification,
and it is reachable by **deleting** a line rather than adding one — which is how it would actually
happen, in a paste or a merge. Everything else in the guard is built to resist an author who is
trying; this needs only an author who is careless.

**Fix (one line each):** default to `draft` in both files, or make an absent `status` a problem.
Then add a mutation row to the `bites` job: *delete `status:`, regenerate the index, guard must
go red.* Note that the existing `illegal status value` mutation does **not** cover this — it
tests a wrong value, not an absent key.

### T2 — HIGH · `verified:` certifies a citation set, not a claim

`sources_digest()` hashes only sorted `(id, locator)` pairs. Its docstring's promise is true —
"adding or re-pointing a citation invalidates it automatically" — and insufficient, because the
stamp means *a human read the cited work and it says what the document claims*, and the claims are
outside the digest.

Reproduced: stamp `caustics.md` with a well-formed
`verified: - { by: human:<id>, at: …, covers: <its own digest> }`, set `status: stable`, then
replace **every prose sentence in the body** with an invention ("Caustics are produced by the
terrain's magnetic field and scale with the cube of the moon's albedo"), preserving only headings,
tables and citation markers. `check.py` → **exit 0**; the index prints **checked**.

Latent today — no document carries `verified:` — which is precisely when it is cheap to fix, and
before the first stamp lands is the only moment the fix costs nothing.

**Fix:** fold a hash of the body into the digest. Hashing the whole body makes the stamp brittle
against a typo fix; hashing `## Use this` plus the failure table covers the two places a reader
lands and the two places this corpus records its corrections landing. Either is better than
hashing neither.

### C1 — MEDIUM-HIGH · `water-optics.md`: `c` is not "5–20×" `K_d` in the water this document is built around

> *"Because natural water scatters strongly forward, `c` typically runs **5–20x larger** than
> `K_d`. Whichever of the two a single constant was fitted to, the other term is wrong by that
> factor."*

The ratio is set by single-scattering albedo, not by "natural water". With `c = a + b` and
Gordon's `K_d ≈ (a + b_b)/μ_d`, `μ_d ≈ 0.75`:

```
c/K_d  =  μ_d · (a + b) / (a + b_b)      →  μ_d ≈ 0.75   as b → 0   (pure absorption)
                                         →  μ_d / B ≈ 42  as b ≫ a  (B = b_b/b ≈ 0.018, particulate)
```

Computed with **this document's own recommended absorption** (Pope & Fry) and standard molecular
scattering `b_w(500) = 0.0029 m⁻¹ ∝ λ^-4.32`:

| Water | c/K_d |
|---|---|
| pure water, 450 / 500 / 550 / 610 nm | **0.90 / 0.80 / 0.76 / 0.75** |
| Jerlov I (clearest ocean) | 0.92 |
| clear oceanic | 1.4 |
| coastal | 4.1 |
| turbid | 7.0 |
| very turbid | 17.9 |

So 5–20× is a **turbid-water** range presented as universal, in a document whose `## Use this`
is built on pure-water absorption and whose worked examples are a clear lake and an ocean. In pure
water the inequality *reverses*: `K_d > c`, because `K_d ≥ a/μ̄ > a ≈ c` once scattering is
negligible. A reader who applies the stated factor to an alpine lake makes the beam path roughly
six times too attenuating — and the failure row *"Water looks far murkier than it is … `c` and
`K_d` are two coefficients, 5–20x apart"* points them at the same number.

**Fix:** keep the doctrine — two coefficients, two transport paths, export both — and replace the
bare range with the mechanism and its span: *the ratio runs from about 0.75 in pure water, where
`K_d` exceeds `c`, to tens in particle-laden water; it is governed by the single-scattering albedo,
so take it from the body's own `a` and `b`, never from a rule of thumb.* That also removes the
"wrong by that factor" sentence, which inherits the error.

**Everything else in this document reproduced to the printed digit**, which makes the one failure
easier to trust rather than harder:

| Claim | Document | Reproduced |
|---|---|---|
| cosine-weighted `R_ext`, `R_int`, ratio | 6.67% / 47.63% / 7.14× | **6.672% / 47.634% / 7.139×** |
| `R_ext` at normal / at 60° | 2.06% / 6.01% | **2.058% / 6.007%** |
| Schlick signed error over 38–79° | max +14.3% @ 78.89°, min −22.8% @ 51.3°, mean −8.9° | **+14.32% @ 78.89°, −22.75% @ 51.30°, −8.91%** |
| Schlick at 83.8° | +11.4% | **+11.40%** |
| θ_c, cos²θ_c, 1/cos θ_c at n = 1.335 | 48.51° / 0.4389 / 1.5094 | **48.5093° / 0.4389 / 1.5094** |
| Snell's window, three fractions | 97° / 33.8% / 56.1% / 43.9% | **97.02° / 0.3375 / 0.5611 / 0.4389** |
| `F0` at 1.335, and the 1.31–1.47 span | 0.0206, 0.018–0.036 | **0.02058, 0.0180–0.0362** |

Two further things deserve credit. The absorption triples (`0.2644 / 0.0565 / 0.00922` at
610/550/450 nm, and `0.2755 / 0.0511 / 0.00979` at 620/545/460) are the genuine tabulated Pope &

### C2 — MEDIUM · `shallow-water.md`: the mass update names an undefined symbol, and the natural reading destroys the section's own claim

```
  Σf  = sum(f_i)
  K   = (Σf > 0) ? min(1, h * cellArea / (dt * Σf)) : 1
  f_i *= K
  h  += dt * (inflow - outflow) / cellArea            # <-- `outflow` is never defined
```

`Σf` is the **pre-clamp** sum. `outflow` appears nowhere else in the document. The correct value is
the **post-clamp** sum, `K·Σf`; reusing the only defined symbol is what an implementer does, and it
breaks *"the outflow scaling factor `K` makes positivity unconditional"* outright.

Evidence — I hit it on the first transcription, which is the point:

| Reading of the last line | min depth over 400 steps, C = 0.2 … 20 | relative mass drift |
|---|---|---|
| `outflow = Σf` (pre-clamp — the natural reading) | **−5.6 × 10¹⁷⁸**, then NaN | 3.9 × 10¹⁷⁸ |
| `outflow = K·Σf` (post-clamp — intended) | **−0.000000** | **1.11 × 10⁻¹⁶** |

The second row is the document's own printed result, reproduced exactly, including
`≤ 1.1e-16`. So the *claim* is right and the *block* under-specifies it, in the one document that
calls the missing clamp "the single most common port error". One word fixes it: recompute `Σf`
after the scale, or write `h += dt * (inflow - K*Σf) / cellArea`.

Every other measured claim in this document also reproduced independently:

| Claim | Document | Reproduced |
|---|---|---|
| `dt_crit`, constant `A`, depths 0.1 / 1 / 10 | 0.1604 flat | **0.1602 flat** |
| `dt_crit`, `A = h·lx` | 0.5056 / 0.1599 / 0.0506 | **0.5049 / 0.1597 / 0.0505** |
| `dt_crit / (dx/√(gA/l))` across `A, l, dx` | 0.502 | **0.5019, invariant over all 8 combinations** |
| `K` NaN on a mostly-dry grid | 63 of 64 at step 0, whole field after one step | **63 of 64; 64 of 64 after one step** |
| `min(1, NaN)` vs `min(NaN, 1)` in scalar Python | 1 / NaN | **1 / nan** |
| `√(g·h)` at 1 mm | 0.099 m/s | **0.09905 m/s** |

The signal-speed derivation is also correct and is the sharpest thing in the document: linearising
the block gives `c² = A·g·dx²/(l·lx·ly)`, i.e. `√(g·A/l)` on a square grid, so `A/l` is the model's
**effective depth** and Šťava's `A = l²` makes it one cell — the reason a per-step `max(√(gh))`
reduction over a constant-`A` pipe grid measures nothing. The measured flat row and the
1/√h row confirm both branches.

### C6 — LOW · `heightfield-lod.md`: `rho = e·K/d` is a worst-case bound presented as the projected error

Geometric error `e` is **vertical**; its screen-space projection carries a factor depending on the
angle between the error direction and the view ray, and goes to zero looking straight down. Using
the orientation-independent bound is the right engineering call — it is conservative and cheap —
but the document presents it as *the* projected error. A reader who instruments it and finds
measured error consistently below prediction has no way to tell whether the metric is conservative
or broken, and the document's own diagnostic (*"halving `tau` should roughly quadruple triangle
count"*) is the thing they would then distrust. One sentence.

### R1 — HIGH · The executable reference implementation's CFL is derived from a quantity that is not in its stability condition

`SKILL.md` names *"the executable reference implementation at
`obsolete/terrain-architect/reference-impl/`, since Gaia ships no code"* as one of two things worth
reaching for in the retired skills, and `simulation-time-budget.md:64` cites it approvingly as
evidence that *"shipped code does not run at `C = 1`"*. So a defect there is a defect in what the
skill hands a reader.

`obsolete/terrain-architect/reference-impl/shallow_water.py:32`:

```python
dt = 0.20 * cellsize / np.sqrt(G * max(np.ptp(bed), 1.0))
```

`np.ptp(bed)` is the **bed relief**. It appears nowhere in this scheme's stability condition. The
module is a **constant-`A`** pipe model — line 37 sets `pipe = G * cellsize`, i.e. `A·g/l` with
`A = l²` and `l = cellsize`, so `A/l = cellsize` — and its signal speed is therefore
`√(g·cellsize)`, independent of both the water depth and the bed. The correct bound is

```
dt_crit = 0.502 · cellsize / √(g · cellsize)
```

which is exactly what `shallow-water.md` derives, and which I measured independently
(coefficient **0.5019**, invariant across `A`, `l` and `dx`). Substituting bed relief is wrong in
both directions:

| Case | code `dt` / true limit | Consequence |
|---|---|---|
| mountain, 500 m relief, 1 m cells | **0.02×** | the bake costs ~50× more iterations than needed |
| mountain, 500 m relief, 30 m cells | 0.10× | ~10× more iterations |
| gentle basin, 0.5 m relief, 30 m cells | **2.18×** | above the stability limit |
| gentle basin, 0.5 m relief, 100 m cells | **3.98×** | above the stability limit |

Above the limit it does **not** produce a NaN — the outflow clamp holds positivity — so a smoke
test passes. What it produces is grid-Nyquist sloshing: measured checkerboard-mode amplitude
**2.1 × 10⁻¹ at the code's `dt` against 3.0 × 10⁻³ at half the limit**, a factor of ~70, over 300
steps on a pre-filled basin. That is verbatim the failure row *"Checkerboard sloshing that never
damps, no NaN"* that **both** `shallow-water.md` and `simulation-time-budget.md` tabulate. The
corpus diagnosed this class of error correctly, in prose, twice, and ships it in the one piece of
code it points at.

I predicted a blow-up before testing and did not get one; the clamp is why. Recording that because

### X1 — HIGH · RE-RUN · `heightfield-raymarching.md:38-55` — the traversal block does not terminate

The skip branch sets `t = tExitNode`, landing the ray exactly on a node boundary. After popping up
a level and descending again, `exitDistance` at the finer level returns `t` itself, so the branch
assigns `t = t` — zero progress, forever.

I wrote my own field, my own DDA and my own ray set rather than reuse the critic's harness:

| | non-termination | hits | misses |
|---|---|---|---|
| critic, 600 rays | 14.8% | — | — |
| **my independent re-run, 600 rays** | **63.0%** | 209 | 13 |
| **same, with `+eps` on the skip** | **0.0%** | 556 | 44 |

Two implementations, two different rates, both non-zero, both driven to zero by the same
one-character change. **The spread is itself a finding**: the block never pins its texel
registration convention, so the livelock rate is implementation-defined. Also confirmed: a
straight-down picking ray — the use the document sells this kernel for — gives `tExitNode = inf`,

**Fix:** `t = tExitNode + eps` on the skip branch, `tExitNode = min(tExitNode, tExit)` before the
predicate, and state the registration convention.

### X39 — HIGH · CHECKED · `stratigraphy-and-lithology.md:47-51` — the column sampler omits rock advection, so `K` becomes a function of absolute elevation

## 4c. Where the findings contradict each other — and why both sides are right

Six critics optimising six axes produce recommendations that pull against each other. **A plan
built by concatenating them, applied literally, would make this corpus worse.** The contradictions
are not errors to adjudicate; in every case below both claims are true, because they answer
different questions — *volume* versus *load-bearing content*, or *what is present* versus *what is
reliable*. Naming them is what turns a findings list into a plan.

**1. `wave-models.md` has too little information and too much, simultaneously.**
X24 says the document about spectra contains no spectrum — no `α`, no `γ`, no `H_s = 4√m₀` — so its
own instruction *"sample an oceanographic spectrum into a frequency grid"* is not executable from
it. X25, X27 and X31 say its cost/accuracy table is where the damage is concentrated: three of four
rows defective, including a citation the same document disclaims 41 lines later. Both true, and the
resolution is not "add" or "cut" — it is that **the document supplied the information a metric
asked for and omitted the information a reader needed.** The cost table exists because
`SKILL.md:73` demands "an error AND a cost" and `check.py` reports `approximation`. Nothing demanded
the spectrum.

**2. Which makes my own plan item — "raise `approximation` past half the corpus" — actively
dangerous as written.** Cost figures are the single worst-attested content class in this corpus:
`STATE.md` records them wrong by 1000× and by four orders of magnitude; X10 finds a timing that is
physically impossible (`a + b` faster than `copy`); X25 finds one sourced to the wrong paper; X31
finds an accuracy cell reconstructable only under a convention the same page repudiates. Raising the
metric means producing more of exactly this. **Both true: the reader genuinely needs both halves,
and the current mechanism for supplying them manufactures defects.** The fix is not to abandon the
metric but to gate it — a cost figure needs the provenance discipline a claim gets, and *"[x] Fig. 2
caption"* is not a measurement anyone can reproduce.

**3. `reach` pushes content toward the two surfaces with the worst defect rate.** The metric flags
sections that share no word with `## Use this` or the failure table, on the sound reasoning that
content reachable from neither is invisible. But X7, X8, X12, X17, X26, X29, X38, X52 and X56 are
*all* located at those two ends — inversions where the summary contradicts the body that corrects
it. Both true: unreferenced content is invisible, **and** the two ends are where this corpus breaks
most often. Pushing content there without a mechanism that keeps it synchronised with the body
raises the defect count. That mechanism did not exist. It does now — see below.

**4. Three instruments, three blind spots, one defect class.** The same shape —
*a correction landing at one end only* — was found three times this pass, by three different
methods, and **no single instrument sees more than one of them**:

## 4d. Splitting documents: how to make it a superset and not a subset

§4c(5) left a tension unresolved — several documents are missing load-bearing content **and** are
near the 450-line cap, whose own doctrine says *"a document at the cap is two topics wanting a
split"*. The cap is therefore a split **trigger** with no split **procedure**. This section supplies
one, because the naive split loses information and the corpus can already prove it.

### The candidates are real

| Document | lines | `##` sections | headroom |
|---|---|---|---|
| `surface-and-scale-space.md` | 446 | 9 | **4** |
| `driver-fields.md` | 438 | 10 | 12 |
| `seamless-and-periodic.md` | 431 | 8 | 19 |
| `river-networks.md` | 430 | 11 | 20 |
| `stratigraphy-and-lithology.md` | 414 | 7 | 36 |
| `flow-routing.md` | 411 | 6 | 39 |
| `node-graph-runtime.md` | 393 | 12 | 57 |

Seven documents with 4–57 lines of headroom and 6–12 sections each. `surface-and-scale-space.md` is
four lines from the cap. These are not hypothetical splits.

### The measured risk, which is the reason not to split naively

Splitting moves content across a document boundary. **The corpus's boundaries are its weakest
surface**, and this audit can put a number on it:

- **127 cross-document reference edges**, over 104 distinct document pairs.
- **84 of those 104 pairs — 81% — are one-way.** A names B; B is silent about A. So a correction
  made in B has no path back to the A that depends on it.
- Roughly **ten of this audit's findings are handoff defects** of exactly that shape: C4, C5, X13,
  X16, X23, X36, X54, X55, X59, and the `n²`-divisor gap. That is a defect on the order of one
  edge in twelve.

And the crucial asymmetry: an intra-document contradiction is now detectable — `check_repudiation`
found two from the text alone. A **cross-document** handoff defect is detectable by nothing. My
cross-document numeric sweep returned zero and was right, because these are not numeric
disagreements; they are **scope and qualifier leaks**, where a bound stated at one end never
travels. So a naive split *converts detectable defects into undetectable ones.*

### The corpus already contains the mechanism, in exactly one place

`water-optics.md:279` is a split done correctly, and it is the best structural thing in the corpus:

```
## The handoff
The rendering axis owns light transport. What it needs from here, and nothing more:

| The renderer wants | Give it |
| Surface blend between reflection and refraction | `ior` — the exact unpolarised form offline… |
| Refracted colour with depth | `c` per channel, and the **refracted** path length |
| The column's own glow | `b_b`, `K_d`, `phase_g` |
| The underwater state | `theta_c`, the 47.6% `R_int`, and the `n^2` divisor — spent by `water-rendering.md` |
```

…and `water-rendering.md:32` carries the reciprocal rule: *"**One owner per quantity**, where this
document and `water-optics.md` touch."*

**That table is the superset mechanism.** It names the **quantity**, not merely the sibling
document. Splitting `A` into `A1 + A2` with a typed handoff yields `A1 + A2 + interface`, and the
interface is information that `A` never had to write down because it was implicit. That is precisely
"superset, not subset": the split *forces* the corpus to state something it previously left unsaid.
A link that only says *"see `foo.md`"* does the opposite — it fragments.

⚠️ **And even this one leaks, which is why the guard has to come first.** `caustics.md` and
`water-optics.md` are reciprocally linked and the handoff table names caustics explicitly — and X13
still happened, because the consuming document wrote *"the same extinction the water column already
applies"* instead of naming `c`. Reciprocity is necessary and not sufficient. The interface has to
be typed at the **quantity** level, which is exactly what the table above does and what the prose
around it does not.

### What is already guarded, and what is not

A split is **structurally** safe today — five existing checks see to it, and this is a genuine
strength worth stating:

| Risk of a split | Caught by |
|---|---|
| a citation dropped on the floor | `check_orphans` — it becomes an orphan, guard goes red |
| the new document unclaimed by the map | `check_coverage`, both directions |
| the new document unroutable | `check_axis_agreement` + `index.py` |
| the new document never exercised | `check_trigger_coverage` — a positive query must reach it |
| the new document surveying instead of recommending | `check_recommendation` |

What is **not** guarded, and is exactly the superset property:

1. **No failure row may be lost.** Nothing counts them. A split that drops three rows is green.
2. **The handoff must be reciprocal.** 81% of edges are not.
3. **The handoff must name quantities, not documents.** Only one document does this.

### Proposed: `check_handoff`, and the split contract

The corpus already applies bidirectional discipline to citations — `check_no_artefact` and
`check_not_opened` both assert that two ends of a claim agree. This is the same rule one level up:

> A document carrying a `## The handoff` table must name, per row, a **quantity** and the **document
> that consumes it**; and the named consumer must carry a reciprocal row naming the same quantity.
> One end saying "see `foo.md`" and the other saying nothing is the defect.

**The split contract**, then, is five clauses — three of them already enforced:

1. Every citation survives (guarded).
2. Every failure row survives — the union must be `≥` the original (**new**, and cheap: count rows
   before and after).
3. Both halves get a coverage row, an axis tag, and a trigger query (guarded).
4. Both halves carry a `## The handoff` table naming the quantities that cross, with units
   (**new** — `check_handoff`).
5. The split is only *complete* when the interface says something neither half said before. If the
   handoff table is empty, the split was a filing decision, not a superset.

Clause 5 is the user-facing test and the one that keeps this honest: **if splitting did not force
you to write down a quantity, a unit or a qualifier that was previously implicit, do not split.**

4. **Do not merge the three consistency instruments.** Cross-document numeric agreement,
