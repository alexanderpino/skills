# 07 · Research Plan

For each major domain, this plan lists the organizations, publications, standards, engines and research programs that the owning skills must investigate **before** making major architectural decisions. The listed items are **starting points, not verified citations**. In phase 2, `research-evidence` grades every source actually cited in a SKILL.md with a provenance tier (T1–T6, see `06-gap-analysis.md`). Any claim that cannot be traced to a graded source is marked as unverified.

## Cross-domain sources (every skill)

- **Conferences and venues:** SIGGRAPH (papers and the *Advances in Real-Time Rendering* and *Open Problems* courses), GDC (programming, tools, production tracks; GDC Vault), High Performance Graphics, Eurographics / EGSR, I3D, SCA (simulation), Digital Dragons, Reboot Develop, CppCon / C++Now (systems), ACM TOG / CGF journals, IEEE TVCG.
- **Platform holders and vendors:** Microsoft DirectX specs and DirectX Developer Blog (spec announcements count as T2), Xbox/PlayStation/Nintendo developer documentation (licensed), Khronos (Vulkan spec, registry and profiles; SPIR-V; glTF; KTX; OpenXR; Slang), Apple Metal documentation and WWDC sessions, AMD GPUOpen (RDNA ISA guides, FidelityFX, RGP/RGD docs), NVIDIA developer (RTX SDKs, Nsight, research papers), Intel (optimization manuals, hybrid-architecture guidance, XeSS docs), Arm (Mali/Immortalis best practices), Qualcomm (Adreno guides).
- **Engine documentation:** Unreal Engine 5.x documentation and Unreal Fest talks; Unity manual, Entities/DOTS docs; Godot docs (useful for scale-down design); O3DE docs. These are capability references only (T3).
- **Studio technical publications:** EA SEED / Frostbite, Ubisoft (Snowdrop, Anvil), Activision Central Tech research publications, id Software talks, Guerrilla (Decima) publications, Remedy (Northlight), Capcom (RE Engine CEDEC talks), Naughty Dog, Insomniac, Epic, Unity Labs, Embark.

## Research procedure every skill follows in phase 2

1. **Survey.** List candidate techniques across the five classes the brief requires: traditional, current mainstream, current high-end, emerging, research-stage.
2. **Grade.** Grade each source (T1–T6) and give each technique a maturity class.
3. **Justify.** State the recommendation against the requirements, in the form "technique X does Y, which matches workload Z", never "engines normally do it".
4. **Spike where thin.** Where evidence is thin (see `06-gap-analysis.md` §A), specify the spike or benchmark that would produce it instead of guessing.
5. **Record.** Record the decision as an ADR with revisit conditions.
