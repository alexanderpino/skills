# K-NET · Networking Critic · Round 2 (blind)

Scope read: data/*.json, docs/00, 06, 09, scripts/model.py; `check.py` passes (0 errors). The findings below cover what the checker cannot see or where its proofs have gaps.

### K-NET-1 · blocker · dependency-error
- Target: milestones.json M1–M4; C-FRAME, C-ID, C-ECS, C-SER, C-PHYS, C-ANIM, C-WORLD, C-SNAPSHOT, C-DET, C-INPUT; network-architect, replication, prediction-rollback
- Finding: The network skills join only at M4. By then the contracts that netcode has to shape are already frozen: C-FRAME, C-ID, C-ECS and C-SER at M1; C-PHYS and C-ANIM at M2; C-WORLD at M3. The contracts that rollback and lockstep actually run on (C-DET, C-SNAPSHOT, C-INPUT) are never frozen at all. So no network skill is a consumer when the net tick domain and resim cadence go into C-FRAME, when stable cross-machine and predicted-spawn IDs go into C-ID, when replicated and rollback-able component marking goes into C-ECS, or when snapshot/resimulate participation goes into C-PHYS and C-ANIM.
- Evidence: Multiplayer that is added after the simulation contracts are fixed is the best-documented failure mode in the industry. Overwatch built its ECS around determinism and prediction from the start (Tim Ford, "Overwatch Gameplay Architecture and Netcode", GDC 2017). Unity's DOTS NetCode needed ghost and prediction semantics designed into Entities, and Unity's earlier UNet/MLAPI retrofits failed. Halo: Reach designed replication priorities into the object model (Aldridge, GDC 2011). C-PHYS already *claims* resim participation and collider history, but its only consumer (prediction-rollback) arrives two milestones after the freeze. "Frozen" then means untested.
- Proposed change: Add network-architect, replication and prediction-rollback to M1 as design authorities: they draft C-NET, C-REP and C-PREDICT at M1 and review every M1/M2 freeze. Add C-DET, C-SNAPSHOT and C-INPUT to M1's `contracts_frozen`. Add to the M1 exit: "indie-2d reference runs a two-instance loopback session (lockstep or rollback) under QA.SIM.netsim". Add to the M2 exit: "predicted character movement and physics resimulation against a loopback authoritative server". Extend check.py so a contract cannot be frozen before at least one of its declared consumers has joined.

### K-NET-2 · blocker · scale-down
- Target: configurations `*-server` (indie-2d-online-moddable-server, online-3d-server, sandbox-online-server, aaa-open-world-online-server); platform-desktop; NET.SRV.host-os
- Finding: No skill declares the platform `server-host`. platform-desktop is `platforms: ["pc"]`, even though its purpose text mentions server hosts, so the four server configurations have no OS/PAL implementer. `members()` confirms that platform-desktop is absent from every server configuration. The closure "proof" for all server targets is therefore false. The checker's implementer check covers C-RHI-style contracts, not C-PAL. Server host-OS concerns are parked in `NET.SRV.host-os` (dedicated-server, not a PAL skill), and its only contributor (platform-desktop) is itself excluded. Those concerns are container-aware core counts and cgroup CPU quotas, huge pages, NUMA on large server instances, and ARM64 (Graviton/Ampere) hosts.
- Evidence: Every shipped dedicated-server engine (UE, Source, id Tech, Frostbite) runs its Linux server on the desktop PAL with server-specific switches. Container CPU quotas cause the classic "hardware_concurrency returns 64 inside a 4-vCPU pod" oversubscription bug, which is a job-system/PAL issue, not a server-gameplay issue.
- Proposed change: Set platform-desktop `platforms: ["pc","server-host"]` (or add a server-host PAL implementer). Move NET.SRV.host-os to platform-desktop, with contributors dedicated-server and job-system-task-graph. Extend the implementer check in check.py to C-PAL for every platform in every configuration.

### K-NET-3 · major · wrong-boundary
- Target: NET.SRV.listen, NET.SRV.auth (dedicated-server, targets `server, tools`)
- Finding: Listen servers, host migration and P2P hosting run *inside the client build*, but the owning skill never ships in `client` (online-3d-client membership confirms it). Listen-host auth validation (NET.SRV.auth) is missing from client builds for the same reason. Co-op, survival and indie online games, which are the majority of small online titles, cannot close.
- Evidence: Valheim, Deep Rock Galactic, Minecraft LAN, It Takes Two and Halo (host migration) all ship an authoritative host inside the client. Destiny uses a hybrid of P2P hosts plus server (Truman, "Shared World Shooter", GDC 2015). The hosting *mode* (dedicated, listen, P2P host, relay-hosted) is a runtime property of the session layer, not of the headless build.
- Proposed change: Move NET.SRV.listen (and host migration) and a host-mode-agnostic NET.SRV.auth to the session owner proposed in K-NET-6, which ships in client, headless-client and server. dedicated-server keeps only headless stripping, density and fleet concerns. Add a configuration `coop-3d-listen-client` (std3d+online, client) that must contain host mode and auth.

### K-NET-4 · major · scale-down
- Target: C-PREDICT.requires, prediction-rollback.consumes, profile `online`, NET.ARCH.async, configurations rts-2d-massim-client and lite-3d-mobile-online-client
- Finding: `online` is a single add-on, so every online game gets UDP transport, entity replication, prediction and rollback. The data also forces it: C-PREDICT *requires* C-REP, so a lockstep RTS or a P2P rollback fighting game must link the whole entity/property replication and interest-management stack. That stack is dead weight there, because these games exchange only input commands. prediction-rollback does not consume C-NETLINK, although the C-NETLINK summary says it carries "rollback input exchange". An async/turn-based mobile game (NET.ARCH.async) needs only HTTPS to a backend, yet it pulls in the UDP stack.
- Evidence: Age of Empires lockstep ("1500 Archers on a 28.8", Terrano & Bettner, GDC 2001), Factorio and StarCraft send only commands. GGPO and Street Fighter 6 exchange only inputs over an unreliable channel. Words with Friends-style async games are pure REST/WebSocket.
- Proposed change: Change C-PREDICT.requires to `["C-NETLINK","C-DET","C-SNAPSHOT","C-INPUT"]`, with C-REP optional. prediction-rollback consumes `C-NETLINK` and `C-REP?`. Split the add-on into `online-async`, `online-lockstep`, `online-rollback` and `online-authoritative` (the current `online` becomes the last one). Set replication's profiles to `online-authoritative`. Set network-transport's profiles to everything except `online-async`. Move NET.ARCH.async to online-services-liveops. Add configurations `fighting-2d-rollback-client` (must exclude replication) and `mobile-async-client` (must exclude network-transport, replication and prediction-rollback).

### K-NET-5 · major · missing-contract
- Target: dedicated-server (`provides: []`), NET.SRV.persistence, NET.SRV.transactions, NET.SRV.zoning, NET.SRV.orchestration, NET.ARCH.meshing
- Finding: dedicated-server owns ten capabilities. They include server-authoritative persistence (write-behind, leases, live schema migration), idempotent economy transactions, zoning with player handoff, and the fleet allocation boundary. It provides **no contract**, so gameplay-architect, persistence-save, voxel-worlds (WLD.VOX.edits "persistence hand-off") and anti-cheat have no sanctioned way to write a persistent record, issue a transaction, hand an entity to another zone or react to drain/shutdown. The skill also mixes two literatures. One is headless builds and Linux containers. The other is distributed-database consistency and authority transfer, and there meshing (NET.ARCH.meshing, network-architect) is split away from zoning (NET.SRV.zoning, dedicated-server), although both are one authority-transfer mechanism.
- Evidence: Fleet SDKs define a mandatory server lifecycle: Agones (Ready/Allocate/Health/Shutdown), Amazon GameLift Server SDK (OnStartGameSession/ProcessEnding) and PlayFab Multiplayer Servers. Game code must participate, for example by rejecting joins when draining and by flushing persistence on SIGTERM. MMO persistence with write-behind and leases (EVE, SpatialOS persistence model) and idempotent grants (the Destiny/Warframe economy duplication postmortems) are game-framework-facing APIs, not internals.
- Proposed change: dedicated-server provides `C-SERVER` (L3): host lifecycle (allocate/ready/health/drain/shutdown), instance metadata, and server auth results. Create a new expert `server-scaleout-persistence` under network-architect, profile `online-authoritative`, targets `server, tools`. It owns NET.SRV.zoning, NET.ARCH.meshing (X), NET.SRV.persistence and NET.SRV.transactions, plus a new NET.SRV.cross-server "Cross-server messaging & entity/player handoff". It provides `C-SHARD` (authority transfer, handoff, cross-server messages) and `C-SRVDATA` (persistent records, leases, idempotent transactions). gameplay-architect, persistence-save, voxel-worlds and anti-cheat-integrity consume C-SRVDATA optionally.

### K-NET-6 · major · omission
- Target: capabilities NET.*; C-REP; GAM.FW.flow; WLD.MODEL.travel
- Finding: Nobody owns the network *session lifecycle*: the connect handshake (version/compat check per NET.ARCH.versioning, auth token, capability negotiation); world/map sync and load-gated readiness; spawn; the join-in-progress baseline; reconnect/rejoin with ownership and state restore inside a grace window; server-driven travel with connected clients; and kick/ban/disconnect reasons. NET.TRANS.lifecycle covers transport connections only. NET.ARCH.connectivity is policy. PLAT.SVC.social "join-in-progress" is the platform invite. WLD.MODEL.travel has no network contributor.
- Evidence: Every shipped netcode has an explicit signon state machine: Source (connect → new → prespawn → spawn → full), Quake 3 (gamestate baseline, then deltas), and UE (NMT_Hello/Login/Join plus seamless travel). Reconnect-to-match is a platform-cert and esports requirement (Valorant, CS2, LoL rejoin). Without an owner, the pieces are built separately by gameplay, replication and transport.
- Proposed change: Add area NET.SESS, owned by a session owner that ships in all targets. Either give it to replication, or create a new expert `net-session` if K-NET-3 and K-NET-5 enlarge the scope. Its capabilities: NET.SESS.handshake, NET.SESS.join (load-gated readiness), NET.SESS.baseline (late-join snapshot), NET.SESS.reconnect, NET.SESS.travel (contributor world-architect; add the session owner as a contributor to WLD.MODEL.travel), NET.SESS.host-mode (from K-NET-3) and NET.SESS.disconnect (reasons, ban hook). Provide contract `C-NETSESSION` (L3), consumed by gameplay-architect (GAM.FW.flow) and editor-architect (PIE).

### K-NET-7 · major · dependency-error
- Target: C-NETLINK (L2, network-transport), C-SVC/C-LIVE (L3); NET.TRANS.nat; PLAT.SVC.matchmaking; gameplay-architect.consumes
- Finding: Two gaps. (a) Platform transports are unreachable: Steam Networking Sockets/SDR, EOS P2P, Xbox (PlayFab Party / secure device association) and PSN P2P are platform-SDK transports. network-transport (L2) cannot consume C-SVC or C-LIVE (L3), and no skill `implements` C-NETLINK, so the NAT/relay capability has no legal path to the platform SDKs that provide it. (b) The matchmaking → connect handoff is unowned. On the client, only gameplay-data, ai-behavior-perception and anti-cheat consume C-LIVE. Neither gameplay-architect nor any network skill takes a matchmaking ticket (address, session ID, auth token) and turns it into a connection.
- Evidence: Valve's GameNetworkingSockets/SDR, EOS P2P and PlayFab Party each replace the socket layer, and console TCRs require platform relays or association in some modes. Existing engines model these as pluggable "net drivers" or "socket subsystems" below replication: UE's OnlineSubsystemSteam SteamSockets NetDriver.
- Proposed change: Declare C-NETLINK as a contract with backend implementers (the C-RHI pattern). platform-services and online-services-liveops `implements: ["C-NETLINK"]` for SDK transports, with module attribution kept at L2. Add an implementer check. The session owner (K-NET-6) consumes `C-SVC?` and `C-LIVE?` for tokens and match results. Add contributors network-transport and the session owner to PLAT.SVC.matchmaking.

### K-NET-8 · major · overlap
- Target: NET.ARCH.validation (network-architect), QA.SIM.netsim (simulation-validation), QA.FUNC.network (functional-automation-soak), NET.TRANS.simulation
- Finding: Four capabilities overlap on "deterministic network simulation, harnesses and correctness metrics", with no stated split. ### K-NET-9 · major · omission
- Target: PLAT.SVC.social (platform-services), online-services-liveops, C-LIVE
- Finding: Cross-platform friends, parties, presence and invites through an own or third-party backend are unowned. PLAT.SVC.social belongs to platform-services, which covers first-party social only. First-party parties do not span networks, so crossplay party-up, cross-network party voice and a unified friends list need a backend social layer, reconciled with first-party privileges, blocks and invites. C-LIVE's summary has no parties or presence.
- Evidence: Fortnite, Rocket League and Fall Guys implement crossplay parties and friends through Epic Online Services, and Call of Duty does the same through Activision ID. Console TRCs still require the first-party invite and block flows alongside them, so the reconciliation is itself certification-sensitive.
- Proposed change: Add PLAT.SVC.xplat-social, "Cross-platform friends, parties, presence & invites via backend; reconciliation with first-party social, privileges and blocks". Owner online-services-liveops; contributors platform-services and certification-compliance. Add parties and presence to C-LIVE.summary.

### K-NET-10 · major · obsolete-assumption
- Target: legacy-patterns.json
- Finding: The anti-legacy catalogue has no networking entries. The networking legacy defaults that agents fall into silently are therefore never flagged.
- Evidence: Each of the following has been replaced in production: per-actor property polling and comparison across all connections every net tick (UE3/UE4 classic, replaced by push model, Iris and ReplicationGraph); net or sim tick tied to the render frame; TCP or all-reliable channels for real-time state; client-authoritative hits and movement; RPC-as-state-sync; exact-build version locks (replaced by compatibility windows); exposed peer IPs in P2P (DDoS/swatting, replaced by relay shielding); lockstep without desync hashing and tooling.
- Proposed change: Add patterns L-NET1..L-NET8 with the stances above: push-based dirty tracking and shared serialization at O(changes); a fixed sim tick independent of render; UDP channels with per-message reliability classes; server authority with bounded-rewind lag compensation; state replication plus events; compatibility windows; relay-shielded addressing; state-hash desync detection. Justification owners are network-architect or replication.

### K-NET-11 · major · dependency-error
- Target: replication.consumes; NET.REP.*; C-REP
- Finding: replication consumes neither C-FRAME nor C-TASK. It therefore cannot declare its access at the "net snapshot" phase of the canonical schedule (CORE.FRAME.sim-schedule), and it cannot parallelize. No capability covers scalable change detection or parallel packet building, although crosscutting "scalability" demands "spatial replicas update in O(changes)". The server replication loop is the dominant server CPU cost at battle-royale and MMO scale.
- Evidence: Fortnite needed ReplicationGraph to reach 100 players (Epic, 2018). UE5 Iris moved to push-based dirty state and per-object serialization shared across connections, with parallel connection processing. Overwatch builds its netcode on scheduled ECS systems.
- Proposed change: Add `C-FRAME` and `C-TASK` to replication.consumes. Add NET.REP.push-model, "Push-based dirty tracking & O(changes) change detection" (E). Add NET.REP.parallel, "Parallel per-connection packet building with shared per-object serialization" (E). Add the dirtying API to the C-REP summary.

### K-NET-12 · major · omission
- Target: performance-architect subtree (PRF.*), crosscutting "latency", NET.ARCH.budgets
- Finding: The performance organization covers CPU, GPU, loading and memory. There is no owner for network and server performance gates: bandwidth per player and per entity class with regression gates, server CPU and memory per CCU and per tick against instance classes (the cost model), and end-to-end networked latency (input → server tick → client display, including input delay and interpolation delay). The crosscutting "latency" concern goes to frame-orchestration and is purely local. NET.ARCH.budgets sets numbers, but no one measures and gates them.
- Evidence: Budgets without a measuring owner go unenforced, which is the framework's own rationale for perf experts. Server cost per CCU drives live-service economics (the Riot "Valorant 128-tick servers" engineering blog), and bandwidth regressions are a routine live-ops incident class.
- Proposed change: Add area PRF.NET: PRF.NET.bandwidth (attribution baselines + CI gate; consumes NET.DBG.profiler), PRF.NET.server-cost (tick cost per CCU per instance class; feeds PRF.METH.model) and PRF.NET.latency (end-to-end networked latency accounting). Owner: a new expert `network-server-performance` under performance-architect, or cpu-performance if staffing is tight. Extend the crosscutting "latency" obligation with "network latency contribution" and add network-architect as co-reviewer.

### K-NET-13 · major · omission
- Target: untrusted_inputs of prediction-rollback, dedicated-server, audio-dsp-mixing, determinism-replay, anti-cheat-integrity
- Finding: Several network-facing untrusted inputs are undeclared, so no fuzz target or validating owner is required for them (K-SEC check "every untrusted input has a validating owner and a fuzz target"). They are: client input-command frames and tick stamps (prediction-rollback), which are a classic speed-hack and time-manipulation vector; auth tickets and client-initiated transaction and persistence requests (dedicated-server); remote voice packets fed to a codec (audio-dsp-mixing); peer inputs and state-hash reports in lockstep/P2P (determinism-replay, prediction-rollback); and client anti-cheat telemetry (anti-cheat-integrity). Only transport and replication declare `packets`.
- Evidence: Speed hacks by timestamp and command-rate abuse appear in CS:GO/CS2 and Source-engine history. Voice codec parsers are fuzzed attack surface: the Opus/libvpx CVE history and the 2023 WebRTC and libvpx zero-days.
- Proposed change: Add `untrusted_inputs`: prediction-rollback `["input-commands","peer-inputs"]`, dedicated-server `["auth-tickets","transaction-requests"]`, audio-dsp-mixing `["voice-packets"]`, determinism-replay `["replays","peer-state-hashes"]`, anti-cheat-integrity `["client-integrity-reports"]`.

### K-NET-14 · major · wrong-boundary
- Target: PLAT.SVC.voice-text (online-services-liveops), NET.TRANS.voice (network-transport), AUD.DSP.voip (audio-dsp-mixing), AUD codecs
- Finding: Voice is split three ways, and nobody owns the end-to-end pipeline. The following are all unowned: the choice between service-hosted and game-transport voice; the voice jitter buffer and packet-loss concealment; proximity/positional voice (a spatialization hand-off to spatial-audio-acoustics plus relevancy from replication); platform voice requirements (for example Xbox Game Chat 2 and console privilege gating); and voice capture for reporting and moderation.

Rename PLAT.SVC.voice-text to "Voice & text chat end to end: path selection (service vs game transport), channels, privileges". Add PLAT.SVC.voice-moderation (reporting capture, retention; contributors certification-compliance, security-engineering). Add AUD.DSP.voice-jitter, "Voice jitter buffer, PLC & codec" (audio-dsp-mixing). Add AUD.SPA.proximity-voice, "Positional voice" (spatial-audio-acoustics; contributor replication).
