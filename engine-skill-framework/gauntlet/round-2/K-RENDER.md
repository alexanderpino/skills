# K-RENDER — Rendering Critic, round 2 (blind)

Scope: `render-architect` subtree, `gpu-platform-architect` subtree, environment rendering (terrain, vegetation, water, atmosphere), character rendering, 2D/UI backend, VFX, video, rendering tooling. `check.py` passes with 0 errors and 0 warnings. Every finding below is something the checker cannot see.

### K-RENDER-1 · blocker · missing-contract
- Target: render-architect, C-RSCENE, RND.ARCH.shading-path, geometry-pipeline, direct-lighting-shadows, global-illumination, reconstruction-upscaling, translucency-decals, vfx-particles, character-rendering, water-ocean, post-color-hdr
- Finding: No contract covers the per-view surface and scene-texture data that almost every render feature reads and writes: depth, HZB, visibility-buffer IDs, decoded surface attributes (normal, roughness, base/specular albedo, shading-model ID), velocity, and the lit scene color. `C-RSCENE` covers only scene streams and feature registration. `C-TEMPORAL` covers motion and jitter. The shading-path decision (RND.ARCH.shading-path: forward+, deferred or visibility buffer) sets this layout, yet no contract publishes the result. Consumers include SSR/SSGI/AO, VSM page marking, contact shadows, decals, particle depth collision (RND.VFX.collision), refraction, SSS, the denoiser and ray-reconstruction guide buffers, and upscaler inputs. Without it, each feature agent will invent its own G-buffer assumptions, and switching shading path per tier (a stated goal) breaks every feature at once.
- Evidence: UE `FSceneTextures`/`FSceneTextureUniformParameters` and Substrate's material buffer are the most widely consumed render interface in UE5. Frostbite's FrameGraph talk (O'Donnell, GDC 2017) treats scene textures as named graph resources that features import by contract. DLSS Ray Reconstruction and AMD FidelityFX denoisers take a fixed set of guide buffers (diffuse/specular albedo, normals, roughness, hit distance). The visibility-buffer papers (Burns & Hunt 2013; Wihlidal/Nanite material resolve) show that the attribute decode itself is a shared API.
- Proposed change: Add `C-SCENETEX` (layer 3, owner `render-architect`, requires `C-RG`, `C-MATIF`): named per-view render-graph resources and their producer phases (depth, HZB, visibility IDs, surface-attribute decode function for visbuffer and deferred, velocity, scene color, guide buffers), with variants per shading path and tier. Add capability `RND.ARCH.scene-textures` (render-architect, E). Add `C-SCENETEX` to the consumes of every skill listed in the Target line and to `render-validation`.

### K-RENDER-2 · major · wrong-owner
- Target: RND.RECON.motion-vectors, post-color-hdr, reconstruction-upscaling, C-TEMPORAL
- Finding: `RND.RECON.motion-vectors` ("Motion vector, jitter & history contract") is owned by `post-color-hdr`. The contract it describes, `C-TEMPORAL`, is owned by `reconstruction-upscaling`, and that skill's purpose text also claims "the motion-vector/jitter/history contract". So one capability sits under a different owner from its contract. `post-color-hdr` also does not consume `C-TEMPORAL`, although motion blur and DOF need velocity and history.
- Evidence: TAA/TSR, DLSS/FSR/XeSS, frame generation and XR spacewarp all set the motion-vector conventions (jitter removal, dilation, reactive masks). The owner of the reconstruction pipeline must own that contract. Post only consumes it.
- Proposed change: Move `RND.RECON.motion-vectors` to owner `reconstruction-upscaling` with contributor `post-color-hdr`. Add `C-TEMPORAL` to the consumes of `post-color-hdr`.

### K-RENDER-3 · major · maturity-error
- Target: RND.GRAPH.work-graphs, RND.RHI.gpu-work, radar "Work graphs & mesh nodes"
- Finding: `RND.GRAPH.work-graphs` is labelled E in capabilities.json, but the radar entry covering it says class X ("no shipped titles"). `RND.RHI.gpu-work` (E) bundles established indirect/ExecuteIndirect/device-generated commands with work-graph programs, so a work-graph dependency comes in labelled as established. The checker only verifies that non-E capabilities appear on the radar, not that the radar class matches the capability's maturity. It also contradicts docs/00 §105 ("work graphs as an optional part of C-RG") and gap A6.
- Evidence: D3D12 Work Graphs 1.0 (2024) is D3D12-only. Vulkan has only the provisional `VK_AMDX_shader_enqueue`, and Metal and current consoles have no support. No shipped-title postmortems exist. Device-generated commands (VK_EXT_device_generated_commands, 2024) and ExecuteIndirect are the established baseline.
- Proposed change: Relabel `RND.GRAPH.work-graphs` to X, or M if the radar entry is promoted with evidence. Split `RND.RHI.gpu-work` into `RND.RHI.indirect` (E: indirect, DGC, backing memory) and `RND.RHI.work-graph-programs` (X, gated at the `aaa` capability level). Add a `check.py` rule that each radar class equals the maturity of every capability it lists (this run also finds `RND.ARCH.multiview` E against radar M).

### K-RENDER-4 · major · missing-contract
- Target: post-color-hdr, render-2d-vector, media-playback, vfx-particles, global-illumination, direct-lighting-shadows, ui-architect, xr-runtime
- Finding: `post-color-hdr` provides no contract, yet it owns state that other features need every frame: exposure/pre-exposure (lighting, GI and emissive VFX write pre-exposed values), the working color space, and the output display state (SDR/HDR, PQ/scRGB, paper-white nits, max luminance, calibration). UI compositing in HDR (RND.2D.ui-backend "HDR compositing"), HDR video (`RND.MEDIA.hdr`, contributor post-color-hdr) and XR compositor layers all need that display state, but can reach it only through undeclared coupling.
- Evidence: UE `View.PreExposure` is threaded through every lighting and translucency pass. Frostbite's "HDR in Frostbite" (Fry, GDC 2017) covers UI paper-white compositing. Microsoft's Advanced Color and Sony HDR guidelines require UI to be composited at a user-calibrated paper white. ACES 2.0 output transforms are parameterized by display peak luminance.
- Proposed change: Add `C-COLOR` (layer 3, owner `post-color-hdr`, requires `C-RG`, `C-PAL`): working color space, per-view exposure and pre-exposure value with its frame latency, output display descriptor, and UI/video composition rules. Consumers: `render-2d-vector`, `media-playback`, `vfx-particles`, `direct-lighting-shadows`, `global-illumination`, `translucency-decals`, `xr-runtime`, `ui-architect`. Also add `C-VIEW` to the consumes of `post-color-hdr` for physical camera parameters.

### K-RENDER-5 · major · dependency-error
- Target: direct-lighting-shadows, atmosphere-weather, global-illumination, C-LIGHT, C-ATMOS
- Finding: Sun and sky data flow both ways between these features, and the acyclic layer-3 contract graph cannot express it. `atmosphere-weather` consumes `C-LIGHT` for volumetric shadows. `direct-lighting-shadows` does not consume `C-ATMOS`, yet it needs atmospheric transmittance on the sun/moon illuminance and cloud shadows. `C-ATMOS` advertises cloud shadows, but the lighting owner is not its consumer. `material-system` does not consume the "weather-driven global material parameters" (wetness, snow) that `C-ATMOS` exports. Today these edges are either missing or will be added as `?` edges that hide a cycle.
- Evidence: Hillaire, "A Scalable and Production Ready Sky and Atmosphere Rendering Technique" (EGSR 2020): the transmittance LUT modulates the directional light at the shading point. Frostbite and Decima (Schneider, "Nubis", SIGGRAPH 2015/2022/2023) feed cloud shadow maps into the lighting pass and fog into translucency. Real engines break the cycle with a per-frame "lighting environment" uniform that runs early in the frame.
- Proposed change: Add `C-LIGHTENV` (layer 3, owner `render-architect`), a per-frame, per-view environment block: sun/moon direction and illuminance after atmospheric transmittance, sky irradiance SH, cloud-shadow and fog resources, and weather material scalars, all published in a declared early phase. `atmosphere-weather` produces it through `implements`, and `direct-lighting-shadows`, `global-illumination`, `translucency-decals`, `material-system`, `vfx-particles` and `water-ocean` consume it. Keep `C-ATMOS` for media sampling only.

### K-RENDER-6 · major · overlap
- Target: RND.VFX.volumes (vfx-particles), WLD.ENV.fog / WLD.ENV.clouds (atmosphere-weather), RND.TRANS.lighting (translucency-decals), C-ATMOS, fluid-simulation
- Finding: Three skills own participating-media rendering. `atmosphere-weather` owns volumetric fog, local media and clouds. `vfx-particles` owns "sparse/heterogeneous volume rendering & lighting (NanoVDB class)". `translucency-decals` owns "volumetric integration". No skill owns the shared volume integrator, froxel grid, or the rule for compositing heterogeneous volumes with fog and translucency. Smoke, explosions (fluid-simulation output), clouds and fog will get three ray-marchers with inconsistent lighting and no shared composition order.
- Evidence: UE splits Heterogeneous Volumes from Volumetric Fog and has documented composition artifacts between them. Frostbite's unified volumetric framework (Hillaire, SIGGRAPH 2015, "Physically Based and Unified Volumetric Rendering in Frostbite") argues for one froxel-based media integrator for fog, local volumes and particles. Wronski's volumetric fog (SIGGRAPH 2014) is the same model.
- Proposed change: Make `atmosphere-weather` (or a render-side owner of your choosing) the single owner of the participating-media integrator (`RND.VOL.integrator`: froxel/grid injection, heterogeneous sparse volumes, composition order), exposed through `C-ATMOS` as "inject media / sample media". Reassign `RND.VFX.volumes` so that `vfx-particles` and `fluid-simulation` are contributors that inject media. Narrow `RND.TRANS.lighting` to "translucent surfaces sampling media via C-ATMOS".

### K-RENDER-7 · major · missing-contract
- Target: translucency-decals, vfx-particles, water-ocean, character-rendering, RND.GEO.splats, UI.FW.world-ui
- Finding: `translucency-decals` owns transparency, OIT, sorting and refraction but provides no contract. VFX (non-responsibility "Translucency sorting → translucency-decals"), water (`WLD.ENV.water-render`, contributor translucency-decals), hair, Gaussian splats (which need sorted alpha blending) and world-space UI therefore have no declared way to submit translucent surfaces into the shared sort/OIT/refraction pass. `vfx-particles` also does not consume `C-MATIF`, although particle materials are materials.
- Evidence: UE translucency passes (standard, after-DOF, separate translucency) and Frostbite's particle and translucency lighting pipeline are a shared submission interface. OIT choices such as weighted-blended (McGuire & Bavoil 2013), MBOIT (Münstermann 2018) and per-pixel lists change what every producer must output.
- Proposed change: Add `C-TRANSLUCENT` (layer 3, owner `translucency-decals`, requires `C-RSCENE`, `C-MATIF`, `C-SCENETEX`): translucent submission (sort keys, OIT tier, composition pass before or after DOF and upscale, refraction/distortion buffer, decal submission). Add consumers `vfx-particles`, `water-ocean`, `character-rendering`, `geometry-pipeline` (splats) and `ui-architect` (world UI). Add `C-MATIF` to the consumes of `vfx-particles`.

### K-RENDER-8 · major · missing-contract
- Target: geometry-pipeline (RND.GEO.visbuffer), virtualized-geometry-lod (RND.LOD.swraster, RND.LOD.clusters), material-system
- Finding: Neither `geometry-pipeline` nor `virtualized-geometry-lod` consumes `C-MATIF`. The visibility-buffer material resolve (classifying pixels by material, then compute or indirect shading bins) has no owner: geometry-pipeline owns rasterization, material-system owns codegen, and nothing assigns the resolve pass. Software micro-polygon rasterization and cluster culling also need material-driven "programmable raster" (alpha mask, world-position offset, displacement), which comes from the material graph.
- Evidence: Nanite's material pipeline (Karis et al., SIGGRAPH 2021 "Deep Dive into Nanite"; UE 5.1+ Programmable Raster; 5.4 compute-shading bins). "Visibility Buffer" (Burns & Hunt, JCGT 2013). Doghramachi & Bucci, "Deferred+" (GPU Zen). Each needs the material system to emit raster and resolve variants.
- Proposed change: Add `C-MATIF` to the consumes of `geometry-pipeline` and `virtualized-geometry-lod`. Extend the `C-MATIF` summary with "raster-stage program (mask/WPO/displacement) and visbuffer/deferred resolve entry points". Add capability `RND.GEO.material-resolve` (owner `geometry-pipeline`, contributor `material-system`, std3d).

### K-RENDER-9 · major · scale-down
- Target: RND.GEO.culling, RND.GEO.cpu-submission, geometry-pipeline, lite-3d-mobile-client
- Finding: The only occlusion-culling capability is "GPU frustum & two-phase HZB occlusion culling", gated to `std3d`. The lite3d/mobile tier (CPU-culled submission path, declared first-class) therefore has no occlusion culling at all: no CPU software occlusion, no precomputed visibility, no portals/cells, and no GPU occlusion-query readback. Mobile and 2.5D indoor games rely heavily on these.
- Evidence: Umbra PVS, shipped in Unity and many mobile titles. Intel Masked Software Occlusion Culling (Hasselgren et al., HPG 2016), used in Frostbite and Unity DOTS/Entities Graphics. UE precomputed visibility and software occlusion for mobile. Portal/cell culling in indoor games.
- Proposed change: Add `RND.GEO.cpu-occlusion` (CPU software occlusion rasterization, E, lite3d) and `RND.GEO.precomputed-visibility` (PVS/portals with a cook step, E), both owned by `geometry-pipeline`, with contributor `world-architect` for cell data. Make `RND.GEO.culling`'s frustum part unconditional and keep only the HZB two-phase part at std3d.

### K-RENDER-10 · major · missing-contract
- Target: vegetation-foliage, terrain, water-ocean, deformation-skinning, direct-lighting-shadows (RND.LIGHT.vsm), global-illumination (RND.GI.hybrid), ray-tracing-infrastructure
- Finding: Cached rendering structures have no invalidation contract: virtual shadow map page caches, surface/radiance caches, BLAS refit/rebuild, and cluster pages. The world-side renderers also lack the render contracts they need. `vegetation-foliage` owns "Vegetation instancing & rendering" but consumes no `C-MATIF`, `C-GEOLOD`, `C-RT` or `C-LIGHT`, although foliage is the main user of OMM, alpha-tested RT and WPO wind. `terrain` owns rendering (clipmaps/CDLOD/virtual) and runtime deformation but consumes no `C-RG`, `C-GEOLOD` or `C-TEMPORAL`. GPU-side animation (wind WPO, terrain deformation, GPU skinning) invalidates VSM pages and BLAS, and the `C-RSCENE` CPU delta streams cannot see it.
- Evidence: UE5 VSM cache invalidation is a known cost center: WPO foliage forces uncached pages, and UE added "Evaluate WPO" per-instance invalidation controls. Lumen surface-cache invalidation and Nanite Foliage (UE 5.7) are further cases. RTX Mega Geometry's partitioned TLAS exists largely for foliage and instance churn. OMM was motivated by foliage (Microsoft DXR 1.2 announcement).
- Proposed change: Add to `C-RSCENE` (or a new `C-INVALIDATE`, owner `render-architect`) a GPU/CPU invalidation channel: per-instance "deforms on GPU" flags, dirty-region/page invalidation, and BLAS-update requests, with producers `vegetation-foliage`, `terrain`, `deformation-skinning` and `water-ocean`. Add `C-MATIF?`, `C-GEOLOD?`, `C-RT?` and `C-LIGHT?` to `vegetation-foliage`, and `C-RG?`, `C-GEOLOD?` and `C-TEMPORAL?` to `terrain` (all optional, to keep the headless builds).

### K-RENDER-11 · major · missing-contract
- Target: reconstruction-upscaling (RND.RECON.denoise), path-tracing, direct-lighting-shadows, global-illumination, C-TEMPORAL
- Finding: The denoiser has no interface. `RND.RECON.denoise` ("spatiotemporal & ML denoising, ray reconstruction class") is owned by reconstruction-upscaling. Lighting and GI list "Denoisers" as a non-responsibility, but `C-TEMPORAL`'s summary has no denoiser input API (signal type, hit distance, sample count, guide buffers). `reconstruction-upscaling` consumes neither `C-LIGHT` nor `C-GI`. `path-tracing` owns real-time path tracing (M) but does not consume `C-TEMPORAL`, although RT path tracing depends on the denoiser or ray reconstruction. `path-tracing` consuming `C-GI?` is also backwards: the path tracer is the oracle GI is compared against, and the neural radiance cache already lists path-tracing as a contributor.
- Evidence: NVIDIA NRD (ReBLUR/ReLAX/SIGMA) takes per-signal inputs. DLSS 3.5 Ray Reconstruction replaces per-signal denoisers and upscaling in one pass, so the choice between "per-signal denoise then TAA" and "joint RR" has to sit behind one contract. Cyberpunk 2077 Overdrive and Indiana Jones PT both use RR.
- Proposed change: Extend `C-TEMPORAL` (or add `C-DENOISE`, owner `reconstruction-upscaling`) with a signal-submission API: noisy signal class, hit distance, sample count, guide buffers from `C-SCENETEX`, and a joint-RR mode. Add it to the consumes of `path-tracing`, `direct-lighting-shadows` and `global-illumination`. Replace `C-GI?` in path-tracing's consumes with `C-TEMPORAL` and `C-INSTANCES`.

### K-RENDER-12 · major · omission
- Target: RND.TOOL.*, post-color-hdr, character-rendering, texture-streaming-vt, translucency-decals, render-architect, world-editor-viewport
- Finding: Rendering tooling covers only the material editor, VFX editor, lighting placement, mesh LOD and tilemap/sprite. The following are missing: (a) color and post tooling: grading/LUT authoring, post-volume editing, and a color-managed HDR editor viewport and thumbnails, meaning the editor displays through the same output transform and paper white; (b) groom/hair and digital-human preview tooling; (c) texture/VT inspection (streaming state, mip bias, residency heatmaps); (d) decal placement/projection tools; (e) render scalability and device-profile authoring and preview-on-tier ("preview as mobile/lite3d"); (f) an in-engine frame/render-graph debugger (pass list, resource viewer, per-pass timings) beyond external PIX/RenderDoc capture. The brief requires tooling to be as thorough as the runtime.
- Evidence: UE has Post Process Volume/Color Grading panels, Groom editor, Texture Streaming accuracy view modes, Decal actors, Device Profiles plus Preview Rendering Level, and `r.RDG` visualizers/Render Resource Viewer. Unity HDRP has the Rendering Debugger and Volume framework. Frostbite's FrameGraph shipped with a graph visualizer (O'Donnell 2017).
- Proposed change: Add `RND.TOOL.color-post` (post-color-hdr), `RND.TOOL.groom` (character-rendering), `RND.TOOL.texture-inspect` (texture-streaming-vt), `RND.TOOL.decals` (translucency-decals), `RND.TOOL.scalability-preview` (render-architect, contributor runtime-scalability) and `RND.TOOL.frame-debugger` (render-graph-scheduling, contributor visual-debugging-tools), all E. Add `C-EDCMD`/`C-EDHOST` tool_consumes where missing (post-color-hdr, character-rendering, translucency-decals, texture-streaming-vt).

### K-RENDER-13 · major · other
- Target: milestones.json, C-RG, C-SHADER, C-GPUTIER, C-GPUMEM, C-MATIF, C-TEMPORAL, C-LIGHT, C-GI, C-GEOLOD, C-VT, C-RT
- Finding: The core render contracts are never frozen in any milestone. `C-RG` has 23 consumers and is drafted at M0 but never frozen. `C-SHADER`, `C-GPUTIER` (11 consumers) and `C-GPUMEM` are also never frozen. All render-feature contracts (`C-MATIF`, `C-TEMPORAL` with 11 consumers, `C-LIGHT`, `C-GI`, `C-GEOLOD`, `C-VT`, `C-RT`) have no freeze point, while M2 freezes `C-RSCENE` and `C-INSTANCES`, which depend on some of them. The feature agents parallelized in M2 would build on moving interfaces.
- Evidence: In practice render-graph APIs churn most in the first year (UE RDG's migration from the old RHI command-list style ran from 4.22 to 5.0). Freezing the scene contract before the graph and shader contracts it requires inverts the dependency order.
- Proposed change: Freeze `C-RG`, `C-SHADER`, `C-GPUMEM` and `C-GPUTIER` at M1, since the indie-2d slice exercises all four. Freeze `C-MATIF`, `C-TEMPORAL`, `C-LIGHT`, `C-GI`, `C-GEOLOD`, `C-VT`, `C-RT`, `C-DRAW2D` (already M1), and the new `C-SCENETEX`/`C-COLOR`/`C-TRANSLUCENT` at M2. Add a `check.py` rule: a frozen contract's `requires` must be frozen at the same or an earlier milestone.

### K-RENDER-14 · major · omission
- Target: render-2d-vector, seed-map "2.5D games", C-RSCENE, lite3d profile
- Finding: 2.5D has no owner. The seed map resolves the brief term "2.5D games" to `RND.2D.lighting` and `RND.ARCH.pipeline`. `render-2d-vector` is a screen/draw-list backend: it consumes no `C-RSCENE`, `C-MATIF` or `C-LIGHT` and has no world-space mode. The dominant forms of 2.5D (HD-2D sprites lit and shadowed in a 3D scene, paper-cutout/billboard characters in 3D levels, orthographic 3D with pixel-art post) need sprites as render-scene primitives that take 3D lighting, depth, shadows and DOF. `render-2d-vector` also consumes no texture contract (`C-VT`) for its atlases.
- Evidence: Square Enix HD-2D (Octopath Traveler, UE4) uses sprite billboards in a lit deferred 3D scene with DOF and tilt-shift post. Paper Mario and Don't Starve use cutout billboards in 3D. Unity URP 2D Renderer vs sprites in 3D (the "Sprite-Lit in 3D" limitations) shows the two paths diverge.
- Proposed change: Add `RND.2D.world-sprites` (world-space sprite/billboard/cutout primitives with 3D lighting and shadows; owner `render-2d-vector`, E, lite3d/std3d), register it as a `C-RSCENE` non-mesh primitive kind, and add `C-RSCENE?`, `C-MATIF?`, `C-LIGHT?` and `C-VT` to render-2d-vector's consumes. Remap seed-map "2.5D games" to include `RND.2D.world-sprites`, `RND.ARCH.submission-strategy` and `RND.POST.stylized`.

- Finding: "GPU instance data layout & delta upload" (render-architect) and "GPU scene & instance data management" (geometry-pipeline, which provides `C-INSTANCES`, "instance data layout … delta upload") describe the same thing. `render-architect` also consumes `C-INSTANCES?` while `geometry-pipeline` consumes `C-RSCENE`. ### K-RENDER-16 · minor · wrong-boundary
- Target: ray-tracing-infrastructure, gpu-platform-architect, C-RT
- Finding: `ray-tracing-infrastructure` sits under `gpu-platform-architect`, whose purpose is infrastructure "shared by every renderer tier" below the render pipeline. `C-RT` requires `C-RSCENE`, and the skill consumes `C-RSCENE`/`C-INSTANCES`, so the GPU-platform lead depends on the render-architect lead's contracts, inverting the stated split (docs/00 §111). `C-RT` advertises "hit/material binding", yet the skill does not consume `C-MATIF`. RT LOD needs `C-GEOLOD`, and cluster BLAS (RTX Mega Geometry) is built from virtualized-geometry clusters, but only a contributor tag links the two.
- Proposed change: Either re-parent `ray-tracing-infrastructure` under `render-architect`, or make `C-RT` require only `C-INSTANCES` plus `C-GPUMEM` and move scene coupling into the consumers. Add `C-MATIF` and `C-GEOLOD?` to its consumes.

### K-RENDER-17 · minor · maturity-error

- Finding: `RND.ARCH.multiview` is E but bundles N-view autostereo/light-field output, which the radar lists as M, so an established capability contains emerging scope. `RND.GEO.splats` is X, but static 3DGS rendering (sorting, compositing, LOD) ships in production web/engine runtimes; only relightable/dynamic splats (`RND.GEO.splat-relight`) are experimental. ### K-RENDER-18 · minor · omission
- Target: character-rendering, ray-tracing-infrastructure, radar
- Finding: `character-rendering` (strand hair, SSS, eyes) consumes no `C-TEMPORAL` (strands rely heavily on temporal accumulation and need per-strand motion vectors), no `C-RT?` (RT shadows and reflections of hair and skin) and no `C-INSTANCES`. The radar has no entry for hardware ray-traced curves/strands (linear swept spheres, Blackwell; DXR/Vulkan extensions 2025) or for dense geometry compression formats (AMD DGF, 2025), both of which affect how the RT and cluster-geometry formats are designed.
- Proposed change: Add `C-TEMPORAL`, `C-RT?` and `C-INSTANCES?` to character-rendering. Add radar entries "HW RT curve primitives (LSS)" (X, owner ray-tracing-infrastructure, fallback: hair cards or tube proxies in the BLAS) and "Hardware-decodable dense geometry formats (DGF)" (X, owner virtualized-geometry-lod).

### K-RENDER-19 · minor · wrong-owner
- Target: RND.RECON.specular-aa
- Finding: Specular/geometric anti-aliasing (normal-distribution filtering, Kaplanyan 2016; Tokuyoshi & Kaplanyan 2019/2021) is a change to roughness in the material BRDF evaluation, not a reconstruction pass. The reconstruction owner cannot implement it without editing shading code owned by material-system.
- Proposed change: Move `RND.RECON.specular-aa` to `material-system` with contributor `reconstruction-upscaling`.

### K-RENDER-20 · minor · wrong-boundary
- Target: ml-inference-runtime
- Finding: `ml-inference-runtime` is parented under `gpu-platform-architect` and gated to lite3d/std3d. Its `C-ML` contract, however, covers CPU and NPU backends consumed by audio (neural TTS/ASR), AI (learned agents) and the server target. Profile gating makes those consumers unavailable in min2d/minimal games (for example, an LLM-NPC narrative game on the `minimal` profile). A GPU-platform parent routes non-rendering disputes to a rendering lead.
- Proposed change: Re-parent to `core-runtime-architect` (or `engine-architect`), keeping `C-MLGPU` arbitration with `gpu-platform-architect` through `ML.RT.scheduling`. Set profiles to `all`, with `C-MLGPU` capabilities gated to lite3d/std3d.
