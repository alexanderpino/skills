# K-TOOLS · Tools & Editor Critic · Round 1 (blind)

Scope reviewed: data/capabilities.json, skills.json, contracts.json, critics.json, crosscutting.json, docs/00. Baseline numbers: the ED and CNT domains together hold 61 of 739 capabilities. Across all runtime domains, only about 6 capabilities name authoring or tool logic (`WLD.ENV.terrain-tools`, `UI.FW.authoring`, `PHY.DEST.authoring`, `AUD.CONTENT.authoring`, `RND.MAT.graph`, `GAM.SCR.visual`). Rendering alone has 130 capabilities. The brief requires tooling to be as thorough as runtime, and the data does not meet that bar.

### K-TOOLS-1 · blocker · wrong-boundary
- Target: docs/00 §4 ("End-to-end feature ownership"), crosscutting `tooling`, `C-EDCMD`, `C-GRAPH`, every user-facing domain skill
- Finding: The data never states the ownership model for domain editors ("domain skill owns tool logic; editor skills provide the host"), and the model is applied in only a few places. §4 limits it to environment features. Among domain skills, only `terrain?` and `cinematics-sequencer?` consume `C-EDCMD`. Only terrain and UI have a tool-logic capability. `vegetation-foliage`, `water-ocean`, `atmosphere-weather`, `procedural-generation`, `ui-architect` (it owns `UI.FW.authoring` but does not consume `C-EDCMD`), `destruction-fracture` (it owns `PHY.DEST.authoring` with no editor contract), `animation-*`, `audio-content-runtime`, `gameplay-systems-toolkit`, `navigation-pathfinding`, `ai-behavior-perception`, `world-data-model` (prefab/override editing) and `global-illumination` (bake UI) have no editor contract at all. The material editor shows the result: `graph-editor-framework` sends "domain graph semantics" to `material-system`, and `material-system` sends "graph editor UI" to `graph-editor-framework`. Nobody owns the material editor's preview viewport, parameter panel, instance editor or live-update loop. The same gap exists for the VFX editor (emitter stack, preview, timeline), the anim editors, the audio editors and the ability/tag editors. Two agents will either both build these or neither will. Edits made outside `C-EDCMD` also bypass universal undo, transactions and multi-user editing, which the critic check "undo/transactions universal" requires.
- Evidence: UE separates an asset editor toolkit and preview scene (host) from per-domain editor modules such as Niagara, Persona and the material editor (domain). Unity's UI Toolkit and GraphView host follows the same split. Without the split, every domain team rewrites undo and preview. The crosscutting obligation "declare authoring path for every user-facing feature" has no capability or contract behind it, so `check.py` cannot enforce it.
- Proposed change: (a) Add ownership pattern 4 to docs/00 §4: "Domain editor = domain tool logic (domain skill, editor module) + host (editor-architect subtree). Tool logic reaches the editor only through `C-EDCMD`, `C-EDHOST` and `C-GRAPH`." (b) Add a `<DOMAIN>.TOOL.*` capability for each user-facing domain: `RND.MAT.editor`→material-system, `RND.VFX.editor`→vfx-particles, `RND.GI.bake-tools`→global-illumination, `WLD.ENV.foliage-tools`→vegetation-foliage, `WLD.ENV.water-tools`→water-ocean, `WLD.ENV.sky-tools`→atmosphere-weather, `WLD.PCG.tools`→procedural-generation, `WLD.MODEL.prefab-editing`→world-data-model, `AUD.CONTENT.editor`→audio-content-runtime, plus the animation and gameplay items in K-TOOLS-4 and K-TOOLS-5. (c) Add contract `C-EDHOST` (L5, owner editor-ui-framework): asset-editor host, preview-scene registration, thumbnail providers, inspector customization, tool-mode registration. (d) Add a checker rule: every skill that owns a capability with a `.TOOL`/`.editor`/`tools` suffix must consume `C-EDCMD` in its tool-side consume list (see K-TOOLS-2).

### K-TOOLS-2 · major · missing-contract
- Target: skills.json schema (`runtime`, `consumes`), `terrain` (runtime=true, consumes `C-EDCMD?`), `C-COOK`/`C-EDCMD`/`C-GRAPH` (L5) consumed by L3 runtime skills
- Finding: The data model has no distinction between editor/tool modules and runtime modules. `terrain`, `cinematics-sequencer`, `material-system` and `vfx-particles` are runtime skills that consume L5 tool contracts through the same `consumes` list their shipping code uses. Configuration closure therefore cannot prove that shipping or server builds exclude editor code. The layering rule applies only to contract `requires`, so a runtime skill can depend upward on L5 without anything catching it. Once K-TOOLS-1 is fixed, most domain skills will do exactly this.
- Evidence: Editor/runtime module typing is how UE (Editor vs Runtime module types, `WITH_EDITOR`) and Unity (Editor assemblies) keep tool code out of shipping binaries. `ED.ARCH.separation` covers data separation only, not code or modules.
- Proposed change: Add `tool_consumes` (and optionally `tool_provides`) to skills.json. Require `C-EDCMD`, `C-EDHOST`, `C-GRAPH` and `C-COOK` to appear only in `tool_consumes` for runtime=true skills. Extend `check.py` so a runtime `consumes` entry cannot name an L5 contract. Split closure into a "shipping closure" and a "tool closure".

### K-TOOLS-3 · major · omission
- Target: ED.UI, ED.WORLD, `editor-ui-framework`, `world-editor-viewport`
- Finding: Several shared tool substrates have no owner: (1) a generic asset-editor host with tabs, a preview scene, per-asset viewers and inspection modes (texture mip/channel/format inspection, mesh wireframe/UV/LOD/collision/normal views); (2) thumbnail generation and caching; (3) a shared curve editor and timeline/dope-sheet widgets, which sequencer, animation, VFX, audio envelopes and UI animation all need (`CORE.MATH.curves` is only math); (4) preview scenes outside the world. `world-editor-viewport` is scoped to the world viewport only. Each domain will build its own preview and curve editor, which recreates the "six node editors" problem that §8 fixed for graphs.
- Evidence: UE has FAssetEditorToolkit, FAdvancedPreviewScene, SCurveEditor (shared by Sequencer, Niagara and Persona) and the thumbnail manager. Unity has the shared Timeline, AnimationCurve editor and PreviewRenderUtility.
- Proposed change: Add `ED.UI.asset-editor-host`→editor-ui-framework, `ED.UI.thumbnails`→editor-ui-framework (contributor content-pipeline-architect), `ED.UI.curves-timeline` ("Shared curve, timeline & dope-sheet editors")→editor-ui-framework (contributors cinematics-sequencer, animation-runtime, vfx-particles), and `ED.WORLD.preview-scenes` ("Isolated preview scenes & asset inspection viewports")→world-editor-viewport. All of these are exposed through `C-EDHOST`.

### K-TOOLS-4 · major · omission
- Target: ANM.*, PHY.COL, PHY.ARCH, `animation-architect`, `animation-runtime`, `ik-procedural-animation`, `collision-detection`
- Finding: Animation has 35 runtime capabilities and no authoring capabilities. The following are missing: a skeleton and skeletal-mesh editor (sockets, virtual bones, LOD bone reduction), retargeting tools (IK-rig/retarget-chain authoring; `ANM.RT.retargeting` covers only runtime), a clip/montage/notify editor, in-engine rigging and keyframe authoring (a Control Rig-class runtime rig graph, established in UE5), a physics-asset/ragdoll editor for body and constraint setup, a pose-database/motion-matching inspector, and simple-collision authoring (convex decomposition such as V-HACD/CoACD, collision primitive fitting). `PHY.COL.cook` covers only cooking.
- Evidence: UE Persona (Skeleton, Mesh, Animation and Physics Asset editors), the IK Rig/IK Retargeter, Control Rig and the pose-search debugger are core AAA animation tools. Animation teams spend most of their time in these editors, not in graph editing.
- Proposed change: Add `ANM.TOOL.skeleton-editor`→animation-architect, `ANM.TOOL.retarget-tools`→animation-runtime, `ANM.TOOL.clip-editing`→animation-runtime, `ANM.TOOL.rigging` ("In-engine rigging & keyframe authoring", E)→ik-procedural-animation, `ANM.TOOL.pose-db-debug`→motion-synthesis, `PHY.TOOL.physics-asset`→ik-procedural-animation (contributor rigid-body-dynamics), and `PHY.COL.decomposition` ("Convex decomposition & simple-collision generation")→collision-detection. All of them consume `C-EDCMD`/`C-EDHOST` as tool dependencies.

### K-TOOLS-5 · major · omission
- Target: GAM.*, `gameplay-architect`, `gameplay-systems-toolkit`, `ai-behavior-perception`, `navigation-pathfinding`, `editor-ui-framework`
- Finding: Designer-facing gameplay authoring is missing. Specifically: data tables and curve tables with spreadsheet round-trip (CSV/XLSX/cloud sheets), schema-driven data assets, bulk/tabular property editing across many assets, a gameplay-tag editor and dictionary management, ability/effect authoring, behavior-tree and state-tree editors (`ai-behavior-perception` consumes neither `C-GRAPH` nor `C-EDCMD`), environment-query testing tools, navmesh authoring (modifier/area volumes, nav links) with navigation debugging (tile, path and query visualization), and dialogue/quest authoring (no owner anywhere). `GAM.SCR.visual` names graph-editor-framework as a contributor, but `scripting-runtime` does not consume `C-GRAPH`.
- Evidence: Data tables and data assets drive most content on shipped games (UE DataTable/CurveTable/DataAsset, the Unity ScriptableObject and Odin workflow). Tags and GAS editors, BT/StateTree editors, the EQS testing pawn and the nav-mesh debug view are the everyday tools of design teams.
- Proposed change: Add `GAM.FW.data-assets` ("Designer data assets & data/curve tables: runtime format, schema, references")→gameplay-architect; `ED.UI.tabular` ("Tabular/bulk editing & spreadsheet round-trip")→editor-ui-framework; `GAM.SYS.authoring` ("Tag dictionary, ability & effect authoring")→gameplay-systems-toolkit; `GAM.AI.authoring` ("BT/state-tree/EQS editors & testing")→ai-behavior-perception; `GAM.AI.nav-tools` ("Nav modifiers, links, nav debugging")→navigation-pathfinding; `GAM.FW.narrative` ("Dialogue & quest data model and authoring")→gameplay-systems-toolkit (contributors localization-i18n, audio-content-runtime). Add `C-GRAPH?` to scripting-runtime and ai-behavior-perception.

### K-TOOLS-6 · major · omission
- Target: CNT.COOK, `C-COOK`, `world-architect`, `global-illumination`, `navigation-pathfinding`, `virtualized-geometry-lod`, `procedural-generation`, `spatial-audio-acoustics`
- Finding: Nobody orchestrates world-scoped derived data. Lightmaps, probe and reflection bakes, HLOD generation, static navmesh, PCG bake results, precomputed acoustic propagation (`AUD.SPAT.propagation`) and precomputed visibility all depend on many assets plus a world region. They must be invalidated when the world is edited, rebuilt per cell, distributed over a farm, and shown as stale in the editor. `C-COOK` is a per-asset processor contract with cache keys. `WLD.PART.hlod` covers only HLOD "generation orchestration". `ED.ARCH.headless` covers only commandlets. Each domain will build its own bake scheduler with its own invalidation rules.
- Evidence: UE has World Partition builders (HLOD, navigation, MiniMap), distributed Lightmass (Swarm) and GPU Lightmass. Frostbite's Flux bake farm and Enlighten precompute pipelines are dedicated world-build infrastructure, separate from asset cooking.
- Proposed change: Add `CNT.COOK.world-build` ("World-scoped derived-data build graph: region/cell invalidation, distributed bakes, staleness reporting")→content-pipeline-architect (contributors world-architect, ci-cd-automation). Extend `C-COOK` with a world-scope step kind (inputs = world region plus asset set). Domain skills keep their bake algorithms under the format-owner pattern.

### K-TOOLS-7 · major · omission
- Target: ED.ARCH, `editor-architect`, `crash-diagnostics`, QA.FUNC, PRF.LOAD
- Finding: No capability covers editor stability or editor quality: autosave, transaction journaling, crash recovery and restoring unsaved work are all missing (`GAM.SAVE.checkpoints` is game autosave). Editor functional and UI automation tests, tool regression tests and editor soak tests are missing (QA.FUNC is game-only). Editor performance budgets are missing: editor startup, asset-open time, PIE start time, viewport frame rate in large worlds, and editor memory ceiling. `PRF.LOAD.startup` is game startup, and `ED.ARCH.scale` is a one-line catch-all. The test and performance skills have no editor-facing territory, so tooling is not covered by the brief's "dedicated ownership for testing and performance".
- Evidence: UE has an editor crash-recovery and autosave system, Automation Spec/Functional Tests running in the editor, and Insights-driven editor-startup work (DDC and shader compile dominate first-open time). At 1000-person scale, editor crash rate and startup time are tracked KPIs.
- Proposed change: Add `ED.ARCH.recovery` ("Autosave, transaction journal, crash recovery")→editor-architect (contributor crash-diagnostics), `QA.FUNC.editor` ("Editor/tool automation & regression testing")→functional-automation-soak (contributor editor-ui-framework), and `PRF.LOAD.editor` ("Editor startup, asset-open, PIE-start and large-world viewport budgets")→loading-streaming-performance (contributor editor-architect). Add editor-architect to K-PERF and K-QUALITY scope explicitly.

### K-TOOLS-8 · major · omission
- Target: ED.ARCH.remote, OBS.LOG.remote, XC.ITER, PLAT.CON.devkit, CNT.COOK
- Finding: No one owns the iteration loop to target devices. Missing pieces: a development host↔target connection service (discovery, transport, auth), cook-on-the-fly and network file serving to devkits and phones, incremental deploy/"launch on device", and pushing iterative cooked deltas to running targets. Three capabilities (`ED.ARCH.remote`, `OBS.LOG.remote`, `XC.ITER.coordination`) plus visual-debugging-tools' remote console each assume a device channel without owning it, so each will build its own transport.
- Evidence: UE has Zen server streaming cooked data to targets, cook-on-the-fly, the Launcher/Turnkey and the Unreal Insights/remote session channel. Console and mobile iteration time is dominated by deploy and cook latency, not compile time.
- Proposed change: Add `PLAT.PAL.devlink` ("Development host↔target connection service")→platform-architect, consumed by editor-architect, observability-telemetry, hot-reload-iteration and visual-debugging-tools. Add `CNT.COOK.on-the-fly` ("Cook-on-the-fly, network file serving & incremental deploy to devices")→content-pipeline-architect (contributors platform-console, platform-mobile-portable).

### K-TOOLS-9 · major · omission
- Target: ED.COLLAB, `collaboration-version-control`, `ci-cd-automation`
- Finding: Collaboration at 100–1000 people is missing its main workflow pieces. First, prebuilt editor/tool binaries matched to content revisions for non-programmers (no one compiles C++ to open the editor). Second, sparse or virtualized workspace sync, with payloads fetched on demand. Third, a team-shared DDC and cloud cache as infrastructure. `CNT.COOK.ddc` defines the cache but not its deployment. Fourth, per-user and per-team workspace scoping for open worlds (sync only the world region you edit). `ED.COLLAB.binaries` ("Large binary storage strategy") covers storage, not sync or distribution.
- Evidence: Unreal Game Sync (precompiled binaries per changelist), UE Virtual Assets, Perforce virtual streams and partial sync, and shared/cloud DDC are standard at AAA scale. Without them, content creators wait hours on sync and compile.
- Proposed change: Add `ED.COLLAB.binary-distribution` ("Prebuilt editor/tool binaries matched to content revision")→ci-cd-automation (contributor collaboration-version-control), `ED.COLLAB.partial-sync` ("Sparse/virtualized workspace & on-demand payloads")→collaboration-version-control, and `CNT.COOK.shared-cache` ("Team/cloud DDC deployment & cache health")→content-pipeline-architect (contributor ci-cd-automation).

### K-TOOLS-10 · major · omission
- Target: OBS.LOG.profilers, PRF.BENCH.dashboards, NET.REP, `observability-telemetry`, `replication`
- Finding: No one owns engine-aware profiler UIs. `OBS.LOG.profilers` only integrates Tracy/PIX-class tools, which lack engine semantics. Nothing covers a trace viewer for task-graph and frame-phase timelines, asset-loading and streaming timelines, memory attribution by tag and asset, or GPU passes by render-graph pass. There is no network profiler (bandwidth per replicated property, per connection and per actor) and no replication debugger, although NET has 34 capabilities. Content creators and technical artists cannot diagnose their own content without these tools.
- Evidence: Unreal Insights (Timing, Memory, Networking, Asset Loading insights) exists because third-party profilers lack engine semantics. Other examples are the UE Network Profiler, Unity Profiler modules and Frostbite's in-house tooling.
- Proposed change: Add `OBS.LOG.trace-analysis` ("Engine-aware trace analysis & profiler UI")→observability-telemetry (contributors job-system-task-graph, resource-streaming-architect, memory-allocators, render-graph-scheduling). Add `NET.REP.profiler` ("Network profiler & replication debugger")→replication (contributor visual-debugging-tools).

### K-TOOLS-14 · major · wrong-owner
- Target: `hot-reload-iteration` non_responsibilities, `C-RELOAD` consumer set
- Finding: `hot-reload-iteration` lists "Each system's own reload implementation → resource-streaming-architect". This is wrong. `RND.SHADER.reload` belongs to shader-system and `GAM.SCR.reload` to scripting-runtime, and the material, animation, audio, UI, localization, config and world owners implement their own reloads. Only shader-system and scripting-runtime consume `C-RELOAD`. ecs-runtime is missing from the consumer list even though live coding with component-layout changes requires state migration there, and so are core-runtime-architect (cvar/config reload), material-system, ui-architect, localization-i18n, world-data-model and audio-content-runtime. `hot-reload-iteration` also does not consume `C-BUILD`, although C++ live coding needs toolchain and linker integration.
- Evidence: Live++ and UE Live Coding need compiler/linker cooperation. State-preserving reload requires every holder of reloadable state to participate, which is docs/00's own argument for making reload cross-cutting.
- Proposed change: Change the non-responsibility to ["Each system's own reload implementation", "the owning domain skill (via C-RELOAD)"]. Add `C-RELOAD` (as a tool-side or dev-build dependency) to ecs-runtime, core-runtime-architect, material-system, ui-architect, localization-i18n, world-data-model, audio-content-runtime and animation-runtime. Add `C-BUILD` to hot-reload-iteration.

### K-TOOLS-15 · major · overlap
- Target: `UI.FW.architecture` (ui-architect, "immediate for dev UI"), `ED.UI.imgui` (editor-ui-framework), `ED.DEBUG.menus` (visual-debugging-tools)
- Finding: Two skills own immediate-mode developer UI: ui-architect's architecture capability and editor-ui-framework's `ED.UI.imgui`. It is also misplaced. In-game debug menus and consoles run in development builds on consoles and phones, but editor-ui-framework is runtime=false and profile `client`, and it provides no contract. visual-debugging-tools (runtime, all profiles) therefore has no contract to draw its UI with. The ADR on whether the editor toolkit dogfoods the game UI framework (retained editor UI on `C-UI`) or is a separate framework has no owner.
- Evidence: Dear ImGui-class dev UI is linked into game builds. UE Slate is shared by editor and runtime. Unity UI Toolkit deliberately unified editor and runtime UI. Either choice is valid, but one skill has to own it.
- Proposed change: Move `ED.UI.imgui` to visual-debugging-tools, or to ui-architect with editor-ui-framework as contributor, and remove "immediate for dev UI" from whichever capability does not own it. Have the owner provide a runtime `C-DEVUI` contract (L3). Add an explicit capability `ED.UI.toolkit-basis` ("Editor toolkit basis: shared vs separate from game UI (ADR)") to editor-ui-framework with contributor ui-architect.

### K-TOOLS-16 · major · wrong-boundary
- Target: `ED.AI.processing`, `ai-assisted-authoring` (profile `aaa`), docs/00 §8 ("All geometric LOD belongs to virtualized-geometry-lod")
- Finding: `ED.AI.processing` ("ML-assisted retopology, rigging, UV, LOD") gives LOD generation to ai-assisted-authoring. Keep ai-assisted-authoring for copilots, generative-tool hosting, evaluation harnesses and provenance. Change its profile to `client`, gated by an ADR, or add a production-scale dimension (see K-TOOLS-19).

- Target: `ED.ARCH.pie`, `editor-architect` consumes

### K-TOOLS-19 · minor · scale-down
- Target: skills.json profiles for the editor-architect subtree (`client`), content-pipeline-architect subtree (`all`)
- Finding: Tool skills are gated by runtime profiles. `indie-2d` therefore pulls in multi-user editing, Perforce-class locking, distributed cooking and partition-aware editing with no way to omit them. `dedicated-server` excludes the editor although headless commandlets (`ED.ARCH.headless`) build server content. ### K-TOOLS-20 · minor · other
- Target: critics.json `K-TOOLS` scope, `graph-editor-framework` non_responsibilities
- Finding: The K-TOOLS G2/S2 scope leaves out most skills that own tool logic: material-system, vfx-particles, global-illumination (baking), vegetation-foliage, water-ocean, atmosphere-weather, the animation subtree, audio-content-runtime, gameplay-systems-toolkit, ai-behavior-perception, navigation-pathfinding, visual-debugging-tools and localization-i18n. Separately, graph-editor-framework's non-responsibility names only material-system as the owner of "each domain's graph semantics", which misattributes animation, VFX, audio, PCG and visual-script semantics.
- Evidence: A domain authoring path that no tools critic reviews will fail the "tooling as thorough as runtime" check without anyone noticing. The non-responsibilities list is the mechanism the brief relies on to prevent overlapping edits.
- Proposed change: Add to K-TOOLS scope: every skill that owns a `*.TOOL.*`/authoring capability (can be generated from data). Change the graph-editor-framework non-responsibility to one entry per graph-owning domain (material-system, animation-graphs, vfx-particles, audio-content-runtime, procedural-generation, scripting-runtime, ai-behavior-perception).
