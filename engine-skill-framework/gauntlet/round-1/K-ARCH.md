# K-ARCH · Engine Architecture Critic · Round 1

Scope: architectural completeness and subsystem boundaries. Findings are ordered most severe first. The structural checker (`check.py`) passes with 0 errors. Every finding below is something it cannot see. Where a finding cites a configuration closure, it was computed with `scripts/model.py`, using the same membership and closure rules as `check.py`.

### K-ARCH-1 · blocker · scale-down
- Target: terrain, water-ocean, vegetation-foliage, destruction-fracture, fluid-simulation, facial-animation, ml-inference-runtime; configurations `dedicated-server`, `aaa-open-world-online`; WLD.PART.server
- Finding: The server side of the flagship configuration cannot be built. The only server configuration is `[server, online]`, which contains no open-world skill. The configurations `[server, online, openworld]` and `[server, online, openworld, aaa]` are **not closed**. For the first, closure fails on terrain→C-RSCENE/C-MATIF, vegetation-foliage→C-RSCENE and water-ocean→C-RSCENE/C-RG. The aaa variant adds failures for destruction-fracture→C-RSCENE, fluid-simulation→C-RG, facial-animation→C-AUDIO, ml-inference-runtime→C-RHI/C-RG and others. The cause is the "end-to-end feature ownership" pattern (principles §4) combined with *required* render contracts. The skills that own authoritative simulation data (heightfields for collision and navmesh, water height and flow for buoyancy, fracture state for replication) can only exist alongside a renderer. WLD.PART.server ("server-side world streaming") therefore has nothing to stream on the server.
- Evidence: Authoritative open-world servers need terrain collision, water queries and destruction state without a GPU. UE dedicated servers strip rendering but keep Landscape collision and Chaos destruction. MMO and survival servers work the same way. C-ML requires C-RHI, which also makes CPU inference for server-side AI (GAM.AI.learned) impossible.
- Proposed change: (a) Add a contract `C-ENV` (layer 3, owner world-architect): environment data and queries covering height, surface type, water height and velocity, and deformation deltas. It requires C-WORLD and C-SPATIAL. terrain, water-ocean and vegetation-foliage implement it, and collision-detection, navigation-pathfinding, character-vehicle-physics and spatial-audio consume it. (b) Mark C-RSCENE, C-MATIF and C-RG as optional (`?`) in terrain, water-ocean, vegetation-foliage, destruction-fracture and fluid-simulation, and require each SKILL.md to define a headless mode. (c) Make C-ML require `C-RHI?` so that inference has a CPU-only path. (d) Add the configurations `open-world-server` = [server, online, openworld] and `aaa-server` = [server, online, openworld, aaa], so that `check.py` proves them closed.

### K-ARCH-2 · blocker · missing-contract
- Target: gpu-driven-pipeline, virtualized-geometry-lod, texture-streaming-vt, direct-lighting-shadows, global-illumination, render-architect (C-RSCENE)
- Finding: 18 render experts sit under one lead, and 12 of them provide **no contract**. Yet their data is consumed across features:
  - The GPU scene, instance buffers and HZB/culling results (gpu-driven-pipeline) are needed by VSM (direct-lighting-shadows), RT instance management (ray-tracing-infrastructure), GI surface caches and vegetation.
  - Cluster/LOD selection (virtualized-geometry-lod) is needed by RND.RT.lod, RND.RT.cluster-blas, VSM page rendering and deforming LOD.
  - The VT page table and feedback (texture-streaming-vt) are needed by terrain ("Virtual texturing core → texture-streaming-vt") and material-system.
  - The light grid and shadow sampling (direct-lighting-shadows) are needed by translucency-decals, atmosphere (volumetric fog), water and VFX.
  - GI/radiance-cache sampling is needed by translucency, water, VFX and hair.

  The only channel for all of this is C-RSCENE, which the lead owns. Either agents reach into each other's internals, or C-RSCENE becomes an unbounded grab bag that every render agent edits. There is also an overlap. RND.ARCH.scene-sync ("render scene representation", owned by render-architect) and RND.GEO.gpu-scene ("GPU scene & instance data", owned by gpu-driven-pipeline) describe the same data structure in a GPU-driven renderer.
- Evidence: UE5's GPUScene, Nanite and VSM interplay is a set of explicit interfaces (VSM renders through Nanite's cluster culling, and Lumen consumes mesh SDF and surface cache data). Frostbite and Decima GPU-driven talks (Wihlidal, GDC 2016; Haar/Aaltonen, SIGGRAPH 2015) treat instance data and culling output as shared producer/consumer interfaces.
- Proposed change: Add layer-3 contracts:
  - `C-GPUSCENE`, owned by gpu-driven-pipeline: instance data layout, culling output and HZB. Move RND.ARCH.scene-sync's GPU half into it. render-architect keeps only the CPU proxy registry and the sync protocol.
  - `C-GEOLOD`, owned by virtualized-geometry-lod: cluster/LOD selection and page residency for raster, shadow and RT consumers.
  - `C-VT`, owned by texture-streaming-vt: page tables, feedback and VT allocation for terrain and materials.
  - `C-LIGHTS`, owned by direct-lighting-shadows: light lists, clustered grid and shadow sampling.
  - `C-GISAMPLE`, owned by global-illumination: an irradiance/radiance query interface for forward, translucent and volumetric consumers.

  Update the consumers' `consumes` lists to match.

### K-ARCH-3 · major · wrong-boundary
- Target: C-SPATIAL, C-PHYS, C-ANIM, C-AUDIO, C-NET, C-GAME (requires C-ECS); render-architect, audio-architect, world-architect, network-architect (consume C-ECS)
- Finding: ECS is a hard build-level prerequisite of the transform contract and of every subsystem contract. This contradicts the stated default in §6: a "hybrid object model; not ECS for everything", with CORE.OBJ.hybrid owned by entity-object-model. It also contradicts the replaceability claim ("C-PHYS can be served by an integrated middleware"), because the contract itself is shaped by ECS component access. Contracts that declare "components, queries, command buffers" as a dependency leak the object-model internals into physics, audio and network APIs. As specified, an agent implementing C-SPATIAL or C-PHYS will write ECS systems by default. That is the dogmatic-ECS failure the brief forbids, arrived at by the dependency graph rather than by an ADR.
- Evidence: Jolt, PhysX and Havok own their body storage and are bridged to ECS by adapter systems (Unity Physics/Havok in DOTS, UE Mass↔Chaos). Wwise and FMOD are object/emitter-ID based. Replication in UE Iris is keyed by NetRefHandle and is not tied to one object model.
- Proposed change: Change `requires` as follows:
  - C-SPATIAL → [C-MATH, C-ID]
  - C-PHYS → [C-SPATIAL, C-FRAME, C-ID]
  - C-ANIM → [C-SPATIAL, C-ID]
  - C-AUDIO → [C-SPATIAL, C-ID]
  - C-NET → [C-ID, C-SER, C-FRAME]
  - C-GAME → [C-ID, C-FRAME, C-WORLD]

  Make C-ECS optional (`C-ECS?`) in render-architect, audio-architect, physics-architect, animation-architect, network-architect, world-architect and spatial-transforms. Add a capability `CORE.ECS.bridges` ("ECS↔subsystem adapter systems and sync points") owned by ecs-runtime, with the subsystem leads as contributors. entity-object-model's hybrid policy then decides *per configuration* whether ECS is the host.

### K-ARCH-4 · major · missing-contract
- Target: prediction-rollback (NET.PRED.rollback, NET.PRED.lagcomp), physics-architect (C-PHYS), animation-architect (C-ANIM), ecs-runtime, determinism-replay (C-DET)
- Finding: Rollback and resimulation need every participating subsystem to snapshot, restore and re-step N frames in a single frame. Lag compensation also needs historical collision state. No contract carries this obligation. C-PHYS is "bodies, shapes, queries, contact events, stepping phases", C-DET is "state-hash hooks", and C-SAVE is save-game granularity. prediction-rollback cannot reach this capability without modifying the physics, animation and ECS internals.
- Evidence: GGPO-class rollback requires save/load/advance callbacks per subsystem. UE's Network Prediction plugin and Chaos resim cache, Photon Quantum and Overwatch's ECS rollback (Ford, GDC 2017) all make snapshot and restore an explicit subsystem interface. Box2D v3 and Jolt state recorders exist for this reason.
- Proposed change: Add a contract `C-SNAPSHOT` (layer 2, owner determinism-replay): frame-state snapshot, restore, resimulate, history ring and cost declaration. It requires C-FRAME and C-SER. physics-architect, animation-architect, ecs-runtime and gameplay-architect implement it. prediction-rollback and replication (NET.REP.replays) consume it. Add the capability `XC.DET.snapshot` with owner determinism-replay.

### K-ARCH-5 · major · dependency-error
- Target: shader-system, localization-i18n (consume C-COOK layer 5), material-system (consumes C-GRAPH layer 5), texture-streaming-vt, virtualized-geometry-lod, content-pipeline-architect (runtime=true), shader-system (requires C-RELOAD); configuration `dedicated-server`
- Finding: Layering is checked only on contract→contract `requires` edges. A skill's *consumption* is never checked against the layer it provides. Runtime providers at layer 3 therefore hard-depend on layer-5 tool contracts (shader-system→C-COOK, localization-i18n→C-COOK, material-system→C-GRAPH). determinism-replay provides layer 1 but consumes C-SER at layer 2, and ml-inference-runtime provides layer 2 but consumes C-RG at layer 3. The "format owner vs pipeline host" pattern makes one skill span runtime and tool code, but the data has no notion of which module side a dependency belongs to. The effect is visible in configurations. The `dedicated-server` configuration contains asset-import-interchange (FBX/USD importers) and asset-cook-processors, and shader-system requires C-RELOAD (hot reload) with no `?`, so shipping builds must include it.
- Evidence: UE separates Runtime, Editor and Developer module types, and the shipping target refuses Developer/Editor modules. Frostbite and Decima keep their pipeline builders in separate tool binaries. A fitness function (ARCH.GOV.fitness) cannot enforce what the data does not express.
- Proposed change: Add `consumes_tool: [...]` to the skill schema, alongside `consumes`, for dependencies used only by the cook or editor module. Move C-COOK, C-GRAPH and C-EDCMD into that list for every runtime skill. Add a `check.py` rule: every required runtime consumption must be at a layer ≤ the lowest layer the skill provides, or be listed as an explicit, justified exception. Give content-pipeline, importer and cook skills a `tooling` profile token that runtime-only closures (server, shipping) exclude. Make C-RELOAD optional in shader-system.

### K-ARCH-6 · major · overlap
- Target: RES.MGMT.streaming (resource-streaming-architect), RND.MEM.residency and RND.MEM.budget (gpu-memory-resources), RND.TEX.mip-streaming (texture-streaming-vt), RND.LOD.streaming (virtualized-geometry-lod), AUD.DSP.streaming (audio-dsp-mixing), WLD.PART.sources (world-architect), C-RES, C-GPUMEM
- Finding: At least five skills own "streaming budgets, priority and eviction", and nothing arbitrates between them. C-RES requires only C-MEM (CPU). C-GPUMEM has its own residency and budget, and neither contract references the other. On UMA consoles and mobile (CORE.MEM.uma, PLAT.CON.os-memory), texture mips, cluster pages, audio banks and world cells all compete for one physical pool. Under memory pressure, each streamer will evict by its own policy and they will fight each other, because no skill owns a single cross-pool priority space.
- Evidence: UE5 exposes separate texture/Nanite/VSM pools and needs manual pool tuning, which is a known production pain point. Spider-Man and Insomniac GDC talks, and Decima streaming (Guerrilla, GDC 2017/2018), describe a central priority system across asset types on fixed-memory consoles.
- Proposed change: Add the capability `RES.MGMT.arbitration` ("cross-pool residency arbitration: a single priority/deadline space across CPU, GPU and UMA, pressure signalling") with owner resource-streaming-architect and contributors gpu-memory-resources and performance-architect. Extend C-RES with "pool registration, pressure callbacks and priority submission". The texture, cluster and audio streamers become *clients* that submit priorities and honour evictions. gpu-memory-resources exposes residency pressure to C-RES through a phase-mediated signal. RND.MEM.budget then becomes enforcement only.

### K-ARCH-7 · major · other
- Target: engine-architect (28 direct children), render-architect (18 children), ARCH.STRUCT.arbitration, C-ORCH
- Finding: The arbitration topology does not scale. engine-architect is the parent and the "final authority on boundaries" for 11 cross-cutting skills, 14 leads, ml-inference-runtime and the two other orchestrators. render-architect alone arbitrates 18 experts and also owns C-RSCENE, which every render and environment agent needs to change. With about 120 concurrent agents, every cross-domain dispute and every C-RSCENE change is serialized through two skills. The GPU-platform experts (rhi-core, gpu-memory-resources, render-graph-scheduling, shader-system, ray-tracing-infrastructure) have different expertise and a different change rate from the feature experts, yet they share one lead.
- Evidence: Production render teams are structured as "render core/RHI" plus "render features" (the UE RHI and RenderCore modules vs the Renderer and feature teams; Frostbite's "FrameGraph" platform group vs the lighting and feature groups). The principles' own split rule is "different literatures or change at different rates."
- Proposed change: Add a lead `gpu-platform-architect` under engine-architect. Move rhi-core, gpu-memory-resources, render-graph-scheduling, shader-system, ray-tracing-infrastructure and ml-inference-runtime under it, and move RND.ARCH.threading to it. render-architect keeps the pipeline, the features and C-RSCENE. Add an explicit `ARCH.ORG.escalation` capability to program-orchestration: an arbitration SLA and delegated arbitration, where a dispute inside one lead's subtree is settled by that lead and only a cross-lead dispute reaches engine-architect.

### K-ARCH-8 · major · wrong-owner
- Target: accessibility (UI.A11Y.vision, UI.A11Y.text-scale, UI.A11Y.subtitles, UI.A11Y.screen-reader), C-A11Y (layer P), runtime cycle accessibility↔input-system↔ui-architect
- Finding: accessibility is runtime=true and owns runtime features, but provides only a *process* contract (C-A11Y, layer P). No runtime consumer can bind to its screen-reader/TTS bridge or to its subtitle service. It also owns implementations that belong to other skills' expertise:
  - Colorblind filters are a post-process pass, but post-color-hdr is only a contributor.
  - Text scaling is a layout-engine property of ui-architect.
  - Subtitle presentation is a UI widget, and its timing data comes from audio-content-runtime.

  This is the "policy vs implementation" pattern (§4), applied inconsistently. It also causes the only runtime cycle the checker reports: accessibility requires C-UI and C-INPUT, while input-system requires C-A11Y.
- Evidence: Xbox Accessibility Guidelines and Apple/Android accessibility APIs are exposed as an *accessibility tree* exported by the UI framework, and a screen reader consumes that tree (UE Slate accessibility, Unity 2023 accessibility hierarchy). Colorblind simulation and correction ship as tonemap-stage passes.
- Proposed change: accessibility keeps UI.A11Y.requirements, UI.A11Y.validation, UI.A11Y.assists (policy) and UI.A11Y.screen-reader (platform bridge). Add a runtime contract `C-A11YRT` (layer 3, owner accessibility): announcements, accessibility-tree ingestion and TTS/STT. It requires C-PAL and C-TEXT and does **not** require C-UI. ui-architect exports the tree into it. Move UI.A11Y.vision to post-color-hdr, UI.A11Y.text-scale to ui-architect, and subtitle presentation to ui-architect, with caption data remaining in audio-content-runtime (AUD.CONTENT.dialogue). In input-system, change `C-A11Y` to a process obligation only. The cycle disappears.

### K-ARCH-9 · major · overlap
- Target: XC.DET.replay (determinism-replay), INP.ACT.recording (input-system), NET.REP.replays (replication), ED.DEBUG.visual-log (visual-debugging-tools), ANM.GRAPH.debug "rewind" (animation-graphs), QA.FUNC.automation
- Finding: Five skills own some form of record/replay/rewind, and the wording hides the overlap: "input & state record/replay", "input recording & replay", "replay recording from the replication stream", "visual logger & rewind", "graph debugging & rewind". There is no shared container format, timeline or versioning owner, so the result will be three or more replay formats with separate build-compatibility rules. XC.DET.compat already claims "replay compatibility across builds" for only one of them.
- Evidence: UE has separate DemoNetDriver replays, Rewind Debugger and Visual Logger, and has spent years unifying their timelines (the Chaos Visual Debugger and Rewind Debugger integration). Killcams and spectating in shipped titles reuse the network replay, not a separate one.
- Proposed change: determinism-replay owns a new capability `XC.DET.replay-format` ("replay container, timeline, stream registration and versioning") and provides a new contract `C-REPLAY` (layer 2). input-system, replication, visual-debugging-tools and animation-graphs become *stream producers* that register streams through C-REPLAY. Rename INP.ACT.recording to "Input stream capture for C-REPLAY" and NET.REP.replays to "Replication stream capture for C-REPLAY".

### K-ARCH-10 · major · overlap
- Target: CORE.FRAME.latency (frame-orchestration), RND.RHI.present (rhi-core), RND.RECON.framegen and RND.RECON.dynres (reconstruction-upscaling), PLAT.XR.reprojection (xr-runtime), PLAT.PAL.cloud-streaming, C-FRAME, C-RHI
- Finding: Four skills own parts of the *present timeline* and no contract states its semantics:
  - pacing and latency markers (frame-orchestration);
  - swapchain, present modes and VRR (rhi-core);
  - frame generation, which changes present cadence, latency and pacing (reconstruction-upscaling);
  - XR reprojection and predicted display time (xr-runtime).

  C-FRAME lists "pipelining depth", and C-RHI lists "presentation". Frame generation, Reflex/Anti-Lag 2, VRR and XR compositor timing must agree on a single model of which frame is presented when, and on its input sample time.
- Evidence: DLSS Frame Generation requires Reflex integration and changes the pacing API. FSR 3 frame-gen ships its own swapchain proxy that replaces the engine's present. OpenXR xrWaitFrame/xrBeginFrame dictate frame timing. These are well-known integration conflicts when each piece is owned separately.
- Proposed change: Add a contract `C-PRESENT` (layer 2, owner frame-orchestration): the present timeline, display-time prediction, latency markers, interposed presenters (frame gen, XR compositor, cloud encoder) and pacing policy. It requires C-FRAME and C-RHI. rhi-core, reconstruction-upscaling, xr-runtime and platform-architect (cloud) implement presenter hooks through it. Mark RND.RECON.framegen with frame-orchestration as a contributor.

### K-ARCH-11 · major · missing-contract
- Target: GAM.SYS.camera (gameplay-systems-toolkit), ANM.CINE.cameras (cinematics-sequencer), ED.WORLD.viewport (world-editor-viewport), GAM.SYS.photo, PLAT.XR (head pose), RND.POST.camera, C-RSCENE "views", WLD.PART.sources, AUD listener
- Finding: The authoritative view has no owner. At least six skills produce a camera or view: gameplay, cinematic, editor, photo mode, XR head pose and split-screen. At least five consume it: renderer views, the audio listener, world streaming sources, LOD and significance, and large-world-coordinate camera-relative rebasing. No capability owns "which view is active, blending between view sources, and view-dependent signals." The gameplay camera sits in a gameplay toolkit at layer 4, but editor and XR must drive views without gameplay.
- Evidence: UE splits this into PlayerCameraManager, ViewTarget and SceneView, with the camera manager arbitrating sources. Many engines hit camera-relative precision bugs precisely where the view origin and the LWC rebase are owned separately.
- Proposed change: Add a capability `WLD.SPACE.views` ("view registry and arbitration: active views, view origin for LWC rebasing, listener and streaming-source derivation") owned by spatial-transforms. Add a contract `C-VIEW` (layer 2) that requires C-SPATIAL. gameplay-systems-toolkit, cinematics-sequencer, world-editor-viewport and xr-runtime become view *sources*. render-architect (C-RSCENE views), audio-architect and world-architect (streaming sources) become view *sinks*.

### K-ARCH-12 · major · dependency-error
- Target: input-devices-haptics, input-system, C-INPUT, INP.DEV.haptics, AUD.CONTENT.haptics, PLAT.XR.input
- Finding: The layering is inverted. The device layer (input-devices-haptics) *consumes* the action contract C-INPUT and provides nothing, while input-system consumes only C-PAL. That means device events reach input-system either through undeclared internals or by device code writing into the action layer. Haptics output (rumble, HD haptics, adaptive triggers) has no contract at all, although audio-content-runtime (audio-to-haptics), gameplay and accessibility must drive it.
- Evidence: GameInput and SDL3 separate device state and events from action mapping, and haptics output is a device-level API. Unity's Input System separates devices and controls from actions for the same reason.
- Proposed change: Add a contract `C-DEVICE` (layer 2, owner input-devices-haptics): device state and events with timestamps, user pairing, and haptics/force-feedback output. It requires C-PAL. input-system consumes C-DEVICE, and input-devices-haptics drops C-INPUT. audio-content-runtime, xr-runtime and gameplay-systems-toolkit consume `C-DEVICE?` for haptics.

### K-ARCH-13 · major · wrong-boundary
- Target: build-release-architect (BLD.CI.branching, BLD.CI.versioning, BLD.CI.orchestration); content-pipeline-architect, resource-streaming-architect, ui-architect, security-engineering, api-lifecycle-migration (parents of fewer than 3 experts)
- Finding: build-release-architect provides **no contract** and consumes only its own children's contracts. Principles §2 forbids exactly this ("a lead never exists only to coordinate"). Its territory also overlaps other skills:
  - BLD.CI.orchestration ("code → content → package pipeline orchestration") overlaps BLD.CI.pipelines (ci-cd-automation) and ARCH.ORG.integration (program-orchestration).
  - BLD.CI.versioning overlaps XC.EXT.versioning and XC.EXT.lts (api-lifecycle-migration).

  Separately, five parents break the stated rule "a lead exists only where a domain has at least three experts": content-pipeline-architect has 2, resource-streaming-architect 2, ui-architect 2, security-engineering 1 and api-lifecycle-migration 2. So the rule the hierarchy claims is not the rule it follows.
- Proposed change: Give build-release-architect a contract `C-RELEASE` (layer P): the branch model, release trains, version identifiers, and client/server/content compatibility keys. Its consumers are packaging-release-patching, api-lifecycle-migration, collaboration-version-control and network-architect (NET.ARCH.versioning). Move BLD.CI.orchestration to ci-cd-automation. Restate the lead rule in §2 as "≥3 experts **or** owns a layer-defining contract (C-ASSET/C-COOK, C-RES, C-UI, C-TRUST, C-API)", and add that rule to `check.py` so that the hierarchy and the principle cannot drift apart again.

### K-ARCH-14 · major · wrong-boundary
- Target: ray-tracing-infrastructure (profile aaa), RND.RT.software, RND.GI.sdf, path-tracing (profile aaa), QA.RENDER.reference, global-illumination
- Finding: The owner of RND.RT.software, the software ray-tracing fallback that exists *for* hardware without RT, is present only in the `aaa` profile. So `standard-3d` and `mobile-3d` have no software RT, and SDF tracing sits in global-illumination with RT infra as contributor. The fallback path is absent exactly where it is needed. The same applies to path-tracing, which is QA.RENDER.reference's ground-truth oracle: it is aaa-only, so the validation oracle is missing from every non-aaa 3D configuration. Hardware RT itself (RND.RT.as and others, all marked E) is profile-gated to aaa despite shipping in mainstream PC and console titles.
- Evidence: Lumen's software path (mesh SDF plus global SDF) is the default on non-RT hardware. HW RT is baseline on PS5, Xbox Series and all current desktop GPUs. Reference path tracers are used for validation regardless of the shipping feature set (UE Path Tracer, Frostbite and Activision reference renderers).
- Proposed change: Move RND.RT.software to global-illumination, which is profile mobile3d,std3d and already owns RND.GI.sdf. Change the ray-tracing-infrastructure profile to `std3d` (consumers already use `C-RT?`). Split path-tracing so that RND.PT.reference is owned by render-validation, or tag it `std3d` with RND.PT.realtime kept aaa-gated.

### K-ARCH-15 · major · omission
- Target: capability map (no owner exists); candidates audio-dsp-mixing, render-2d-vector, cinematics-sequencer
- Finding: The capability map has no video playback capability: hardware and software video decode (AV1/H.264/HEVC, Bink class), A/V sync with the audio clock, video as textures for UI, world or cutscenes, and platform DRM surfaces. Every configuration from indie-2d to AAA ships intro movies, prerendered cutscenes or in-world screens. Video playback spans the IO, GPU upload, audio clock and frame pacing boundaries, so leaving it unowned invites four agents to build fragments of it.
- Evidence: Bink 2 and platform media APIs are integrated in most shipped engines, for example UE Media Framework/Electra and Unity VideoPlayer. Console TRCs include requirements on skippable, stable-rate movie playback.
- Proposed change: Add an area `RND.MEDIA` with capabilities `RND.MEDIA.decode` (HW/SW decode backends, M/E), `RND.MEDIA.sync` (A/V sync against the audio clock) and `RND.MEDIA.surfaces` (video textures for UI, world and cinematics). Assign the owner as a new small expert `media-playback` under render-architect, or under gpu-platform-architect if K-ARCH-7 is adopted. It consumes C-IO, C-GPUMEM, C-AUDIO and C-FRAME, and its profile is `client`.

### K-ARCH-16 · major · other
- Target: program-orchestration (ARCH.ORG.*), C-FRAME phase list, RND.ARCH.feature-contract, C-CFG cvar registry, CORE.LIFE.modules, C-RSCENE
- Finding: The ownership ledger is territory-based. The highest-contention artefacts are *shared registration points* that every agent must edit: the frame phase list (every runtime skill adds phases), the render feature registry, module and service registration, cvar namespaces, reflection codegen inputs and shader interop headers. No capability states that these must be declarative, per-skill extension points rather than central tables. If they are not, every contract change request to C-FRAME or C-RSCENE blocks dozens of agents, and merge conflicts land on the orchestrator.
- Evidence: Large engine codebases (UE modules and subsystems, Bevy plugins and schedules) avoid central edit points by letting each module self-register into phases and sets with ordering constraints. That is what allows parallel teams to work without lock-step edits.
- Proposed change: Add a capability `ARCH.STRUCT.registration` ("declarative self-registration for phases, render features, services, cvars and codegen inputs; no central tables") owned by engine-architect, with contributors frame-orchestration and render-architect. Add a fitness function (ARCH.GOV.fitness) that rejects edits to another skill's registration file. Extend C-FRAME's summary with "phase registration with ordering constraints (before/after/in-set)".

### K-ARCH-17 · minor · wrong-boundary
- Target: ml-inference-runtime (parent engine-architect, profile aaa), ML.RT.scheduling, C-ML
- Finding: The shared inference runtime is an orphan expert with no lead. It is restricted to `aaa` even though its consumers (texture-streaming-vt, reconstruction-upscaling, deformation-skinning) are in mobile3d and std3d. Engine-owned inference on mobile NPUs and consoles, such as neural upscaling or ML deformers, is therefore unavailable outside aaa. Its GPU scheduling depends on C-RG, so GPU time arbitration belongs with the GPU scheduler, not with engine-architect.
- Proposed change: Parent ml-inference-runtime under gpu-platform-architect (see K-ARCH-7) or render-architect. Change its profiles to `mobile3d,std3d,server`. Make C-RG optional in its consumes list (see K-ARCH-1(c)).

### K-ARCH-18 · minor · overlap
- Target: CORE.OBJ.events (entity-object-model) vs GAM.SYS.messages (gameplay-systems-toolkit); UI.FW.architecture "immediate for dev UI" (ui-architect) vs ED.UI.imgui (editor-ui-framework)
- Finding: There are two hidden overlaps. (a) "Events, messaging & inter-system communication" and "tag-scoped gameplay message routing" are both message buses, and neither states that one is built on the other. (b) ui-architect's architecture capability claims the immediate-mode developer UI decision, while editor-ui-framework owns the immediate-mode developer UI itself.

### K-ARCH-19 · minor · wrong-owner

### K-ARCH-20 · minor · other
- Target: non_responsibilities of cpu-performance ("Owning subsystem code → engine-architect"), gameplay-architect ("Game-specific code → engine-architect"), hot-reload-iteration ("Each system's own reload implementation → resource-streaming-architect"), ml-inference-runtime ("Neural feature design (texture, material, animation) → texture-streaming-vt"), render-architect ("Individual features → global-illumination"), graph-editor-framework ("Each domain's graph semantics → material-system")
- Finding: The schema allows a single redirect target per non-responsibility. As a result, several entries route agents to the wrong owner. Subsystem code is not engine-architect's, shader reload is not resource-streaming's, and animation ML features are not texture-streaming's. Others route to an out-of-engine party (the game team) through engine-architect. Agents use these entries to decide where to send work, so the misrouting becomes wrong change requests.
- Proposed change: Allow `[text, [owners...]]` or a sentinel target such as `"owning-skill"` or `"out-of-scope"`, and fix the six entries listed. Add a `check.py` rule that the redirect target owns at least one capability whose name matches the text's domain, or is a declared sentinel.
