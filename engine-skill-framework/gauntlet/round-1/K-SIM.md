# K-SIM · Physics & Simulation Critic · Round 1

### K-SIM-1 · blocker · scale-down
- Target: configurations `dedicated-server`, `aaa-open-world-online`, `open-world`; skills terrain, water-ocean, vegetation-foliage, destruction-fracture, fluid-simulation, crowd-simulation, procedural-generation, physics-2d, collision-detection, rigid-body-dynamics, character-vehicle-physics; `model.in_configuration`
- Finding: No server configuration can be built for the flagship open-world or AAA games. The only server configuration is a generic `[server, online]`, which contains no terrain collision source, water queries, PCG stream-in, crowd or destruction. If the add-ons are appended (`[server, online, openworld]` or `[server, online, openworld, aaa]`), the closure check fails. I ran the checker's own logic: terrain → C-RSCENE/C-MATIF, water-ocean → C-RSCENE/C-RG, destruction-fracture → C-RSCENE and fluid-simulation → C-RG are required dependencies whose owners are client-only. The add-on tag also pulls path-tracing, character-rendering and ray-tracing-infrastructure into the server, because the `aaa` token matches regardless of `server`. In the other direction, a 2D server `[server, online, min2d]` closes but contains all three 3D physics experts (tagged `server` unconditionally) and platform-mobile-portable.
- Evidence: Authoritative servers for open-world online games must run the same collision world (heightfield, water volumes, runtime-generated PCG content, destructible state) as the client. Examples are UE5 dedicated servers with World Partition server streaming and The Finals' server-authoritative destruction. The capability map itself declares WLD.PART.server "Server-side world streaming". The profile model has one axis (client vs. server base) and cannot express "the server half of configuration X".
- Proposed change: (a) Add a derived configuration per online game: `aaa-open-world-online-server = [server, online, openworld, aaa]`, `indie-2d-online-server = [server, online, min2d]`, and require check.py to close each one. (b) Make the render dependencies of end-to-end environment skills optional (terrain `C-RSCENE?`, `C-MATIF?`; water-ocean `C-RSCENE?`, `C-RG?`; destruction-fracture `C-RSCENE?`; fluid-simulation `C-RG?`) so their simulation/collision halves close headless. (c) Add a `client-only` profile flag so that `aaa`/`openworld` tags on pure render skills (path-tracing, ray-tracing-infrastructure, character-rendering, vegetation-foliage render) do not match server configurations. (d) Replace the `server` tag on collision-detection, rigid-body-dynamics and character-vehicle-physics with a dimension token (e.g. `dim3d`, carried by mobile3d/std3d/server-3d), and tag physics-2d `dim2d`. That keeps the 3D engine out of a 2D server, which the principles doc explicitly requires ("The 2D configuration must not carry the 3D engine").

### K-SIM-2 · major · wrong-boundary
- Target: character-vehicle-physics, gameplay-systems-toolkit, animation-graphs, prediction-rollback; PHY.CTRL.character
- Finding: No skill owns character movement: movement modes (walk, fall, swim, fly, climb, mantle), step-up and slope rules, root-motion consumption and the networked move/resimulate loop. character-vehicle-physics lists "Movement gameplay logic → gameplay-systems-toolkit", and animation-graphs lists "Locomotion gameplay → gameplay-systems-toolkit". But gameplay-systems-toolkit owns only abilities, tags, camera, spawning, messages and photo mode. prediction-rollback owns "Client prediction & reconciliation" generically, not the movement model that is predicted. Two non-responsibilities point at territory nobody owns.
- Evidence: In UE, CharacterMovementComponent (and the newer Mover plugin) is a single subsystem, because the movement model, its saved-move and replay format, and its interaction with the physics controller are one hot loop. Glenn Fiedler's "Networked Physics" work and Overwatch's GDC 2017 netcode talk (Ford) both treat the movement simulation as the unit of prediction. When it is split across three skills with no owner, each agent assumes another agent builds it.
- Proposed change: Add capability `GAM.MOVE.modes` "Character movement model: modes, step/slope rules, root-motion consumption, resimulatable move API" owned by gameplay-systems-toolkit (or a new expert `character-movement` under gameplay-architect), with contributors character-vehicle-physics, prediction-rollback and animation-architect. Add a contract `C-MOVE` (layer 4) that prediction-rollback and animation-graphs consume. Fix the non-responsibilities to point at the new capability.

### K-SIM-3 · major · omission
- Target: PHY (all areas), ED.*, visual-debugging-tools, editor-architect
- Finding: Physics tooling is absent from the capability map. It has no entry for: collision authoring (auto-fit primitives, convex decomposition), a physics-asset/ragdoll-body editor, a constraint/joint editor, a physics visual debugger/recorder (contacts, islands, sleep state, solver iterations, frame scrubbing), simulate-in-editor and simulation-driven placement, or vehicle/controller tuning tools. The only physics tooling touchpoint is the generic ED.DEBUG.draw. PHY.DEST.authoring exists for destruction only. The brief requires production tooling "as thorough as runtime".
- Evidence: Every production physics stack ships these as first-class tools: the PhysX Visual Debugger, the Chaos Visual Debugger (UE 5.3+), the Jolt Physics recorder/viewer, the Havok Visual Debugger, UE's Physics Asset Editor, and V-HACD/CoACD convex decomposition (CoACD, SIGGRAPH 2022). Without an owner, the ragdoll body set that ANM.IK.physical consumes has no authoring path. Physics bugs then can only be reproduced through generic draw lines.
- Proposed change: Add area `PHY.TOOL` owned by physics-architect, or by a new expert `physics-tools` under physics-architect with profile `client` that consumes C-EDCMD, C-PHYS and C-INSTR. Its capabilities would be: `PHY.TOOL.collision-authoring` (primitives, convex decomposition; contributor collision-detection), `PHY.TOOL.physics-asset` (ragdoll bodies/constraints per skeleton; contributor ik-procedural-animation), `PHY.TOOL.constraint-editor`, `PHY.TOOL.visual-debugger` (record/replay of physics state; contributors visual-debugging-tools, determinism-replay), `PHY.TOOL.simulate-in-editor` (contributor editor-architect) and `PHY.TOOL.tuning` (vehicle/controller tuning).

### K-SIM-4 · major · missing-contract
- Target: WLD.PART.sim-lod, C-WORLD; physics-architect, animation-architect, crowd-simulation, ai-behavior-perception, vfx-particles, audio-architect; PHY.ARCH.lod, ANM.ARCH.lod, GAM.AI.lod, RND.VFX.budgets
- Finding: Simulation LOD has an owner (world-architect) and a signal carrier (C-WORLD summary: "simulation LOD signals"), but none of the simulation subsystems that must act on it consume C-WORLD: physics-architect, animation-architect, crowd-simulation, ai-behavior-perception, vfx-particles and audio-architect. Each has its own LOD capability (PHY.ARCH.lod, ANM.ARCH.lod, GAM.AI.lod, RND.VFX.budgets "significance"), so the framework will get five significance systems. Separately, no capability covers amortized/time-sliced ticking (per-entity update-rate buckets, tick budgets) or tiered simulation outside the player's bubble (full → reduced → abstract/statistical → dormant, with promotion and demotion). Both are part of the mandate.
- Evidence: Production examples are UE's SignificanceManager plus per-component tick intervals and Mass LOD (full/simple/off-LOD processors), the tiered ambient simulation in Spider-Man, GTA V and Cyberpunk 2077, and the RDR2 GDC talks on off-screen ecosystem simulation. Significance must be computed once from views and players (and from all players on a server), then consumed by each domain's LOD policy.
- Proposed change: Split the significance/tier signal into its own contract `C-SIGNIF` (layer 2 or 3, owner world-architect). It carries per-entity significance, sim tier and update budget. physics-architect, animation-architect, crowd-simulation, ai-behavior-perception, vfx-particles and audio-architect consume it (optional where the profile lacks world streaming). Add `CORE.FRAME.amortized` "Time-sliced / rate-bucketed ticking & per-phase tick budgets" owned by frame-orchestration. Add `WLD.PART.sim-tiers` "Off-bubble simulation tiers (abstract/statistical sim, promotion/demotion, server-side remote regions)" owned by world-architect, with contributors crowd-simulation and dedicated-server. Each domain LOD capability's name should say it implements the C-SIGNIF policy.

### K-SIM-5 · major · omission
- Target: crowd-simulation (profile `openworld`), GAM.AI.mass, seed-map "large-scale simulation", configurations
- Finding: The brief lists large-scale simulation as its own target class, but it has no profile. Mass agents, flow fields and ORCA avoidance are reachable only through `openworld`. An RTS, colony sim or city builder, whether 2D (`min2d`) or 3D (`std3d`), and any dedicated server cannot get crowd-simulation without also taking terrain, water, PCG and vegetation. Three pieces are also missing: vehicle traffic simulation (lane graphs, intersections, traffic LOD from physics vehicle to kinematic spline to abstract flow), crowd-scale animation and rendering (animation sharing/instancing, vertex-animation textures, impostor agents), and deterministic lockstep at large entity counts as a configuration.
- Evidence: Examples are Factorio, They Are Billions, Cities: Skylines II (Unity DOTS), UE5 Mass with the City Sample traffic and crowd, and Total War. All of them are large-scale simulations without an open-world streaming requirement. City Sample shows that traffic and crowd rendering are separate from AI decision-making.
- Proposed change: Add profile add-on `massim` ("Large-scale agent simulation"). Tag crowd-simulation `[openworld, massim]` and include it in server configurations of either. Add configuration `rts-sim = [std3d, massim]` and ensure `[min2d, massim]` closes (crowd-simulation must not require 3D-only contracts). Add `GAM.AI.traffic` "Traffic simulation & lane graphs with LOD" owned by crowd-simulation, contributor character-vehicle-physics. Add `ANM.ARCH.crowd` "Crowd-scale animation (animation sharing, instancing, VAT, impostor agents)" owned by animation-architect, with contributors deformation-skinning and gpu-driven-pipeline.

### K-SIM-6 · major · missing-contract
- Target: C-PHYS, NET.PRED.physics, NET.PRED.lagcomp, rigid-body-dynamics, character-vehicle-physics, prediction-rollback
- Finding: Networked physics is owned by prediction-rollback, but the physics-side capabilities that make it possible are not owned anywhere and are not in C-PHYS. These are world/body state snapshot and restore, partial rewind and resimulation of a subset of bodies, deterministic re-step, per-body state hashing and historical collider poses for lag compensation. The C-PHYS summary ("Bodies, shapes, queries, contact events, stepping phases") has no rewind surface. rigid-body-dynamics and character-vehicle-physics do not consume C-NET or declare resimulation obligations. If a middleware is integrated (PHY.ARCH.build-integrate), this is the property most likely to be missing: PhysX has no built-in state restore, while Jolt provides SaveState/RestoreState.
- Evidence: Rocket League (GDC 2018, Cone), "Overwatch Gameplay Architecture and Netcode" (GDC 2017) and Photon Quantum all require snapshot and resimulate from the physics layer. Lag compensation needs a history buffer of hitbox poses, which is a physics/animation data product.
- Proposed change: Add `PHY.ARCH.rewind` "State snapshot/restore, partial resimulation, state hashing & collider history" owned by physics-architect, with contributors rigid-body-dynamics, prediction-rollback and determinism-replay. Extend the C-PHYS summary with "snapshot/restore, resimulate, state-hash hooks, collider history". Make PHY.ARCH.build-integrate's evaluation criteria explicitly include rewind support and determinism level.

### K-SIM-7 · major · missing-contract
- Target: ANM.ARCH.sync, PHY.ARCH.stepping, CORE.FRAME.phases/fixed-step, C-FRAME, C-ANIM, rigid-body-dynamics; docs/00 §3 and docs/02 "Runtime coupling cycles"
- Finding: The order of simulation phases has three partial owners and no single one. The order is: input → pre-physics gameplay → animation pre-physics pose/kinematic targets → physics step(s)/substeps → post-physics animation (ragdoll blend, foot IK) → post-physics gameplay → net snapshot → render extract. animation-architect owns "Animation / physics / gameplay sync", physics-architect owns stepping and frame-orchestration owns generic phases. The principles doc says animation↔physics data flows through phases declared in C-FRAME. However, rigid-body-dynamics (owner of PHY.DYN.kinematic "Kinematic & animated bodies") does not consume C-ANIM, and animation-architect consumes C-PHYS only optionally. The runtime cycle is therefore not recorded, and docs/02 lists only the accessibility/input/UI cycle. Asynchronous or decoupled physics is also not a capability: physics runs on its own fixed rate, concurrent with the game frame, with input marshalling and result interpolation.
- Evidence: UE Chaos async physics (physics thread at fixed rate with marshalled inputs/outputs), Rocket League's 120 Hz fixed physics, and Unity DOTS' FixedStepSimulationSystemGroup all define this order as one engine-wide schedule. When animation owns the order, the physics and network agents cannot change it without violating the ownership rule.
- Proposed change: Add `CORE.FRAME.sim-schedule` "Canonical simulation phase order (pre/post-physics, substeps, net snapshot, render extract)" owned by frame-orchestration, with contributors physics-architect, animation-architect and network-architect. Rename ANM.ARCH.sync to "Animation-side sync obligations within the canonical schedule; root-motion policy". Add `PHY.ARCH.async` "Decoupled/async physics stepping with input marshalling and interpolation" owned by physics-architect. Make rigid-body-dynamics consume C-ANIM, and list animation↔physics in the runtime-coupling-cycles section.

### K-SIM-8 · major · omission
- Target: PHY.ARCH.world, C-PHYS (requires only C-SPATIAL, C-ECS), physics-architect consumes; WLD.PART.lwc-policy, WLD.SPACE.lwc
- Finding: The physics world has no streaming or large-world capability. It does not cover per-cell collision data stream-in/out, bulk body insertion and broadphase rebuild without hitches, collision presence ahead of render (bodies must exist before a player or server entity arrives), or physics precision under large-world coordinates (double-precision positions, local simulation origins or origin rebasing). physics-architect consumes neither C-WORLD nor C-RES, so no contract path exists from world partition cells to the physics world.
- Evidence: Jolt added `JPH_DOUBLE_PRECISION` for this reason. PhysX offers `shiftOrigin`, and UE5 Chaos adopted LWC doubles. Broadphase insertion of thousands of streamed bodies is a known hitch source: PhysX broadphase add/remove cost and UE's async physics state creation (UE5 "async physics state creation" and the World Partition hitch work). Open-world server streaming (WLD.PART.server) also needs this.
- Proposed change: Add `PHY.ARCH.streaming` "Physics world streaming: per-cell collision activation, bulk/async body insertion, collision-before-render guarantee" and `PHY.ARCH.lwc` "Physics precision under large-world coordinates (double or local-origin simulation)", both owned by physics-architect with contributors collision-detection, world-architect and spatial-transforms. Add `C-WORLD?` and `C-RES` to physics-architect consumes. Add `PRF.LOAD.hitches` contributor physics-architect.

### K-SIM-9 · major · missing-contract
- Target: water-ocean (provides nothing, profile `openworld`), WLD.ENV.buoyancy vs PHY.CTRL.buoyancy, PHY.FLUID.shallow, fluid-simulation
- Finding: (a) water-ocean provides no contract. Water height, velocity, flow and depth queries are needed by physics (buoyancy), gameplay (swimming), AI/navigation, audio, VFX and fluids, but consumers have no contract to use. The dependency runs the wrong way: water-ocean consumes C-PHYS, while the buoyancy force owner (character-vehicle-physics) consumes nothing from water. (b) Buoyancy has two owners with overlapping names: WLD.ENV.buoyancy "Water queries & buoyancy data" (water-ocean) and PHY.CTRL.buoyancy "Buoyancy" (character-vehicle-physics). Buoyancy also applies to debris and ragdolls, not only characters and vehicles. (c) Shallow-water simulation is owned by fluid-simulation (aaa), but water-ocean lists "shallow-water models" as core expertise and owns rivers, which creates a boundary dispute over interactive water surfaces. (d) Water is openworld-only, so a standard-3d game with a lake or boats has a buoyancy owner in configuration but no water.
- Evidence: UE Water exposes a water-query API (`GetWaterSurfaceInfo`-class) consumed by buoyancy, swimming, audio and Niagara. Sea of Thieves and AC Black Flag used a single water query service with many consumers.
- Proposed change: Add contract `C-WATER` (layer 3, owner water-ocean) "Water surface/volume queries: height, normal, velocity, depth, water body id". Consumers: character-vehicle-physics, rigid-body-dynamics, gameplay-systems-toolkit, navigation-pathfinding?, audio-content-runtime?, vfx-particles?, fluid-simulation?. Rename WLD.ENV.buoyancy to "Water query service" and move generic buoyancy force (`PHY.CTRL.buoyancy`) to physics-architect or rigid-body-dynamics as `PHY.DYN.buoyancy`. Make water-ocean own local interactive surface simulation, and make PHY.FLUID.shallow fluid-simulation's only for large-scale coupled flow, stated in both non-responsibility lists. Tag water-ocean `[mobile3d, std3d]` with rivers and ocean as optional features, not `openworld` only.

### K-SIM-10 · major · wrong-boundary
- Target: character-vehicle-physics (PHY.CTRL.character, PHY.CTRL.vehicles, PHY.CTRL.platforms)
- Finding: This merge breaks the framework's own split rule. The principles doc's example of distinct literatures is "a tire model and a solver". Here, tire, suspension and drivetrain modelling is merged with character controllers, which are tightly coupled to movement, prediction and animation instead. The result is also a scale-down failure: vehicle dynamics is pulled into every mobile3d, std3d and server configuration, and a single agent must know both Pacejka/brush tire models and kinematic capsule sweeps.
- Evidence: Vehicle physics is routinely separate middleware or a separate module (UE ChaosVehicles plugin, PhysX Vehicles SDK 2 as its own SDK, Jolt VehicleConstraint as an optional part). Character controllers (PhysX CCT, Jolt CharacterVirtual) are core. The two change at different rates and are validated differently (tire force curves against reference data versus movement feel and netcode resimulation).
- Proposed change: Split into `character-physics` (PHY.CTRL.character, PHY.CTRL.platforms; profiles mobile3d/std3d/server) and `vehicle-physics` (PHY.CTRL.vehicles plus new `PHY.CTRL.vehicle-net` "vehicle prediction/replication specifics"; new add-on or optional tag, e.g. `vehicles`, or at least marked optional in ARCH.STRUCT.replaceability).

### K-SIM-11 · major · wrong-boundary
- Target: PHY.ARCH.build-integrate; collision-detection, rigid-body-dynamics, cloth-deformables, physics-2d
- Finding: The expert split (collision vs. rigid body vs. character vs. cloth) assumes the physics engine is built in-house, yet build-vs-integrate is left open as an E capability. Integrated middleware (Jolt, PhysX, Havok, Box2D v3) ships collision, solver, character and often cloth as one library. If "integrate" is chosen, four agents share one vendor or fork tree with no rule for who changes it, and the collision/solver skills have nothing to own. The evidence path for the decision is not specified: no benchmark scenes, determinism/rewind criteria, license/source access, or 2D/3D consistency.
- Evidence: Horizon Forbidden West and Death Stranding (Decima) use Jolt, many studios integrate Havok, and Unity DOTS offers Unity Physics or Havok behind one API. In all of these, the engine-side team owns an integration layer plus a small set of upstream patches, not the collision or solver internals.
- Proposed change: Add `PHY.ARCH.middleware-layer` "Middleware/fork integration layer & upstream patch ownership" owned by physics-architect. Add to each 3D physics expert's card a mode clause: under "integrate" the expert owns engine-side extensions, tuning and validation of its area, and all edits to vendor code go through physics-architect. Attach an evidence template to PHY.ARCH.build-integrate: the benchmark scene set (stacking, ragdoll pile, 10k bodies, streaming insert), determinism level achievable, rewind support, GPU path, source availability and license. Link it to ARCH.EVID.spike.

### K-SIM-12 · major · omission
- Target: C-PHYS contact events; PHY.ARCH.materials; audio-content-runtime, vfx-particles, input-devices-haptics, gameplay-systems-toolkit
- Finding: Physics-driven effects have no owner or contract. Nothing covers turning contacts into impact, slide and roll events (thresholds, per-frame event budgets, deduplication, significance culling), mapping surface type × impact class to sound, VFX, decals and haptics, or scrape/roll loops driven by relative velocity. audio-content-runtime does not consume C-PHYS, and no skill owns the surface-effect mapping table.
- Evidence: UE Physical Materials with surface-type → sound/Niagara tables in gameplay, Frostbite/Battlefield "material grid" impact systems, and Wwise/Audiokinetic physics-impact integrations all use contact-event filtering as an explicit, budgeted system. Unbudgeted contact callbacks are a well-known CPU and voice-count spike source (debris piles).
- Proposed change: Add `PHY.ARCH.events` "Contact/impact/slide event generation, filtering & budgets" owned by physics-architect. Add `GAM.SYS.impacts` "Surface-type impact effects routing (audio, VFX, decals, haptics)" owned by gameplay-systems-toolkit, with contributors audio-content-runtime and vfx-particles. Add C-PHYS as an optional consumption for audio-content-runtime, or route it through gameplay-systems-toolkit consuming C-PHYS and C-AUDIO.

### K-SIM-13 · major · wrong-owner
- Target: WLD.ENV.wind (vegetation-foliage, profile `openworld`)
- Finding: The global wind field is owned by vegetation-foliage and exists only in open-world configurations. Cloth (std3d), VFX (client), fluids (aaa), audio and weather all need wind. In standard-3d, cloth-deformables is present but no wind provider exists, and no contract exposes wind anyway.
- Evidence: UE's WindDirectionalSource is a world-level service consumed by foliage, cloth and Niagara. Frostbite and Decima drive vegetation, cloth, particles and weather from one wind simulation (Ghost of Tsushima's wind is a gameplay-wide system, GDC 2021).
- Proposed change: Move wind-field state and queries to atmosphere-weather (`WLD.ENV.wind-field`, profile mobile3d/std3d) and expose it through a small contract (`C-ENVFIELD` or an extension of C-WORLD) consumed optionally by cloth-deformables, vfx-particles, fluid-simulation, vegetation-foliage and audio. Keep "vegetation wind response & interaction" with vegetation-foliage.

### K-SIM-14 · major · omission
- Target: QA.* (no simulation validation), XC.DET.desync, test-architect subtree
- Finding: The test subtree has a dedicated render-validation expert, but simulation has no validation capability. It lacks cross-platform, cross-compiler determinism CI (the same replay produces identical state hashes on every target ISA/compiler), a physics stability regression suite (stacking, joint chains, mass ratios, tunnelling/CCD cases, ragdoll explosions) and simulation golden-trace comparison. XC.DET.desync is runtime detection only, and PHY.2D.determinism and PHY.ARCH.determinism define levels but not how they are proven.
- Evidence: Lockstep RTS titles (Age of Empires, StarCraft II) and rollback titles (GGPO/Quantum-based) run determinism farms across platforms. Box2D v3 and Jolt run determinism and benchmark suites in CI (Jolt's "determinism check" and PerformanceTest; Box2D's benchmark and cross-platform determinism tests). Without them, "determinism levels declared" is unverifiable.
- Proposed change: Add area `QA.SIM` owned by test-architect (or a new expert `simulation-validation`): `QA.SIM.determinism-matrix` (contributor determinism-replay), `QA.SIM.stability-suite` (contributors rigid-body-dynamics, physics-2d), `QA.SIM.golden-traces` and `QA.SIM.netsim` (prediction/rollback under link simulation; contributor prediction-rollback). Add physics benchmark scenes to PRF.BENCH.workloads' contributors.

### K-SIM-15 · minor · missing-contract
- Target: collision-detection, character-vehicle-physics, cloth-deformables consumes
- Finding: collision-detection and character-vehicle-physics do not consume C-DET. Broadphase pair ordering, contact-manifold ordering and collision cooking output directly determine solver results, and character controllers are resimulated for prediction. Only rigid-body-dynamics and physics-2d are bound to the determinism rules.
- Evidence: Jolt documents that determinism requires sorted broadphase pairs and constraints. Box2D v3 sorts contacts for determinism. Cooked mesh BVH layout must be byte-identical across cook machines for cross-platform lockstep.
- Proposed change: Add `C-DET` to collision-detection and character-vehicle-physics (or character-physics after K-SIM-10) consumes, and `C-DET?` to cloth-deformables.

### K-SIM-16 · minor · missing-contract
- Target: destruction-fracture (PHY.DEST.propagation, PHY.DEST.authoring; profile `aaa`)
- Finding: PHY.DEST.propagation promises "Destruction → navigation / render / audio updates", but the skill consumes neither C-NAV nor C-AUDIO, and fracture authoring does not consume C-EDCMD. The profile is also `aaa` only, although pre-fractured breakables are a staple of indie and standard 3D games.
- Evidence: Teardown is an indie game built around destruction, and The Finals is a mid-size team. Chaos Destruction in UE is available to every project tier.

### K-SIM-17 · minor · maturity-error
- Target: PHY.FLUID.particles (E), PHY.FLUID.gpu (E), PHY.COL.complex (E, includes SDF), PHY.ARCH.gpu (M)
- Finding: Real-time 3D particle fluids (SPH/PBF/FLIP) as gameplay-interacting systems are rare in shipped games, and GPU fluid solvers beyond VFX-grade grid smoke are not established production practice. Labelling both E while PHY.ARCH.gpu "GPU physics offload" is M is inconsistent. SDF-based rigid-body collision (PhysX 5 SDF mesh collision, 2022) is newer than mesh and heightfield collision but shares one E entry with them.

### K-SIM-18 · minor · scale-down
- Target: ik-procedural-animation (profile `std3d`), cloth-deformables (`std3d`), physics-2d, min2d "2.5D"
- Finding: mobile-3d has no ragdoll, foot IK or physical animation (ANM.IK.* is std3d-only) and no cloth or bone springs, although mobile 3D titles routinely ship all of these in reduced form (Genshin Impact, PUBG Mobile). The `min2d` profile claims 2.5D, but 2.5D games commonly use 3D physics constrained to a plane (DOF locking), which the 2D configuration cannot express: 3D physics is excluded and no planar-constraint capability exists.
- Evidence: Examples are Trine and Ori (3D physics on a plane), Unity's Rigidbody constraints and Jolt's allowed-DOFs. Mobile titles commonly use spring-bone secondary motion in place of full cloth.
- Proposed change: Tag ik-procedural-animation `[mobile3d, std3d]` and cloth-deformables `[mobile3d, std3d]` with tiered feature sets. Add `PHY.DYN.dof-lock` "Planar / DOF-locked simulation" owned by rigid-body-dynamics. Either drop "2.5D" from min2d or define a `min25d` configuration `[min2d, dim3d]` per K-SIM-1.

### K-SIM-19 · minor · omission
- Target: PHY.DYN, PHY.ARCH.gpu, physics-architect consumes
- Finding: Reduced-coordinate articulations (Featherstone), used for stable long chains, mechs, robotic rigs and high-mass-ratio ragdolls, have no entry. PHY.ARCH.gpu (GPU offload) is owned by a skill that consumes no GPU contract (C-RHI/C-RG), so the evaluation has no path to an implementation. fluid-simulation and cloth-deformables reach the GPU on their own.
- Evidence: PhysX articulations, MuJoCo, Havok ragdoll articulation modes and Jolt's skeleton-mapper plus ragdoll constraints show articulations are established. Every GPU physics path (PhysX GPU rigid bodies, UE Chaos GPU cloth research) needs render-graph scheduling for async compute.
- Proposed change: Add `PHY.DYN.articulations` "Reduced-coordinate articulations" owned by rigid-body-dynamics (E). Add `C-RG?` to physics-architect consumes, or state in PHY.ARCH.gpu that GPU simulation work is scheduled only through the owning expert's C-RG consumption.
