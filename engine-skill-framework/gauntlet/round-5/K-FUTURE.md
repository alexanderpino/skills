# K-FUTURE findings (round 5)

### K-FUTURE-1 · major · maturity-error
- Target: CORE.MATH.deterministic, PHY.DEST.procedural, NET.PRED.physics-rollback, ANM.SYN.learned, ANM.DEF.ml, GAM.AI.learned, ML.RT.sequence-exec, ML.RT.os-models, RND.SHADER.autodiff, XC.EXT.generated-assets, PLAT.PAL.cloud-render-host, ED.COLLAB.concurrent-world, ARCH.ORG.* program entry (radar)
- Finding: radar.json states "M requires at least two shipped titles with published postmortems; one shipped title or research evidence is X", and check.py does not enforce it. At least a dozen M entries carry evidence or revisit text that contradicts the rule: CORE.MATH.deterministic (evidence "cross-ISA reproducibility of floats is not established"; revisit "two shipped titles run mixed-platform lockstep"), PHY.DEST.procedural ("research-grade"), NET.PRED.physics-rollback ("Chaos prediction is beta"; no shipped title), ANM.SYN.learned (Holden 2020 only), ML.RT.os-models (revisit "shipped title using an OS model API" means zero today), RND.SHADER.autodiff (evidence is SM 6.9 preview), XC.EXT.generated-assets and GAM.AI.learned (one title), PLAT.PAL.cloud-render-host (revisit "two shipped first-party hosts"), ED.COLLAB.concurrent-world (evidence outside games), and the 150-agent coordination entry ("no published precedent"). ML.RT.sequence-exec is M while its sibling ML.RT.constrained-decoding is X, and its revisit ("two shipping consumers on min-spec") is unmet. The class decides opt-in: X/S sit behind the `experimental` profile, M rows land in default profiles, so over-labelled rows become silent defaults.
- Evidence: the framework's own evidence-to-class rule; 2025-26 state: OS model APIs and NPU paths have no shipped game consumers, cross-ISA float determinism is solved in production only by fixed-point or same-binary builds.
- Proposed change: reclassify the rows above to X and add the `experimental` profile tag (the fallback exists for each). Add a `shipped_titles` integer and `postmortems` list to radar entries, and have check.py fail an M entry with fewer than two. Where the framework wants to keep M for program-level items (agent coordination), add an explicit class-rule exception field with justification.

### K-FUTURE-2 · major · maturity-error
- Target: RND.RT.cluster-blas, RND.RT.omm, RND.RT.ser, radar "Advanced RT hardware features (OMM, SER, cluster BLAS)"
- Finding: one M entry covers three features of different cross-vendor status. Its revisit, "Availability on >=2 vendors", is already met for OMM and SER (DXR 1.2 / Agility SDK) and unmet for cluster acceleration structures (NVIDIA-only: VK_NV_cluster_acceleration_structure, RTX Mega Geometry). By the entry's own trigger cluster-blas is X. The fallback "Standard BLAS/TLAS" also hides that cluster BLAS is what makes virtualized geometry (Nanite-class) ray-traceable at scale; without it RT of clustered geometry needs proxy meshes (RND.LOD.* interplay).
- Evidence: DXR 1.2 spec (OMM, SER); RTX Mega Geometry SDK (2025), single-vendor.
- Proposed change: split the entry: OMM+SER stay M; cluster-blas becomes X (experimental tag) with fallback "fallback proxy-mesh BLAS per cluster LOD level (RND.RT.lod)" and a trigger of a vendor-neutral API in D3D12 or Vulkan KHR.

### K-FUTURE-3 · minor · omission
- Target: NET.TRANS.crypto, XC.SEC.crypto-policy, XC.SEC.pqc-signatures, radar "Post-quantum signatures"
- Finding: the post-quantum work covers only signatures. Harvest-now-decrypt-later applies to key exchange, which is the migration already deployed: TLS 1.3 hybrid X25519MLKEM768 is default in Chrome, Firefox, Cloudflare and OpenSSL 3.5. NET.TRANS.crypto/handshake and platform services (C-LIVE) have no hybrid-KEM or algorithm-agility requirement. ML-KEM adds about 1.2 KB per handshake message, which interacts with NET.TRANS.dos anti-amplification limits (QUIC 3x rule) and MTU-bounded custom UDP handshakes.
- Evidence: NIST FIPS 203; IETF draft-ietf-tls-ecdhe-mlkem; QUIC RFC 9000 anti-amplification.
- Proposed change: extend radar entry to "Post-quantum key exchange and signatures", add capability NET.TRANS.pq-kex (M, owner network-transport, contributor security-engineering) with requirement that handshake formats carry algorithm ids and fit the anti-amplification budget with hybrid KEM.

### K-FUTURE-4 · minor · scale-down
- Target: radar "GLES / WebGL backends" non-goal, PLAT.WEB.webgpu-target, configuration indie-2d-online-web-client
- Finding: min2d web games are hard-wired to WebGPU. Web 2D is the largest indie distribution channel (itch.io, portal iframes, playable ads), and WebGPU is gated by browser version, OS (Firefox Linux/Android, older iOS), embedded WebViews and iframe permission policy. The non-goal reversal trigger (>10% share lacking WebGPU) is measured, but reversal would need a whole new backend under C-RHI. Nothing reserves a narrow 2D sink that avoids C-RHI's binding-tier and render-graph obligations.
- Evidence: WebGPU shipped across major browsers by 2025-26 but with platform gaps; portal SDKs still ship WebGL2 builds.
- Proposed change: add a non-goal note that any reversal is scoped to a 2D-only presentation sink (batched sprite/tilemap/text draw list; RND.2D.*) behind C-RENDER2D, never a full C-RHI backend, and state that contract slot now so the trigger is actionable.

### K-FUTURE-5 · minor · other
- Target: radar entries for ANM.CINE.timecode, QA.FUNC.agent-exploration, RND.GI.restir/RND.PT.realtime, CORE.LIFE.interop/XC.SEC.memory-safety, work-graph entries
- Finding: radar quality defects that break revisit governance: ANM.CINE.timecode has evidence, revisit and fallback copy-pasted from RND.ARCH.cluster-sync ("A shipped title runs synchronised cluster output") which is not a timecode predicate; QA.FUNC.agent-exploration sits under the tech name "Agent/automation control API (MCP class)" with an unrelated trigger pair; the same technology appears as up to three entries (work graphs x3, memory-safe language x2, splats x2, WebGPU x2) with divergent fallbacks, and the ReSTIR family has one entry at class E (RND.GI.restir) and another at M (RND.PT.realtime) with identical evidence. A milestone-exit review can promote one copy and leave the other stale, and check.py's per-entry age check will not notice.
- Evidence: radar.json entries as listed; radar-transitions promotion checklist assumes one record per technology.
- Proposed change: one radar entry per technology with a capabilities list and per-capability fallback map; check.py fails duplicate `tech` names and revisit strings shared between entries with different `tech`. Fix timecode with its own predicate (e.g. "a shipped title slaves cinematic playback to an external LTC/PTP source").

### K-FUTURE-6 · minor · maturity-error
- Target: RND.TEX.feedback (M, std3d profile)
- Finding: sampler-feedback streaming is in the std3d default profile. Evidence is "D3D12 sampler feedback; SFS samples" only: D3D12-only (no Vulkan or Metal equivalent) and no cited shipped titles, so by the framework's own rule it is X. Its fallback (mip streaming) exists, so the cost is misclassification, not architecture; but std3d default lets an agent build the feedback path first. Note RND.RECON.framegen and RND.RECON.upscalers are E without any fallback text; that is right for classes but the ML-upscaler half (DLSS4/FSR4/PSSR are per-vendor binary integrations) needs the per-vendor integration cost recorded as M like RND.RECON.ml-denoise.
- Evidence: D3D12 SFS spec; Vulkan lacks an equivalent; Xbox-era Forza is the usual sole reference.
- Proposed change: RND.TEX.feedback to X or move profile to aaa; split RND.RECON.upscalers into E (temporal, engine-owned) and M (vendor ML integrations) with radar fallback "engine temporal upscaler".
