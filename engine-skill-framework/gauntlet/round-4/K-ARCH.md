# K-ARCH round 4 findings

### K-ARCH-1 · major · dependency-error
- Target: render-2d-vector, post-color-hdr, vfx-particles, material-system, texture-streaming-vt, C-VT, C-COLOR, C-TEMPORAL, C-SCENETEX, C-RSCENE
- Finding: In minimal-client / indie-2d-client, non-optional edges pull the whole 3D render stack into 2D and UI-only builds. render-2d-vector consumes C-VT and C-COLOR non-optionally; post-color-hdr consumes C-TEMPORAL and C-SCENETEX non-optionally; vfx-particles (profile 'all') consumes C-RSCENE, C-MATIF, C-SCENETEX non-optionally; material-system consumes C-VT non-optionally. So a card game requires virtual texturing, temporal history/jitter plumbing and the named per-view scene-texture registry, contradicting the 'batched draw lists by design' 2D stance.
- Evidence: model.deps() for minimal-client members (C-TEMPORAL <- post-color-hdr; C-VT <- material-system, render-2d-vector; C-SCENETEX <- reconstruction-upscaling, post-color-hdr, vfx-particles). Precedent: Unity URP 2D/Godot Compatibility renderers and Bevy 2D run without VT, TAA or a G-buffer registry.
- Proposed change: make C-VT optional in render-2d-vector and material-system (direct-texture fallback), make C-TEMPORAL and C-SCENETEX optional in post-color-hdr (tonemap-only path), split C-COLOR's 2D-needed subset (working space/output transform) from history-dependent parts, retag vfx-particles and reconstruction-upscaling to lite3d/std3d plus a min2d 2D-emitter path via C-DRAW2D. Add a check that minimal/min2d closures contain none of C-VT, C-TEMPORAL, C-SCENETEX, C-RSCENE.

### K-ARCH-2 · major · scale-down
- Target: skills.json profiles/targets, configurations minimal-client, online-3d-server, reference-games; docs/00 section 5
- Finding: The 'proven' scale-down only proves each configuration is closed, not minimal. Membership is 'skill profile contains all OR matches' and about 70% of skills are tagged 'all', so minimal-client (UI/card game, no physics) contains 74 skills against 98 for standard-3d-client. It includes anti-cheat-integrity (online only), cinematics-sequencer, vfx-particles, media-playback, animation-graphs/runtime, ai-behavior-perception, gameplay-systems-toolkit, reconstruction-upscaling, gpu-memory-resources, plus reference-games (a game, not engine runtime). online-3d-server includes cloth-deformables, motion-synthesis, vegetation-foliage, atmosphere-weather, water-ocean and localization-i18n although these are cosmetic or client-side on an authoritative server.
- Evidence: python model.members(); check.py only asserts closure. Small-engine precedent: Godot/Bevy minimal builds via feature flags with dependency-driven inclusion.
- Proposed change: give each configuration explicit feature roots and add a check that every member is reachable from roots plus universals (fail on unreachable). Retag anti-cheat-integrity to online add-ons; cinematics, vfx, media-playback, ai, animation-graphs to opt-in profiles; remove 'server' from targets of cloth, motion-synthesis, vegetation, atmosphere and water unless a headless capability is declared; mark reference-games kind process or a separate 'sample' kind excluded from builds.

### K-ARCH-3 · major · missing-contract
- Target: C-SNAPSHOT, C-REP, C-PREDICT, C-SAVE, C-SRVDATA, C-SIGNIF (tier hand-off), CORE.REFL.attributes, CORE.ECS.snapshot, PHY.ARCH.persistence
- Finding: Every stateful subsystem must independently declare its state to five or more registries (snapshot/rollback, replication, prediction, save, server persistence, tier-transition hand-off, replay). No capability owns a single state-classification schema (transient / derived / saved / replicated / predicted / persisted-server / editor-only) attached to reflected properties. GAM.FW.customization-descriptor and GAM.NARR.facts each re-declare 'save/replication participation'; PHY.ARCH.persistence, WLD.VOX.edits and GAM.SAVE.world-state each define their own persistence hand-off. Divergent declarations produce desyncs (state saved but not predicted, replicated but not snapshotted) that no single agent can detect.
- Evidence: contract summaries above; Unreal's UPROPERTY flags (SaveGame, Replicated) plus separate rollback registration (Network Prediction plugin) is a documented source of such drift; Overwatch ECS talk derives all of them from one component definition.
- Proposed change: add a capability CORE.REFL.state-classes (owner reflection-metadata, contributors ecs-runtime, replication, prediction-rollback, persistence-save, server-scaleout-persistence, determinism-replay) and a small contract C-STATECLASS (L2, requires C-REFL) that C-SNAPSHOT, C-REP, C-PREDICT, C-SAVE, C-SRVDATA derive from; add a fitness function that every declared component/property has a class.

### K-ARCH-4 · major · overlap
- Target: PHY.ARCH.validation, ANM.ARCH.validation, AUD.ARCH.validation, GAM.AI.validation, RES.MGMT.validation, UI.FW.validation vs QA.SIM.stability-suite, QA.SIM.animation, QA.SIM.audio, C-PHYS, C-ANIM, C-AUDIO, C-NAV, C-RES, C-UI oracle_author
- Finding: The same oracle suites are owned twice. PHY.ARCH.validation 'Physics oracle suite: analytic and reference scenes' (physics-architect, the C-PHYS owner) versus QA.SIM.stability-suite (simulation-validation, the declared oracle author of C-PHYS); ANM.ARCH.validation 'pose/compression/retarget error metrics' versus QA.SIM.animation 'Animation error metrics'; AUD.ARCH.validation 'loudness, glitch' versus QA.SIM.audio 'BS.1770 loudness, glitch detection'. GAM.AI.validation and RES.MGMT.validation put the suite in the implementer's hands while C-NAV/C-RES name another oracle author. Unlike RND.MAT.validation, RND.RHI.conformance and ML.RT.validation, these lack the 'hooks only; suite authorship belongs to the oracle_author' qualifier, so the implementer-vs-oracle-author independence rule is contradicted by capability ownership.
- Evidence: contracts.json oracle_author fields; ARCH.ORG.independence; QA.AGENT.oracle-independence.
- Proposed change: reword all *.validation capabilities to 'hooks, reference scenes as data and thresholds proposal; suite authorship belongs to the contract oracle_author' and move authorship caps to the QA owner (add QA.SIM.navigation, QA.SIM.streaming or assign C-NAV/C-RES to an independent oracle author). Add a check: a capability whose name contains oracle/validation and whose owner equals the owner of a contract with a different oracle_author must carry the 'hooks only' marker.

### K-ARCH-5 · major · wrong-owner
- Target: robustness-fuzzing, functional-automation-soak, simulation-validation, render-validation as oracle_author of 111 code contracts
- Finding: Four process skills author all conformance suites: functional-automation-soak 35 contracts, robustness-fuzzing 26, simulation-validation 26, render-validation 24. robustness-fuzzing (5 capabilities: fuzzing, sanitizers, faults, concurrency stress, distributed faults) is oracle author for C-MATH (IEEE-754/CORE-MATH vectors), C-SYNC (herd7 litmus, linearizability), C-TASK (model checking), C-MEM, C-ECS, C-CFG, C-CRASH (minidump corpora), C-ML (ONNX parity), C-PAL. functional-automation-soak authors suites for C-TEXT (shaping, bidi conformance), C-LOC (CLDR), C-BUILD, C-VCS, C-EDCMD, C-SAVE, C-SVC. This violates the framework's own rule that a skill has distinct expertise, and makes four agents a serial bottleneck for milestone freezes (a contract cannot freeze before its oracle author is built).
- Evidence: contracts.json counts; oracle_reference entries name disjoint literatures (litmus tests, CLDR, Perfetto, Wycheproof).
- Proposed change: add an expert 'foundation-conformance' (memory model, math reference, containers, allocator, config, ECS model tests) under test-architect and re-point C-MATH, C-SYNC, C-TASK, C-MEM, C-TYPES, C-ECS, C-ID, C-ERR, C-CFG, C-MOD to it; add 'ui-text-conformance' (text shaping, CLDR, layout, focus) for C-TEXT, C-LOC, C-UI, C-DIALOGUE; keep robustness-fuzzing for parsers and fault campaigns. Update independence matrix workstream separation accordingly.

### K-ARCH-6 · major · omission
- Target: ARCH.ORG.ownership-ledger, ARCH.ORG.agent-continuity, ARCH.ORG.write-sets, ARCH.ORG.provenance, BLD.CI.sealed-suites, ARCH.GOV.fitness, program-orchestration, C-ORCH
- Finding: The coordination machinery is software (lock/lease server with heartbeats and fencing tokens, per-path access-class enforcement including sealed:oracle, work-package queue, provenance store, fitness-function runner, check.py itself) but is owned by process skills (program-orchestration, architecture-governance), and docs/00 states a process skill cannot own code. No tool or runtime skill owns building, testing or operating it, although every agent's write access depends on it and it is labelled M (emerging).
- Evidence: ARCH.ORG.agent-continuity 'lock leases with heartbeats and fencing tokens'; C-ORCH summary 'ownership ledger with access classes ... sealed holdouts readable only by oracle_author'; principle 'a process skill cannot own code' (security-runtime rationale).
- Proposed change: add a tool-kind expert 'orchestration-infrastructure' (parent build-release-architect or program-orchestration) owning ledger and lease service, ACL enforcement in VCS/CI, work queue, provenance attestation store and fitness-function runner, with C-ORCH split into the process protocol (P) and a code contract; give it its own conformance oracle (fencing-token and stale-lock chaos tests) and put it in milestone M0 skills.

### K-ARCH-7 · major · dependency-error
- Target: milestones M1, M2, M3 contracts_frozen; configurations indie-2d-client, minimal-client, fighting-2d-rollback-client; C-RG, C-SHADER, C-MATIF, C-RSCENE, C-DRAW2D, C-COLOR, C-PHYS, C-UI
- Finding: M2 claims indie-2d, minimal and fighting-2d configurations shipping on PC, console, mobile and web, but C-RG, C-SHADER, C-MATIF, C-RSCENE, C-SCENETEX, C-DRAW2D, C-COLOR, C-TEMPORAL, C-VT, C-PHYS (and C-UI, C-NAV, C-MOVE for M1/M2 games) are frozen only at M3. Games shipped at M2 thus sit on contracts that M3 may still change. check.py verifies freeze-before-consumer-built and freeze order, not that a claimed configuration's non-optional contract closure is frozen by the claiming milestone.
- Evidence: computed over milestones.json: M2 late-frozen non-optional contracts for indie-2d-client = C-COLOR, C-DRAW2D, C-MATIF, C-PHYS, C-RG, C-RSCENE, C-SCENETEX, C-SHADER, C-TEMPORAL, C-VT.
- Proposed change: add a check that every non-optional contract in a claimed configuration's closure is frozen at or before the claiming milestone; then either freeze the 2D-relevant subset of the render contracts (C-RG, C-SHADER, C-DRAW2D, C-COLOR-2D, C-PHYS with 2D modules) in M1/M2 with explicit 'extension tier' for 3D additions, or claim indie-2d shipping at M3.

### K-ARCH-8 · major · missing-contract
- Target: NET.PRED.lagcomp, PHY.ARCH.rewind, ANM.RT.pose-history, GAM.SYS.hit-detection, GAM.SYS.projectiles, anti-cheat-integrity, C-PREDICT, C-PHYS, C-ANIM
- Finding: Lag compensation and server rewind is split across four skills with no contract naming the composite: collider history (physics-architect), pose history (animation-runtime), protocol/rewind window (prediction-rollback), hit/hurtbox resolution and 'server-side rewind validation' (gameplay-systems-toolkit) plus validators (anti-cheat-integrity). The queryable object, 'the world's hit volumes as of tick T with hurtbox poses from animation at T', has no owner, so consistency of skinned hitboxes and colliders under rewind, memory cost per tick and fairness policy are unowned. Competitive shooters (Overwatch, Valorant, Source lag compensation) treat this as one subsystem.
- Evidence: capability texts above; C-PREDICT summary says only 'rewind queries'.
- Proposed change: add capability NET.PRED.rewound-world-query (owner prediction-rollback) and contract C-REWIND (L3, requires C-PHYS, C-ANIM?, C-SNAPSHOT) with collider-history and pose-history providers implemented by physics and animation-runtime and consumed by C-ABILITY hit resolution and C-INTEGRITY; oracle author simulation-validation.

### K-ARCH-9 · major · wrong-owner
- Target: PHY.ARCH.materials, C-ENV, GAM.SYS.impacts, WLD.ENV.terrain-materials, audio-content-runtime, vfx-particles, material-system
- Finding: The surface-type/physical-material taxonomy is owned by physics-architect ('Physics materials and surface types') but is the shared key for terrain layers (C-ENV returns 'surface type'), audio footsteps and impacts, VFX/decals, projectile penetration and haptics. Consumers (terrain, audio-content-runtime, vfx-particles, water-ocean) do not consume C-PHYS or consume it optionally, so the identifier space has an owner that they cannot legitimately depend on, and routing lives in a layer-4 skill (GAM.SYS.impacts).
- Evidence: skills.json consumes for terrain (C-PHYS?), audio-content-runtime (no C-PHYS); capability texts.
- Proposed change: move the taxonomy (IDs, hierarchy, per-surface parameters as assets) to gameplay-data or content-pipeline-architect as an L2/L3 asset type (e.g. capability GAM.DATA.surface-types with contract C-SURFACE in C-ASSET/C-GAMEDATA), keep PHY.ARCH.materials as the physics parameter binding, and have C-ENV, audio, VFX and material-system reference the shared IDs.

### K-ARCH-10 · minor · other
- Target: CORE.FRAME.sim-schedule, CORE.FRAME.phases, CORE.FRAME.access-model, C-FRAME, docs/00 section 6
- Finding: Contradictory wording inside one owner. CORE.FRAME.access-model and C-FRAME say ordering is 'derived' from declared access by a single scheduler; CORE.FRAME.sim-schedule says 'fixed sequence per tick; declared access used only for validation'. Section 6 of docs/00 asserts both. Agents implementing physics, animation and netcode will read different rules about whether adding a system can reorder simulation.
- Evidence: capability texts.
- Proposed change: reword sim-schedule as 'fixed relative order of the named simulation groups (determinism anchor); ordering inside groups derived from access; a violation of declared access versus the canonical order fails validation' and state it in C-FRAME.

### K-ARCH-11 · minor · wrong-boundary
- Target: visual-debugging-tools (parent editor-architect), C-DEVUI, C-AUTOMATION
- Finding: A runtime skill that ships in client, headless and server builds (debug draw, in-game console, C-AUTOMATION, C-DEVUI) is parented to the tool lead editor-architect. Under the arbitration rule, disputes inside a lead's subtree are settled by that lead, so a tool lead without runtime literature arbitrates server-shipping code, and its C-DEVUI/C-AUTOMATION consumers sit across three other subtrees.
- Evidence: skills.json parent/kind/targets; ARCH.ORG.escalation.
- Proposed change: reparent to core-runtime-architect (or observability-telemetry) keeping the editor host contribution via C-EDHOST, or record an explicit arbitration exception in ARCH.ORG.escalation.

### K-ARCH-12 · minor · other
- Target: engine-architect (29 direct children), ARCH.ORG.escalation, C-A11Y
- Finding: engine-architect has 29 direct children and is the sole arbiter for inter-lead disputes within a workstream, cross-workstream disputes and party-lead cases, while 16 workstreams have no designated coordinator; with ~150 agents this makes one agent the queue. Separately, C-A11Y (P contract) is the only contract never frozen by a milestone because check.py only requires freezes of code contracts.
- Evidence: skills.json parent counts; milestones.json contracts_frozen; check.py line 352.
- Proposed change: name a workstream coordinator (a lead of the workstream, excluded when a party) as first-instance arbiter for intra-workstream disputes and leave engine-architect for cross-workstream ones; freeze C-A11Y at M1 with the other process contracts (extend the never-frozen check to all non-P contracts plus named P ones).
