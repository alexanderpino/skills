# K-TEST round 4 findings

### K-TEST-1 · major · missing-contract
- Target: data/milestones.json (M0-M7 `skills`, `contracts_frozen`, `gates`); test-architect, robustness-fuzzing, simulation-validation, render-validation, functional-automation-soak, perf-benchmarking, certification-compliance, security-engineering, architecture-governance, program-orchestration
- Finding: No milestone lists any process skill in `skills` (M0 lists ci-cd-automation and test-runtime-harness only). M0 freezes C-MEM, C-SYNC, C-TASK, C-MATH, C-TYPES, C-ERR, C-MOD, C-CFG, C-CRASH, C-INSTR, C-TEST, whose oracle_author is robustness-fuzzing. M0 gates name validators owned by simulation-validation (QA.SIM.golden-traces), certification-compliance (QA.CERT.prechecks), security-engineering and test-architect. None of these skills arrives in any milestone. check.py proves closure over runtime skills only, so "freeze after owner and a consumer" never checks that the oracle author and gate validator exist by then.
- Evidence: contracts.json oracle_author field. milestones.json M0 skills and gates. The walking-skeleton proof is vacuous for the validation side.
- Proposed change: add `process_skills` (or allow process skills in `skills`) per milestone. Check that every contract frozen or drafted at Mk has its oracle_author, and every gate's capability owner and validator owner, present at or before Mk. Put test-architect, robustness-fuzzing, simulation-validation and render-validation at M0, functional-automation-soak at M1, certification-compliance at M1 or M2.

### K-TEST-2 · major · other
- Target: data/milestones.json gates; QA.AGENT.holdout, QA.AGENT.mutation-gate, QA.AGENT.gate-canaries, XC.SEC.agent-boundary, QA.STRAT.release-criteria, QA.FUNC.compat-corpus, QA.CERT.prechecks, PRF.BENCH.scale-content, PRF.METH.asymptotics
- Finding: Gate validators are not independent and often do not exercise the property they validate. Of 55-odd gates, about 28 have the capability owner and validator owner in the same workstream; security-engineering and privacy-data-protection sit in `quality` with the QA skills. Several pairs are circular. gate-canaries is validated by agent-redteam, and agent-boundary by gate-canaries. QA.FUNC.soak and PRF.MEM.footprint validate each other at M2. M5 and M6 swap PRF.BENCH.scale-content and PRF.METH.asymptotics. At M7, release-criteria is validated by compat-corpus, which is validated by prechecks. Some pairings are unrelated. The sealed holdout (QA.AGENT.holdout) is validated by QA.SIM.golden-traces, which cannot show that an implementer cannot read the holdout. The mutation gate (QA.AGENT.mutation-gate) is validated by fuzzing, not by seeded weak tests. Gates carry no pass criterion, so an independent critic cannot decide pass or fail.
- Evidence: the PROTOCOL rule "builder never grades its own fixes"; the framework's own claim "a guard never seen to fail is not a guard". Pass criteria for gates are prose in `exit` only.
- Proposed change: extend the gate schema to {capability, validator, kind (red-team|canary|measurement|conformance), criterion (metric, threshold, evidence-bundle item)}. Require validator owner workstream different from capability owner workstream, and no 2-cycles or triangles among gates. Re-pair holdout to a red-team read attempt (agent-redteam plus BLD.CI.sealed-suites) and mutation-gate to seeded weak-test injection. Move security-engineering and privacy-data-protection into `assurance`.

### K-TEST-3 · major · missing-contract
- Target: contracts.json oracle_reference on ~70 conformance contracts at layers 3-5 (C-PHYS, C-ANIM, C-AUDIO, C-NET, C-REP, C-PREDICT, C-NAV, C-UI, C-TEXT, C-LOC, C-SCRIPT, C-SAVE, C-SHADER, C-COLOR, C-VIDEO, C-RG, C-WORLD, C-BUILD, C-PKG, C-COOK, C-VCS, C-TARGETPLAT ...)
- Finding: `oracle_reference` (the external ground truth) is mandatory only for layers 0-2 (check.py line 367). About 70 of ~113 conformance contracts at layers 3-5 name none, exactly where the domain oracles the mandate asks for live (physics, animation, audio, netcode, text, video, colour). Without a named reference, the oracle author falls back to golden output produced by the implementation, which proves regression only, not correctness.
- Evidence: production practice: HarfBuzz and Unicode BidiCharacterTest and UAX#14 tests (C-TEXT); CLDR/ICU data (C-LOC); Lua, test262 and Wasm spec suites (C-SCRIPT); Argon/JVET conformance bitstreams (C-VIDEO); ITU-R BS.1770 loudness and scipy/DSP reference renders (C-AUDIO); Box2D/Jolt/Bullet analytic scenes and energy and momentum invariants (C-PHYS); Recast/Detour parity and brute-force path optimality (C-NAV); ACES/ICC/ST.2084 transfer vectors (C-COLOR); dEQP-class shader tests (C-SHADER); OpenXR CTS (C-XRVIEW); ozz/DCC ground-truth pose error bounds (C-ANIM).
- Proposed change: require `oracle_reference` on every contract with `conformance: true`, at all layers (a kind and locator, marked external vs derived). Fill the list above. Mark derived-from-implementation goldens as `regression-only` and disallow them as the sole reference for a layer 0-3 contract.

### K-TEST-4 · major · wrong-owner
- Target: contracts.json oracle_author assignments (robustness-fuzzing 26, functional-automation-soak 35, simulation-validation 26, render-validation 24); CORE.CONC.correctness; C-SYNC, C-TASK, C-MEM, C-MATH, C-ECS, C-TYPES, C-BUILD, C-PKG, C-VCS, C-COOK, C-TEXT, C-LOC, C-XRVIEW, C-VIDEO
- Finding: Oracle authorship is assigned by category rather than expertise. robustness-fuzzing (expertise: libFuzzer/AFL, sanitizers, fault injection, TSan) is oracle author for semantic L1/L2 contracts that need model checking, litmus and linearizability tests, MPFR-class numeric references and model-based container/ECS testing. Fuzzing is not a semantic oracle. The one capability that names model checking (CORE.CONC.correctness) is owned by the implementer concurrency-primitives, with robustness-fuzzing only as contributor, which inverts the independence rule. functional-automation-soak (bots, smoke, soak) authors conformance for the build system, packaging, VCS, cook, text shaping and localization, which are outside its stated expertise. render-validation is asked to author C-VIDEO (decode conformance) and C-XRVIEW.
- Evidence: C-SYNC's own oracle_reference already lists herd7, loom and linearizability checkers: a skill with those capabilities does not exist. Loom/Shuttle/CDSChecker, Jepsen/Knossos and MPFR differential testing are distinct disciplines from coverage-guided fuzzing. About 110 suites concentrated in 3-4 agents is also a throughput bottleneck.
- Proposed change: add a capability QA.ROBUST.model-based (model checking, linearizability, litmus, differential-vs-reference for allocators, containers, ECS, tasks), owned by robustness-fuzzing with the expertise list widened. Move CORE.CONC.correctness ownership to it (concurrency-primitives as contributor). Move C-MATH and C-SPATIAL oracle authorship to simulation-validation (numerical error metrics). Add QA.FUNC.pipeline (build, cook, package, patch and VCS end-to-end and hermetic-rebuild verification) to functional-automation-soak and add "build/cook/VCS conformance" to its expertise. Give C-TEXT and C-LOC a Unicode/ICU conformance capability in render-validation (text final-frame) or functional-automation-soak, declared. Reassign C-VIDEO to functional-automation-soak with a bitstream-conformance capability.

### K-TEST-5 · major · omission
- Target: QA.AGENT.holdout, BLD.CI.sealed-suites, QA.AGENT.oracle-independence, C-ORCH (sealed:oracle), QA.STRAT.selection-policy
- Finding: The sealed holdout has no anti-probing protocol. Results are returned as "pass/fail plus failure category" to the implementer, with no attempt budget per work package, no rotation or burn of a holdout case after it has failed or been queried, no limit on distinct submissions, and no rule for regenerating gate-time seeds. An autonomous implementer can hill-climb against the holdout through repeated submissions, since the feedback channel leaks bits every run. There is also no defined path by which an implementer legitimately learns why a holdout failed (a redacted minimal repro, or promotion of the case to the visible acceptance suite after retirement).
- Evidence: reward-hacking and test-overfitting reports in agentic coding (the framework's own radar cites them); the standard held-out-set discipline in ML evaluation (adaptive data analysis, Dwork et al. 2015; Kaggle private leaderboard reuse limits).
- Proposed change: add capability QA.AGENT.holdout-hygiene (test-architect, with program-orchestration and ci-cd-automation). It covers a per-package holdout query budget, retirement of a holdout case after any failure with replacement drawn from a seeded generator, a fixed failure-category taxonomy that carries no input detail, a redacted-repro channel, and a periodic canary that tries to overfit. Record queries in the provenance ledger and add it to the M0 gate set.

### K-TEST-6 · major · omission
- Target: contracts.json `boundary`/`test_double` (only C-PAL, C-MEM, C-IO, C-RHI, C-SVC, C-DEVICE, C-NETLINK, C-LIVE, C-SHARD, C-SRVDATA declare one); C-XRVIEW, C-VIDEO, C-ML, C-MLGPU, C-INTEGRITY, C-SIGN, C-VCS, C-TARGETPLAT, PLAT.CON.confidential-slots, C-PHYS (middleware mode B23)
- Finding: Several contracts sit on an external boundary but declare no verified double. An agent with no headset, no console devkit, no NDA, no HSM or no third-party anti-cheat SDK cannot verify its side. Missing doubles: an OpenXR runtime emulator, a media decoder double, a vendor ML runtime double, a key-service/HSM emulator, an anti-cheat SDK stub, a VCS server double, and public reference implementations of the confidential slots (so non-cleared agents run the same conformance suite against a null slot). QA.STRAT.contract-fakes only verifies doubles that exist.
- Evidence: Monado headless / OpenXR CTS simulated runtime; SoftHSM/KMS emulators; WARP/lavapipe already used for C-RHI. The framework accepts the pattern for other boundaries but applies it inconsistently.
- Proposed change: set `boundary: true` and a `test_double` (kind, owner) on the contracts listed, with each double passing the contract's conformance suite. Add PLAT.CON.public-slot-reference (platform-console, with platform-architect): a public conformance-passing null implementation for every confidential slot. Extend the check that boundary contracts declare doubles to a list of expected external boundaries.

### K-TEST-7 · major · omission
- Target: QA.RENDER.*, RND.SHADER.toolchain, RND.SHADER.permutations, C-SHADER (no oracle_reference), shader-system
- Finding: There is no capability that validates the shader toolchain itself: the front-end to backend translation path (HLSL/Slang to DXIL, SPIR-V, MSL, WGSL) and the compiler versions pinned per platform. Nothing covers cross-backend numeric equivalence of the same shader, compile-all-permutations validation, miscompile detection, and qualification of each compiler or driver-compiler update. render-validation only compares final images, which is late, tolerance-masked and backend-dependent, and it cannot localize a shader miscompile. RND.SHADER.pso-lists validates PSO coverage, not correctness.
- Evidence: Vulkan CTS/dEQP and WebGPU CTS shader tests, Slang's test suite and cross-compile tests, Naga/Tint differential fuzzing, and the routine production failure mode of DXC and driver-compiler regressions.
- Proposed change: add QA.RENDER.shader-conformance (render-validation, with shader-system and rhi-core): differential execution of compute-shader reference kernels across backends with numeric tolerances, all-permutation compile gates, compiler-fuzz lane, and compiler/driver version qualification. Set C-SHADER.oracle_reference accordingly.

### K-TEST-8 · minor · missing-contract
- Target: C-TESTHOST (oracle_author robustness-fuzzing, oracle_reference "host-conformance scenarios shipped with the runner"); C-DET (oracle_reference "cross-platform golden state-hash traces")
- Finding: C-TESTHOST is universal and all evidence flows through it, yet its only reference ships with the runner, so it is authored by its implementer. A runner that reports green wrongly defeats every gate downstream. The gate-canary known-red case also runs through the same runner. The C-DET golden traces are recorded from the implementation, so they show consistency across platforms, not correctness of the level declared.
- Evidence: differential testing against an independent minimal runner (gtest/Catch2-class) is the standard trust anchor.
- Proposed change: give C-TESTHOST an out-of-tree reference verifier: a tiny independent result and exit-code checker written by the oracle author, run over the canary suite in CI outside the runner. Mark C-DET traces `regression-only` and add an analytic determinism reference (a scenario with a known closed-form or fixed-point outcome).

### K-TEST-9 · minor · omission
- Target: QA.ROBUST.fuzzing, QA.FUNC.bug-capture, XC.DET (no failure-minimisation capability)
- Finding: No capability owns test-case reduction: shrinking a fuzz crash, a diverging million-step replay, or a failing frame capture to a minimal repro. Autonomous agents receive failure evidence as bounded context, and BLD.CI.bisection localizes changes but not inputs.
- Evidence: C-Reduce/afl-tmin, Hypothesis/QuickCheck shrinking, delta debugging (Zeller); deterministic simulation testing systems ship trace shrinking.
- Proposed change: add QA.ROBUST.minimization (robustness-fuzzing, with determinism-replay and render-validation) covering input, replay-trace and scene reduction, required for every failure handed to an implementer.

### K-TEST-10 · minor · omission
- Target: QA.SIM.netsim, NET.TRANS.simulation, QA.FUNC.network
- Finding: Netcode acceptance runs against a synthetic link conditioner (latency, loss, jitter parameters). Nothing validates the conditioner's realism against measured WAN, Wi-Fi and cellular traces (bursty loss, reordering, handover), so the rollback and prediction thresholds in M2 ("8 frames under 150 ms / 5% loss") may be met only under unrealistically smooth conditions.
- Evidence: trace-driven emulation (Mahimahi, Pantheon) and published mobile/Wi-Fi loss burstiness.
- Proposed change: add to QA.SIM.netsim a governed corpus of captured network traces replayed by NET.TRANS.simulation, and require netcode gates to pass on it as well as on parametric profiles.
