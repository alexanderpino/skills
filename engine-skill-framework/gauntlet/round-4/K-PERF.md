# K-PERF findings (Performance Critic, round 4)

### K-PERF-1 · major · wrong-owner
- Target: PRF.CPU.compiler, BLD.SYS.toolchains, BLD.SYS.configs, XC.DET.float, XC.DET.conformance, cpu-performance
- Finding: PRF.CPU.compiler says "optimization flag policy (sole owner)" and is owned by cpu-performance, a process skill that owns no code or build files. BLD.SYS.toolchains/configs own the compiler matrix and build configurations, and XC.DET.float owns "flags, FMA, transcendentals". Three skills each claim compiler flags. PGO, LTO, -ffast-math, FMA contraction and cross-module inlining change floating-point results, so a performance flag policy can silently break cross-platform determinism for lockstep, rollback and replay. The XC.DET.conformance matrix (toolchain x ISA x platform x cores x schedule) does not include the optimization level or PGO/LTO profile, so the gate can pass on a debug/dev flag set and fail on the shipped one.
- Evidence: PGO/LTO/fast-math are known sources of FP result drift between builds (GCC/Clang -ffp-contract, MSVC /fp:fast, LTO vectorization changing reduction order). Lockstep RTS and rollback fighting games (GGPO-class, Factorio, SC2) pin flags per module for this reason.
- Proposed change: reword PRF.CPU.compiler to "PGO/LTO profile data and recommendations" and make BLD.SYS.configs the sole owner of flag mechanism. Add per-module flag classes ("det-strict" and "perf") declared by module. Set the owner of the det-strict class to determinism-replay (XC.DET.float). Add optimization level, PGO and LTO to the XC.DET.conformance matrix, run on the profile and shipping configurations. Add a non-responsibility to cpu-performance: "flag mechanism -> build-system-toolchains; FP flags of det-strict modules -> determinism-replay".

### K-PERF-2 · major · missing-contract
- Target: CORE.SCALE.actuators, C-SCALE, C-GOVERN, XC.DET.float, NET.SESS.overload, WLD.PART.sim-lod, C-SIGNIF
- Finding: Registered actuators include significance, animation rate, worker count and time dilation, and the governor changes them from local, non-deterministic signals (GPU time, thermal, present feedback). Nothing declares which actuators may alter simulation-visible state. In server-authoritative, lockstep and rollback configurations, and under replay, a client-local governor that changes significance tier, physics or AI rate, or worker count (which changes reduction order) desyncs or invalidates recordings. The actuator registry has no "sim-affecting" versus "presentation-only" class, and no rule that sim-affecting actuators are driven only by server-decided or tick-stamped inputs recorded as external inputs for C-REPLAY.
- Evidence: Lockstep and rollback engines restrict adaptive quality to presentation (dynamic resolution, VFX, audio LOD) because sim inputs must be identical on all peers. Server-side LOD changes are legitimate only when replicated as authoritative state. In UE, world-partition streaming and net-relevancy scalability are server-decided for the same reason.
- Proposed change: add an actuator class attribute to C-SCALE ("presentation" | "sim-local-nonobservable" | "sim-authoritative") with the rules that (a) under online-lockstep, online-rollback and replay recording only "presentation" actuators are client-drivable, (b) sim-authoritative actuators are commanded through C-SNAPSHOT/tick-stamped events and recorded as external inputs, (c) worker-count changes must not change deterministic results, proven by XC.DET.conformance across core counts. Add an owner capability CORE.SCALE.actuator-classes (runtime-scalability, contributors determinism-replay, network-architect). Add a legacy pattern "Client-local adaptive quality that alters simulation" with default stance the class rule.

### K-PERF-3 · major · dependency-error
- Target: PRF.METH.asymptotics, PRF.BENCH.scale-content, milestones M1/M5/M6, contracts_frozen M1 (C-FRAME, C-FLOW, C-SPATIAL, C-VIEW), C-SIGNIF
- Finding: The structural contracts that fix world-scale asymptotics (C-FRAME, C-FLOW, C-SPATIAL, C-VIEW, C-PRESENT) are frozen at M1, on 2D-indie reference games. Asymptotic declarations and synthetic stress worlds are first gated at M5 (scale-content) and M6 (asymptotics). Their validators are circular: M5 gates PRF.BENCH.scale-content validated by PRF.METH.asymptotics, and M6 gates PRF.METH.asymptotics validated by PRF.BENCH.scale-content. If open-world scale exposes an O(n) or serialization flaw in a frozen contract at M5, the fix is a breaking change to contracts consumed by the roughly 120 skills built in between. No scale probe (1e5 to 1e6 entities, 64 cores, 1e4 streaming cells) runs before freeze.
- Evidence: Freezing before scale evidence is the classic cause of late rewrites (Unity DOTS transform and hierarchy redesign, UE world-partition retrofit onto level streaming). Frostbite, Decima and UE5 all validated entity and streaming scaling on synthetic worlds before locking their scheduler and data-flow interfaces.
- Proposed change: add a gate at M1 for PRF.METH.asymptotics (declaration only) validated by PRF.BENCH.scale-content, and an M1 "scale-probe" gate: a synthetic 1e6-entity and 1e4-cell run on the skeleton scheduler and channels, with fitted-slope checks, as a precondition to freezing C-FRAME, C-FLOW, C-SPATIAL, C-VIEW and C-SIGNIF. Change the M5 validator of scale-content to QA.SIM.stability-suite or an independent reference-scaling oracle, breaking the circularity. Make "asymptotic line declared" part of every contract freeze condition.

### K-PERF-4 · major · omission
- Target: PRF.CPU.*, PRF.BENCH.lab, PRF.METH.budgets, CORE.JOBS.scheduler, ARCH.REQ.hardware-tiers
- Finding: No capability owns parallel scalability of the frame: work/span and critical-path analysis of the compiled task graph, per-task scheduling overhead and granularity, worker starvation and core-count scaling curves (2/4/8/16/32/64 workers, SMT off/on, P/E cores). PRF.CPU.contention, cache and hybrid are micro-architectural analyses. C-GOVERN consumes a "CPU critical-path signal" but nothing produces, validates or gates it offline. Budgets are per hardware tier x configuration x refresh class, which fixes one core count per tier. The brief targets many-core and hybrid CPUs. A serialization point (a global sync point, a single-threaded extraction or a channel swap) only shows when core count grows, and the lab cannot sweep it.
- Evidence: Amdahl and span analysis are the standard tools for task-graph engines (Naughty Dog GDC 2015 fiber talk, Destiny "Multithreading the Frostbite" work, UE Insights task-graph critical-path views). AMD Threadripper and Intel hybrid cores exposed engine scaling caps above 16 threads, and Zen 4/5 CCD split changed behavior at 8 cores.
- Proposed change: add PRF.CPU.parallel-scaling (owner cpu-performance; contributors job-system-task-graph, frame-orchestration, observability-telemetry): work/span extraction from the trace, scaling-curve benchmarks with core masks, per-task overhead limits, and a "parallel efficiency at N workers" line per tier in C-BUDGET. Add core-mask control to PRF.BENCH.lab. Add a serial-fraction budget to C-FRAME sync points and a gate to PRF.METH.gates at M3.

### K-PERF-5 · major · omission
- Target: C-BUDGET, PRF.METH.budgets, PRF.GPU.analysis, PRF.MEM.footprint, C-GOVERN, CORE.MEM.uma, OBS.LOG.hw-counters
- Finding: Memory capacity on UMA is arbitrated (RES.MGMT.arbitration, CORE.MEM.uma), but DRAM/fabric bandwidth is not a budget dimension. C-BUDGET lists "transfer bytes per frame" and queue occupancy (PCIe/staging), not CPU+GPU shared memory bandwidth. On consoles, Apple silicon, handhelds and mobile TBDR, bandwidth is usually the binding limit. GPU-driven culling, visibility buffers, RT BVH refit, GPU decompression, streaming decompress/copy and CPU simulation all compete for it. Bandwidth appears only as GPU analysis ("bandwidth" in PRF.GPU.analysis) and mobile TBDR notes. The governor's CPU-bound versus GPU-bound classification has no memory-bound class, so it picks wrong actuators (reducing worker count or resolution when the fix is cutting streaming or copies).
- Evidence: PS5/Xbox Series shared GDDR6 with CPU-induced GPU bandwidth loss (Xbox and Sony GDC talks on CPU/GPU contention), Apple GPU performance guidance, Arm Mali/Immortalis bandwidth counters. Handheld PCs (Steam Deck class) throttle frame time from DRAM bandwidth.
- Proposed change: add a "DRAM/fabric bandwidth per frame by consumer class (GPU passes, streaming/decompress, CPU sim, upload)" line to C-BUDGET for UMA and mobile tiers. Add capability PRF.MEM.bandwidth (owner memory-performance; contributors gpu-performance, loading-streaming-performance) with attribution from OBS.LOG.hw-counters. Add a "memory-bound" classification and bandwidth-reducing actuators (streaming rate, decompress throttle) to C-GOVERN/CORE.SCALE.actuators, and let RES.MGMT.arbitration take a bandwidth budget as well as a capacity budget.

### K-PERF-6 · major · scale-down
- Target: PRF.METH.gates, PRF.BENCH.lab, PRF.BENCH.regression, C-BENCH, BLD.CI.device-lanes, BLD.CI.merge-queue
- Finding: Every perf gate is defined as measurement on reference hardware ("gates run on the profile build configuration", lab exclusivity, thermal soak, warm-up and variance rules). With many autonomous agents producing changes in parallel, wall-clock lab runs are the scarcest resource: exclusive hardware, per tier, NDA console devkits, thermal soak minutes per run. Nothing defines a cheaper pre-merge tier, lab scheduling, or what to do when the lab is the bottleneck. The predictable outcomes are gates skipped under load, batched merges too coarse to attribute, or noisy statistical gates that reject good changes. QA.STRAT.selection-policy covers test selection but not perf gate selection.
- Evidence: Chromium/V8 and Rust perf infrastructure use instruction-count (cachegrind/perf stat) proxies and per-PR deterministic metrics for pre-merge, with wall-clock on dedicated bots post-merge. Mozilla Perfherder and Google "perf sheriffs" tier the same way. Game studios use replay-driven capture (already PRF.BENCH.replay) but on a nightly cadence.
- Proposed change: add PRF.BENCH.proxy-metrics (owner perf-benchmarking): deterministic pre-merge proxies (instruction and cache-miss counts, allocation counts per frame, draw/dispatch/barrier counts, bytes per entity/component, memory traffic from replays, size-sweep complexity fits) with calibrated correlation to lab wall-clock. Add PRF.BENCH.lab-scheduling (lab queueing, priority by risk, batching with bisect budget, NDA-device allocation). Define gate tiers in PRF.METH.gates: pre-merge proxies, merge-queue lab run on the pre-merge risk subset, nightly full tier x configuration. Make proxy calibration drift a tracked critic canary metric.

### K-PERF-7 · minor · other
- Target: milestones M2/M3/M4, PRF.METH.energy, PRF.NET.resim-cost, PRF.MEM.size, PRF.NET.latency, PRF.CPU.hybrid, PRF.GPU.power, PRF.NET.server-density
- Finding: Milestone exits and gates disagree with claimed obligations. (a) M4 exit says "server density within budget" but PRF.NET.server-density is gated only at M6, and online-3d-server is claimed at M4. (b) M2 claims the rollback configuration and its 8-frame resim budget, but PRF.NET.resim-cost is never a gate. (c) lite-3d mobile and portable configurations at M3 and xr-standalone at M5 carry no energy or sustained-thermal gate (PRF.METH.energy, PRF.GPU.power), although C-BUDGET defines battery and sustained-state lines. (d) PRF.MEM.size (WASM/download size) is ungated although the web configuration ships at M2/M4. (e) PRF.NET.latency is ungated.
- Evidence: milestones.json gates for M2 to M6 list only PRF.MEM.footprint, PRF.LOAD.pacing-latency, PRF.BENCH.stats, PRF.GPU.baselines, PRF.NET.bandwidth, PRF.NET.load-analysis, PRF.NET.server-density (M6), PRF.METH.asymptotics. Mobile sustained throttling is the dominant mobile failure mode (Arm and Google ADPF guidance).
- Proposed change: add gates M2 PRF.NET.resim-cost (validator QA.SIM.netsim), M2 PRF.MEM.size (validator PRF.BENCH.stats), M3 PRF.METH.energy (validator PRF.GPU.power) for lite3d, M4 PRF.NET.server-density, M4 PRF.NET.latency (validator QA.FUNC.load), M5 PRF.METH.energy for xr-standalone. Leave M6 server-density for the AAA scale point.

### K-PERF-8 · minor · missing-contract
- Target: C-BUDGET, PRF.METH.budgets, L70
- Finding: L70 forbids average-fps targets, and PRF.LOAD.pacing-latency mentions percentiles, but C-BUDGET's summary enumerates no percentile frame-time (p99, p99.9), hitch-count-per-hour, stream-in speed at target traversal speed, time-to-first-interactive/startup, or input-to-photon latency lines. Those live only in analyzer capabilities. A budget that is not a C-BUDGET line cannot be referenced by C-BENCH or gated.
- Evidence: C-BENCH requires a "C-BUDGET line reference" per benchmark. Modern pacing standards use 1% and 0.1% lows and frame-time histograms (Digital Foundry, PresentMon, Frame Time Analysis).
- Proposed change: extend the C-BUDGET summary and PRF.METH.budgets with: p50/p99/p99.9 frame time, max hitch length and hitches per hour per tier, startup and level-transition time, traversal-speed x stream-in-quality line, and input-to-photon latency per refresh class and netcode family.

### K-PERF-9 · minor · obsolete-assumption
- Target: legacy-patterns.json (L25, L03, L65), CORE.JOBS.thread-model, PRF.CPU.parallel-scaling (new)
- Finding: The catalogue has no pattern for fixed core-count and thread-per-subsystem assumptions (worker pools sized to a constant, "leave 1-2 cores", per-subsystem threads such as physics, audio, streaming, network each running their own loop), which is a very common legacy default in agent-written code. L03 and L25 cover only the game/render split and single-thread-first. Also absent are unbounded queues without back-pressure between pipeline stages and benchmarking on debug or dev configurations.
- Evidence: Thread-per-subsystem engines (Source, early Unreal, Unity pre-DOTS) capped scaling by the busiest subsystem and oversubscribed hybrid CPUs. Back-pressure is an explicit requirement of async IO pipelines (DirectStorage queue depth, RES.MGMT.pipeline).
- Proposed change: add L75 "Thread-per-subsystem and fixed worker counts" (stance: one worker pool sized from PAL topology, subsystem work as tasks; justification owner job-system-task-graph; stance_capabilities CORE.JOBS.thread-model, CORE.JOBS.scheduler, CORE.SCALE.actuators, PRF.CPU.hybrid). Add L76 "Unbounded stage queues and benchmarks on non-profile builds" (stance: bounded queues with back-pressure; gates only on the profile configuration; owner performance-architect; stance_capabilities RES.MGMT.pipeline, OBS.LOG.bench-runtime, PRF.METH.gates).
