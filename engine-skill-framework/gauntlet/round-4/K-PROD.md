### K-PROD-1 · major · omission
- Target: ARCH.PROD (new ARCH.PROD.support-policy), BLD.CI.backports, XC.EXT.versioning, C-RELEASE, M7
- Finding: No capability owns the support commitment for engine versions: LTS duration, N-1 support, end-of-support dates, platform-SDK and store-mandate end-of-support, migration deadlines for licensees. BLD.CI.backports owns backport mechanics, XC.EXT.versioning owns API deprecation, and PLAT.PAL.os-support-policy owns OS versions. Nobody decides how long a stream is supported or what its cost is. The ladder ends at M7 "first LTS" and has no post-1.0 lifecycle (minor cadence, next major, LTS expiry, engine-version sunset). A capability search for sunset/EOL/support-window returns nothing engine-side.
- Evidence: Unreal, Unity and Godot publish support windows, and licensees plan multi-year titles against them. Backport streams with no declared end grow without bound and drain the agent budget.
- Proposed change: add ARCH.PROD.support-policy (owner engine-product-management, E, contributors build-release-architect, api-lifecycle-migration, security-engineering) covering the stream matrix, support window, EOL notice period and platform-SDK sunset. Add it to C-PROD and to the C-RELEASE consumption. Add an M7 exit item "EOL rehearsal of one release stream", and note that post-M7 milestones are cadence-driven rather than a ladder.

### K-PROD-2 · major · omission
- Target: ARCH.ORG.cost-ledger, ARCH.ORG.risk, milestones.json, ARCH.ORG.human-gates
- Finding: ARCH.ORG.cost-ledger only accounts for cost. No capability holds authority to act on it: a budget envelope per milestone, a burn-rate or slip trigger, a descope order (which profiles, configurations or capabilities to cut first), or a stop/cancel criterion. Milestones have exit criteria but no time or cost box. The risk register is "risk-driven ordering" only, with no contingency response. Agents without a cut list will keep expanding scope, because every capability is "required for the bar".
- Evidence: Production practice is a cut list and vertical-slice triage tied to milestone burn-down. The ladder is already ordered by configuration, so cuts can be expressed as unclaimed configurations.
- Proposed change: add ARCH.ORG.scope-control (program-orchestration, E, contributors engine-architect, engine-product-management). It defines a budget envelope per milestone, a burn/slip trigger, an ordered descope list expressed as configurations and non-goals, and a human gate for envelope raises and cancellation. Add "cap raise / descope past M-N / cancel" to ARCH.ORG.human-gates, and make cost-ledger a contributor.

### K-PROD-3 · major · omission
- Target: ARCH.PROD.customer-corpus, ARCH.PROD.intake, QA.REF.dogfood, milestones.json M2-M7
- Finding: Every "customer" of the engine is agent-authored. Reference games are written by the same agent organization against the public API, and dogfood is internal. The ladder has no external design-partner or early-access milestone. ARCH.PROD.intake and field-feedback have no real inflow until after M7. This risks a self-consistent engine: the same blind spots produce both the API and the games that validate it.
- Evidence: Frostbite's history of engine tuned for shooters and forced onto RPG teams. Successful engines matured through real title teams (Fortnite for UE, external alpha and beta programs for Unity and Godot).
- Proposed change: add ARCH.PROD.design-partners (engine-product-management, E): recruit external teams per profile, with agreements, feedback SLAs and support tiers. Add milestone gates: M2 (one external indie title on the public API), M4 (an external multiplayer team), M7 (at least N external titles on the release candidate). Register partner agreements as human gates. Extend the untrusted input class `external-reports` to cover partner projects.

### K-PROD-4 · major · omission
- Target: ARCH.ORG.human-gates, ARCH.ORG.escalation, ARCH.ORG.human-audit, C-ORCH
- Finding: The human-gate register lists which decisions need a human but says nothing about human capacity. There is no roster of human roles (legal counsel, security lead, platform account holder, product owner), no decision latency or queue, no batching, no delegate or dead-man rule, and no policy for what agents do while blocked (continue on a speculative branch or stall). Several gates are on the critical path: contracts, key custody, pen test, production rollout, NDA material. With N parallel agents, humans are the throughput ceiling.
- Evidence: Production experience is that sign-off queues, not build capacity, set schedule once automation exists. The framework already sets SLAs for agent escalation but not for humans.
- Proposed change: extend ARCH.ORG.human-gates (or add ARCH.ORG.human-capacity) with a role roster and SLA per gate class. Add a non-blocking continuation rule (a gated task parks and agents proceed on independent work packages), batching cadence per milestone, an explicit delegate and expiry rule, and a metric (gate wait time) in the cost-ledger. Add a `human_gate` work-package type in C-ORCH with an owner role.

### K-PROD-5 · major · omission
- Target: ARCH.ORG.risk, ARCH.ORG.milestones, PLAT.CON, QA.CERT.programs, M2/M4/M7
- Finding: External lead-time dependencies are not owned anywhere: platform-holder program admission and NDAs, devkit and hardware-lab procurement, certification/store-review queue slots, external pen-test vendor booking, and licensed middleware negotiation. Milestones M2 (TRC dry run, console ship), M4 (external pen test) and M7 (console certification pass) assume them. BLD.CI.devices schedules an existing device fleet and PLAT.CON.devkit covers workflows, not acquisition. The risk register has no owner for this critical path.
- Evidence: Console programs and cert slots take weeks to months, and an agent organization cannot compress them. Studios book cert windows and kits far ahead of code-complete.
- Proposed change: add ARCH.ORG.external-dependencies (program-orchestration, E, contributors platform-console, certification-compliance, ci-cd-automation). It is a lead-time register with start-by dates derived backwards from milestone exits, feeding ARCH.ORG.risk. Add a milestone entry-precondition "external item requested by M-1" and register the procurement and agreement steps as human gates.

### K-PROD-6 · major · omission
- Target: ARCH.PROD.licensing-model, QA.CERT.code-provenance, ARCH.ORG.provenance, ARCH.EVID.source-policy
- Finding: Inbound contamination is covered by snippet scanning and clean-room source policy. Outbound ownership is not: who owns the copyright in an engine written largely by autonomous agents, whether the licensing model is enforceable, who is the licensor of record, and what human-authorship record supports it. ARCH.PROD.licensing-model is owned by a product-management skill with no legal-review owner or contributor. ARCH.ORG.provenance records agent/model/task per change but is not linked to any rights determination. Trademark and name clearance for the engine and its shipped sample assets is also unowned.
- Evidence: The U.S. Copyright Office position (2023-25) is that purely machine-generated material is not copyrightable and human authorship must be shown. A permissive or paid licence over uncopyrightable code offers little enforceable protection. Model-vendor output terms also vary.
- Proposed change: add QA.CERT.authorship-ip (certification-compliance, E, contributor program-orchestration for the provenance data) covering authorship records, model-vendor terms register, licensor of record and trademark clearance. Make certification-compliance a contributor to ARCH.PROD.licensing-model. Add "licence terms, EULA and contributor terms published" to the ARCH.ORG.human-gates register with a legal reviewer role, before M7.

### K-PROD-7 · minor · scale-down
- Target: ED.UI.ux, ED.ARCH.discipline-workflows, XC.DX.creator-docs, ARCH.ORG.human-gates
- Finding: Editor usability and creator documentation are validated only by agent-runnable oracles (iteration targets, doc snippet tests). A non-programmer creator's experience (artist, designer, audio, level) cannot be judged by agents. No milestone or human gate samples real creators, so the "content creators as users" bar is unverified.
- Evidence: Editor UX failures in production are found by creator playtests and task observation, not by latency targets.
- Proposed change: add a human creator-panel sampling gate per discipline at M2 (indie tools), M3 and M6 (team-large tools), with task-completion rate and time-to-first-asset thresholds. Register it in ARCH.ORG.human-gates and make ED.UI.ux the metric owner, with developer-experience-docs as contributor.
